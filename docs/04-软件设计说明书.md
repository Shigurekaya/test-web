# 软件设计说明书

**项目名称**：智慧企业知识财富库系统  
**文档版本**：V1.3  
**日期**：2026-10-17

---

## 1. 设计目标

在满足《系统需求说明书》`SR-*` 的前提下，交付：

1. 可本机运行的 Flask Web 应用；  
2. 可演示的权限、检索、问答、图谱主路径；  
3. 与 UML / 测试可双向追踪的清晰分层。

非目标：商业级向量平台、生产多租户与完整 LLM 运维。

## 2. 总体架构（三层）

```
┌─────────────────────────────────────────┐
│ 表现层  Jinja2 + Bootstrap + ECharts     │
├─────────────────────────────────────────┤
│ 业务层  Blueprints + services(RAG/Graph)│
├─────────────────────────────────────────┤
│ 数据层  SQLAlchemy ORM + SQLite          │
└─────────────────────────────────────────┘
```

| 层 | 职责 | 禁止事项 |
|----|------|----------|
| 表现层 | 渲染、表单、图可视化 | 不写鉴权与检索算法 |
| 业务层 | 路由编排、权限调用、服务调用 | 不在模板内拼 SQL |
| 数据层 | 模型与持久化 | 不耦合具体页面文案 |

对应 UML：[`docs/uml/10-三层架构.puml`](uml/10-三层架构.puml)、[`08-部署图.puml`](uml/08-部署图.puml)、[`09-构件图.puml`](uml/09-构件图.puml)

## 4. RAG 设计

| 步骤 | 设计要点 |
|------|----------|
| 切分 | 段落优先；超长滑动窗口（默认约 400 字窗口、50 字重叠，可配置） |
| 索引 | `knowledge_chunks` 持久化；jieba 关键词辅助 |
| 检索 | 问题分词后与片段重合打分；关键词命中加权（约 1.5） |
| 生成 | 默认本地摘要拼接；配置 `OPENAI_API_KEY` 后可在命中上下文上调用 Chat Completions |
| 权限 | **先**按 `can_view` 过滤可访问 `document_id`，**再**在对应 chunk 中检索，避免机密泄漏 |
| 可追溯 | 返回来源标题、部门、片段摘要、相关度；并持久化到历史 |

对应 UML：[`03-RAG问答时序图.puml`](uml/03-RAG问答时序图.puml)

## 5. 知识图谱设计

- **节点类型**：`document` / `department` / `project` / `keyword` / `concept`  
- **自动同步**：文档保存触发 `sync_document_graph`，按部门、标签等建边  
- **手工维护**：管理员可在 `/graph/manage` 补节点与关系  
- **前端**：ECharts 关系图，支持核心结构与完整视图。

对应需求：SR-KG-001～005。

## 6. 权限设计

```
can_view(user, doc):
  if user is admin: allow
  if doc.visibility == secret:
      allow iff same department OR author
  else:
      allow for logged-in users (public / internal)
```

补充约定：

- 未登录不可进入业务页（跳转登录）；  
- 无权限详情返回 HTTP 403，不渲染正文；  
- 列表、问答、图谱相关读路径共用同一套判定；  
- 检索**先**按权限圈定可访问文档，再在对应片段内打分，机密内容不进入候选集；  
- 面向用户展示的统计数字跟随其可见范围（关于页），避免数量反推机密规模。

对应需求：SR-AUTH-005/006、SR-QA-008。

### 6.1 登录防爆破设计

| 步骤 | 设计要点 |
|------|----------|
| 计数 | 按客户端地址维护失败次数，滑动窗口（默认 5 分钟 / 8 次，可配置） |
| 判定顺序 | **先**查锁定状态，**再**校验密码，避免锁定被绕过 |
| 锁定行为 | 返回 429 并给出重试提示；锁定期间凭据正确同样拒绝 |
| 清零 | 登录成功后清空该来源计数，爆破无法靠间隔性成功续命 |
| 存储 | 进程内字典 + 过期裁剪；单机/单进程演示够用，多进程部署需换共享存储（已在代码注明） |
| 审计 | 每次失败写 `login_failed`，含用户名不存在的情形，使爆破在审计中可见 |

对应需求：SR-AUTH-007 / 008 / 009。对应测试：AT-21～AT-26。

## 8. 界面设计原则

1. **工作台**：个人可见规模、部门分布、最近文档与最近提问 + 建议试用路径。  
2. **登录 / 首页**：说明产品价值与演示账号，避免空白壳登录框。  
3. **问答页**：答案与命中证据卡并列；示例问题降低上手成本。  
4. **文档列表**：筛选条 + 卡片摘要 + 密级徽章；空状态给下一步动作。  
5. **错误页**：403 / 404 / 500 统一风格，避免裸堆栈（非调试模式）。

## 9. 运行与部署设计

| 场景 | 方案 |
|------|------|
| 开发 / 演示 | `run.py` 或 `start.ps1`，默认 `127.0.0.1:5000` |
| 自动化验证 | `run_tests.ps1` → `tests/test_system.py` |
| 演进（可选） | Nginx → WSGI → Flask；SQLite 可换 PostgreSQL（见部署图） |

配置项通过环境 / `.env` 注入（密钥、切分参数等），避免硬编码散落业务代码。
