## 1. 引言

### 1.1 编写目的

本计划用于指导 V2.0《智慧企业知识财富库系统》的课程大作业测试活动，明确测试目标、范围、策略、级别、环境、数据、进度、职责、准入准出条件、缺陷规则、风险和质量度量，使测试工作可计划、可执行、可追踪、可复核。

本计划的直接读者包括：项目负责人、开发人员、测试执行人员、课程指导教师及验收人员。由于本项目为单人项目，计划中的开发、测试、运维等角色由同一人兼任，但必须按角色分别留下记录，避免“自己开发、自己测试、无证据”的问题。

### 1.2 项目背景

系统面向企业内部知识管理场景，以可鉴权的知识文档库为基础，提供文档 CRUD、收藏、检索、带来源的 RAG 问答、知识图谱、管理员用户与审计查询等能力。V2.0 采用前后端分离架构：Flask 提供 REST API，Vue 3 SPA 提供交互界面，SQLite 保存业务数据，pytest 承担自动化回归。

系统重点风险不是“页面能否打开”，而是：三级密级与部门隔离是否一致、RAG 问答是否只使用当前用户可见内容、登录防爆破是否有效、审计日志是否完整且可追溯、前后端 API 契约是否稳定、测试是否污染演示数据库。

### 1.4 术语与缩略语

| 术语 | 说明 |
|---|---|
| REST API | 基于 HTTP 的资源接口，本项目以 JSON 为主要交换格式 |
| SPA | 单页应用，V2.0 前端采用 Vue 3 + Vue Router + Vite |
| RAG | 检索增强生成，先检索权限内知识片段，再生成或拼接带来源回答 |
| Chunk | 文档切分后的知识片段，是检索、问答与来源展示的基本单元 |
| 三级密级 | 公开、内部、机密三个可见性等级 |
| 部门隔离 | 机密文档仅同部门用户、作者本人和管理员可访问 |
| 防爆破 | 按 IP 和时间窗口限制连续登录失败，超过阈值后临时锁定 |
| 审计 | 记录登录、登录失败、浏览、问答、写操作等关键行为 |
| 跨库隔离 | 自动化测试使用独立 SQLite 测试库，不读写演示数据库 |
| P0/P1/P2/P3 | 缺陷或测试优先级，P0 最高 |

## 2. 测试目标、范围与不测项

### 2.1 测试目标

1. 验证 V2.0 Flask REST API 与 Vue 3 SPA 的核心业务链路能够完整运行。
2. 验证登录、角色、三级密级、部门隔离和作者例外规则在列表、详情、检索、问答、统计等入口保持一致。
3. 验证文档 CRUD、收藏、分类、检索、RAG 来源、图谱、管理员用户、审计分页、健康检查等功能符合需求。
4. 验证登录防爆破、安全跳转、密码存储、未授权访问、跨库隔离等安全控制有效。
5. 验证自动化测试可重复执行且不污染 instance 下的演示数据库；计划/交付基线为 133 条，以最终执行记录为准。
6. 验证 Vue 页面在主流浏览器中的关键交互、错误提示、空状态和响应式布局可用。
7. 形成可追踪的用例、执行记录、缺陷记录和测试报告，支撑课程验收与答辩演示。

### 2.2 测试范围

| 模块 | 主要测试内容 | 主要风险 |
|---|---|---|
| 认证与会话 | 登录、退出、当前用户、未登录拦截、会话保持、安全 next 跳转 | 未授权访问、开放重定向、会话残留 |
| 登录防爆破 | 失败阈值、锁定时间窗、窗口过期、成功清零、Retry-After | 账号被暴力尝试、误锁定 |
| 权限与隔离 | 公开/内部/机密、同部门、作者例外、管理员、草稿可见性、统计口径 | 机密内容越权或通过统计泄露 |
| 文档管理 | 新建、详情、修改、删除、标签、分类、版本、发布状态 | 数据不一致、索引未更新 |
| 收藏 | 收藏、取消收藏、收藏列表、重复操作 | 重复数据、越权查看 |
| 检索 | 标题/摘要/正文搜索、分类/部门/密级筛选、分页 | 结果泄漏、排序异常、翻页参数丢失 |
| RAG 问答 | 切分、分词、打分、Top-K、来源去重、无命中降级、历史 | 非权限内容进入来源、回答不可追溯 |
| 知识图谱 | 节点/边结构、可见范围、自动同步、管理员维护 | 图谱泄露、脏节点、删除后残留 |
| 管理员功能 | 用户列表、分类维护、审计查询、权限限制 | 普通用户越权 |
| 审计 | 登录、失败登录、浏览、问答、写操作、筛选、分页、时间口径 | 日志缺失、时间错乱、分页失效 |
| 非线性功能 | 健康检查、建库与种子、API 契约、错误页、性能烟测、兼容性 | 部署失败、前后端错位、恢复困难 |
| 前端交互 | 登录、导航、查询、编辑、问答、图谱、后台表格、响应式 | 页面状态错误、操作反馈缺失 |

### 2.3 不测项与边界说明

| 不测项 | 原因与边界 |
|---|---|
| 真实大模型的回答质量、稳定性和计费 | 课程环境不强制依赖外部模型；重点验证本地检索与降级链路，外部模型仅做接口级检查 |
| 千人以上并发压测和容量规划 | 本系统定位单机/局域网演示，性能只做烟测，不作生产容量承诺 |
| 多进程、多机部署下的共享限流 | 当前防爆破为进程内实现，多实例共享限流不在本期范围 |
| 跨浏览器像素级视觉回归 | 只检查 Chrome、Edge 主流版本的布局与关键交互，不做像素比对 |
| 移动端原生应用、离线同步 | 系统为 Web SPA，不提供原生客户端与离线能力 |
| 第三方支付、邮件、短信、SSO | 系统未集成这些外部能力 |
| 生产级安全认证、渗透测试和灾备演练 | 课程项目执行基础安全检查，不替代正式安全测评 |
| SQLite 高并发、海量数据性能 | 仅验证演示规模下的可用性，明确其为演示型数据库 |
| instance/knowledge.db 的人为删除恢复 | 只验证全新库自动建表和种子流程，不负责生产数据备份恢复 |

## 3. 测试策略

### 3.1 总体策略

采用“风险优先、接口为主、分层验证、自动化回归、人工补充体验”的策略。测试顺序不按页面菜单机械排列，而按风险从高到低推进：

1. 先验证认证、会话和未授权访问边界；
2. 再验证三级密级、部门隔离、作者例外和跨库隔离；
3. 验证文档 CRUD 与索引/图谱同步；
4. 验证检索、RAG 来源、Top-K、去重和降级；
5. 验证管理员、审计分页和时间口径；
6. 验证 SPA 关键交互、错误状态、兼容性与性能烟测；
7. 最后执行课程验收故事线和全量回归。

### 3.2 自动化策略

后端以 pytest 为主要验证手段，测试文件与重点如下：

| 测试文件 | 重点 |
|---|---|
| tests/test_system.py | 系统冒烟、主路径、路由、错误页、建库、时间口径、演示故事线 |
| tests/test_security.py | 权限矩阵、检索范围、统计口径、审计筛选与分页、文本截断 |
| tests/test_rag.py | 切分、分词、打分、Top-K、来源分组、去重与降级 |
| tests/test_login_security.py | 防爆破阈值、窗口、锁定、失败审计、密码哈希、行为文案 |
| tests/test_api.py | V2.0 REST API 契约、登录退出、文档 CRUD、收藏、问答、图谱、管理员接口 |

自动化执行原则：

- 每个测试使用独立测试应用、内存 SQLite 或临时文件 SQLite；
- 用例之间通过事务回滚或独立夹具隔离，不共享可变业务数据；
- 不得读写 instance/knowledge.db；
- 使用 fresh_app 等夹具验证全新库建表和种子流程；
- 参数化用例可让自动化执行数大于抽象测试场景数，故“133 条”以 pytest 收集/执行记录为准；
- 前端未建立独立组件测试框架时，关键页面以人工 UI 清单补充，接口契约由 test_api.py 保障。

### 3.3 人工测试策略

人工检查重点覆盖自动化难以稳定判断的内容：页面布局、导航可达性、表单提示、空状态、确认对话框、图谱拖拽缩放、表格横向滚动、键盘基本操作、不同浏览器渲染。所有人工检查必须有截图、浏览器版本和结论，不能只写“已看”。

### 3.4 测试轮次

| 轮次 | 目的 | 触发条件 | 输出 |
|---|---|---|---|
| 冒烟轮 | 确认 V2.0 可启动、可登录、可访问核心 API | 版本冻结后 | 冒烟记录、阻断问题 |
| 首轮全量 | 执行功能、安全、接口、非功能用例 | 冒烟通过 | 首轮执行记录、缺陷台账 |
| 缺陷回归 | 验证修复不引入新问题 | 开发提交修复 | 回归记录、缺陷状态 |
| 验收轮 | 按课程故事线和准出条件复验 | 修复完成、环境确认 | 验收记录、测试报告 |
| 最终基线 | 保留可重复执行的最终证据 | 提交前 | pytest 日志、前端构建日志、截图 |

## 4. 测试级别

| 测试级别 | 测试对象 | 重点与方法 | 主要证据 |
|---|---|---|---|
| 单元测试 | RAG 切分/分词/打分、登录限流器、工具函数、文本截断 | 等价类、边界值、错误猜测、断言函数级输入输出 | test_rag.py、test_login_security.py 中的单元级用例 |
| 集成测试 | REST API、SQLAlchemy、SQLite、认证装饰器、服务层 | 使用 Flask test client，验证接口+数据库+权限的组合 | test_api.py、test_security.py |
| 系统测试 | 登录→工作台→文档→问答→图谱→审计的完整链路 | 端到端场景、故事线、状态转换、异常路径 | test_system.py、人工 UI 检查 |
| 验收测试 | 课程验收场景与需求基线 | 按角色执行演示脚本，核对可见性与来源 | 验收记录、截图、最终测试报告 |
| 安全测试 | 认证、权限、开放重定向、防爆破、密码存储、跨库隔离 | 权限矩阵、负向输入、边界阈值、日志核验 | test_security.py、test_login_security.py、安全缺陷记录 |
| 兼容性测试 | Vue SPA、浏览器、屏幕宽度、构建产物 | Chrome/Edge 同版本对照、响应式人工检查 | 浏览器版本表、截图、npm build 日志 |

### 4.1 单元测试关注点

- 空文本、短文本、长段落、空行、超长无标点段落的切分边界；
- 中文领域词“年假”等分词结果；
- 标题、关键词、正文、精确短语的权重关系；
- Top-K、单文档来源上限、去重和排序；
- 登录失败阈值、窗口过期、成功清零、不同 key 独立计数；
- 密码哈希、文本截断和标签映射。

### 4.2 集成测试关注点

- API 状态码、JSON 字段、错误 code 和前端可消费性；
- 文档保存后知识片段、图谱节点/边是否同步；
- 同一份可见性判定是否被列表、详情、搜索、问答共同复用；
- 普通用户和管理员的接口权限差异；
- 审计记录是否与业务动作一致；
- 测试库与演示库是否物理隔离。

### 4.3 系统与验收测试关注点

使用 admin、hr、it 等演示账号执行完整故事线：管理员总览 → 搜索“年假” → 查看文档 → 问答“员工年假有几天” → 查看来源 → 图谱 → 审计；再用 hr/it 对比机密文档访问结果。验收时特别核对“来源是否可追溯”和“机密内容是否不进入普通用户结果”。

### 4.4 安全与兼容性测试关注点

安全测试采用权限矩阵和负向用例，不以正向成功代替安全验证。兼容性测试覆盖当前主流 Chrome 与 Edge，检查布局、导航、表单、图表和错误提示；不承诺所有历史浏览器。性能只做关键页面和 API 烟测，发现明显阻塞、超时或 N+1 类问题时记录缺陷。

| 测试专用数据 | 独立测试库、临时文档、临时分类 | 用完回滚或删除，不进入演示库 |

### 5.4 环境配置与隔离要求

- 测试配置必须显式使用 TestingConfig 或等价测试配置；
- 测试开始前确认数据库 URI 指向内存库或临时文件，而不是 instance/knowledge.db；
- 测试结束核对演示数据库未被修改，必要时记录文件大小/关键表行数；
- 不把真实 API Key、生产密码、个人数据放入测试夹具或截图；
- 时间相关用例应允许合理的执行时间误差，但必须验证顺序和无微秒展示口径；
- 前端人工检查应固定浏览器版本、分辨率、缩放比例和后端提交版本。

### 5.5 环境检查清单

| 检查项 | 通过标准 |

## 9. 测试用例设计方法

| 方法 | 使用场景 | 示例 |
|---|---|---|
| 等价类划分 | 用户名、密码、密级、部门、状态、动作筛选 | 合法/非法登录；公开/内部/机密可见性 |
| 边界值分析 | 失败次数、时间窗口、分页页码、文本长度、Top-K | 第 8 次失败锁定、超出页码钳制、超长问题截断 |
| 判定表 | 密级 × 部门 × 作者 × 角色 | 管理员、同部门、作者、异部门对机密文档的决定 |
| 状态转换 | 登录锁定、草稿/发布、文档编辑/删除、收藏切换 | 失败计数→锁定→过期解锁→成功清零 |
| 场景法 | 登录→文档→问答→图谱→审计 | 课程验收故事线与 SPA 导航 |
| 错误猜测 | 空字段、非法 JSON、越权 ID、异常 next、重复收藏 | 未登录访问、开放重定向、重复收藏、404 |
| 配对组合 | 浏览器 × 页面 × 数据状态 | Chrome/Edge 下的空列表、错误、长表格 |
| 权限矩阵法 | 角色、部门、密级、资源状态的正交组合 | 列表、详情、搜索、问答、统计范围一致性 |

测试用例应做到“前置条件可搭建、步骤可复现、预期可判定、证据可保存”。对随机性、时间、中文分词和第三方模型相关结果，避免模糊断言，优先断言权限边界、结构字段、排序关系、来源标题和明确降级状态。

## 10. 缺陷管理与严重级别

### 10.1 缺陷流程

新建 → 复核/分级 → 指派 → 修复 → 待回归 → 回归通过关闭；若暂不修复，进入延期/接受风险状态，必须记录理由、影响范围、责任人和评审结论。缺陷记录必须包含环境、版本、复现步骤、实际结果、预期结果、证据和关联用例。

### 10.2 严重级别

| 级别 | 名称 | 判定标准 | 示例 |
|---|---|---|---|
| S1 | 阻断 | 系统不可用、数据丢失、核心安全边界被绕过、测试污染演示库 | 任意人可读机密；测试写入生产库；无法登录 |
| S2 | 严重 | 核心功能不可用或关键结果错误，无合理绕行 | RAG 来源越权；文档保存后不可检索；审计缺失关键动作 |
| S3 | 一般 | 非核心功能错误或体验明显受损，有绕行方式 | 筛选参数丢失；分页边界异常；错误提示不准确 |
| S4 | 轻微 | 文案、样式、轻微体验问题 | 标签大小不一致；非关键空状态文案不当 |

### 10.3 优先级

| 优先级 | 处理原则 |
|---|---|
| P0 | 立即停止测试并处理，修复后再进入 |
| P1 | 当前轮次必须修复，准出前关闭 |
| P2 | 计划内修复；若延期需接受风险并记录影响 |
| P3 | 可排入后续版本，不阻断课程验收 |

严重级别描述“影响有多大”，优先级描述“何时修”。S1 通常对应 P0/P1，避免用 P3 掩盖安全问题。

| 课程时间不足 | 中 | 中高 | 优先完成高风险权限、来源、审计和主路径；低风险项明确延期 |
