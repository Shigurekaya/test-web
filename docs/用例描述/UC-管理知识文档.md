# 用例描述：管理知识文档

| 项 | 内容 |
|----|------|
| 用例名称 | 管理知识文档（新建 / 编辑 / 删除） |
| 用例编号 | UC-DOC-01 |
| 参与者 | 管理员、普通员工（文档作者） |
| 用例目标 | 让授权用户沉淀制度与经验文档，并保证写入后能被检索、问答与图谱使用 |
| 优先级 | 高 |
| 前置条件 | 用户已登录；分类表非空 |
| 后置条件 | 文档持久化；成功：写入 `knowledge_chunks`、同步图谱节点与边、写审计 |
| 关联需求 | UR-DOC-04 / 05；SR-DOC-005 / 006 / 007 |
| 关联 UML | `docs/uml/04-文档发布活动图.puml`、`05-文档状态图.puml`、`03-RAG问答时序图.puml` |
| 触发条件 | 用户在文档列表点击「新建文档」，或在详情页点击「编辑」/「删除」 |

## 基本事件流（新建）

| 步骤 | 参与者 | 系统动作 |
|------|--------|----------|
| 1 | 用户点击「新建文档」 | 展示表单：标题、摘要、正文、分类、部门、密级、状态、版本、标签 |
| 2 | 填写并提交 | 接收表单，校验标题与正文非空 |
| 3 | — | 摘要为空时按正文首段自动生成 |
| 4 | — | 归一化枚举值：密级仅取 `public/internal/secret`，状态仅取 `draft/published/archived`，非法值回落默认 |
| 5 | — | 部门字段不在合法列表内时回落为当前用户所属部门 |
| 6 | — | 持久化文档，作者记为当前用户 |
| 7 | — | 按 `CHUNK_SIZE` / `CHUNK_OVERLAP` 切分正文，写入 `knowledge_chunks` 并用 jieba 抽取关键词 |
| 8 | — | 同步图谱：文档节点、所属部门、分类、标签关键词节点与边 |
| 9 | — | 写入 `create_document` 审计日志 |
| 10 | — | 跳转文档详情页，提示「文档已创建，并完成知识切分与图谱同步」 |
| 11 | 用户查看详情 | 展示正文、密级、部门、分类、标签、版本与更新时间 |

## 备选事件流

| 编号 | 条件 | 系统行为 |
|------|------|----------|
| 2a | 标题或正文为空 | 停留在表单并提示「标题与正文不能为空」，不写库 |
| 4a | 表单传入非法密级/状态 | 归一化为默认值（`internal` / `published`），不因构造请求而进入非法状态 |
| 4b | 非本人且非管理员编辑/删除 | 返回 403，不执行 |
| 7a | 正文极长 | 超长段落按滑动窗口切分（带重叠），保证跨窗口语义不断裂 |
| 7b | 重复保存同一文档 | 先删除该文档旧片段再重建，避免片段累积重复 |
| 8a | 标题变更 | 同步更新图谱节点名称，并清理同名残留节点，避免出现重复节点 |
| 8b | 标签为空 | 自动用正文关键词补标签，保证图谱仍有可连线实体 |

## 业务规则

1. 编辑与删除仅限**作者本人或管理员**，其他角色一律 403。  
2. 文档密级三档：`public` / `internal` / `secret`；`secret` 仅管理员、同部门或作者可见。  
3. 文档状态三档：`draft` / `published` / `archived`；**只有已发布文档**进入列表、检索与问答候选集。  
4. 保存后必须完成「切分建索引 + 图谱同步」，否则文档写得进却搜不到。  
5. 删除文档时同步清理其图谱节点与相关边，避免残留孤点。  
6. 写操作使用事务提交，避免半写入状态残留。

## 特殊需求

- 一致性：详情页、列表页、问答来源三处展示的密级与部门口径必须一致。  
- 可检索性：保存完成后，用文档正文中的关键词提问应能命中该文档（由 AT-12 覆盖）。  
- 可维护性：切分参数由配置注入，散落在业务代码中的硬编码会被静态检查拦下。
