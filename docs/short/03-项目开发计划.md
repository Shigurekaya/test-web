## 1 项目目标与成功标准

### 1.1 项目目标

在 12 周内完成一个可运行、可演示、可测试、可复现的企业知识管理数据库应用，覆盖：

- 文档统一管理与权限控制；
- 关键词检索与可溯源 RAG 问答；
- 知识关系图和工作台可视化；
- 收藏、用户、分类和审计治理；
- 前后端分离工程与 Cloudflare Pages 静态演示；
- 需求、设计、测试、UML、截图和最终报告。

### 1.2 成功标准

| 编号 | 成功标准 | 验收证据 |
|---|---|---|
| S-01 | 主链路可连续演示 | 登录→文档→问答→来源→图谱→审计 |
| S-02 | 权限边界正确 | 匿名、员工、作者、管理员、跨部门场景测试 |
| S-03 | 自动化测试通过 | pytest 全量测试日志 |
| S-04 | 前端可构建、可部署 | `npm run build`、`npm run pages:build` |
| S-05 | 静态演示可访问 | lkaya.com 首页、路由、资源和 Mock 登录正常 |
| S-06 | 交付材料完整 | 文档、UML、截图、报告和提交包清单 |

## 2 项目范围

### 2.1 范围内

- 登录、退出、会话、管理员/员工角色；
- 登录失败限流、密码哈希、失败审计；
- 文档 CRUD、分类、标签、版本、发布状态；
- 公开/内部/机密三级密级和部门隔离；
- 文档搜索、筛选、排序和分页；
- RAG 问答、本地摘要降级、来源和历史；
- 知识图谱同步、浏览和管理员维护；
- 收藏、工作台、用户目录、分类和审计；
- 健康检查、启动/停止脚本、生产构建；
- Cloudflare Pages 静态演示和 Mock 数据。

### 2.2 范围外

- 真实 SSO、企业组织架构同步、细粒度 RBAC；
- 真实附件上传解析、文档版本快照回滚；
- 向量数据库、语义重排、模型训练和大数据平台；
- 微服务、消息队列、分布式缓存和多租户；
- 移动原生应用、跨设备数据同步；
- 生产级 SLA、灾备和真实企业运营指标。

### 5.1 每周执行节奏

- 周一：确认本周目标、范围和依赖，更新风险。
- 周二至周四：完成功能增量，当天形成可验证结果。
- 周五：补测试并执行回归，记录缺陷。
- 周六：同步文档、图表和截图。
- 周日：按验收条件检查，决定是否进入下一阶段。

### 5.2 进度控制规则

1. 以“可启动、可调用、可测试、可审阅”为完成标准，不以口头状态代替产物。
2. 认证、权限、文档和 RAG 是关键路径；视觉优化不得挤占核心测试时间。
3. 发生延期时先压缩非核心范围，不减少权限、安全或回归测试。
4. 每周预留半天处理缺陷和文档同步。
5. 最终冻结阶段只修复验收问题，不新增业务模块。

### 7.1 质量目标

| 指标 | 目标 |

| 响应式 | 桌面和手机宽度无页面级横向溢出 |
| 浏览器质量 | 核心页面控制台无未处理错误 |
| 文档一致性 | 版本、技术栈、测试数量、路径与冻结代码一致 |

### 7.2 测试层次

1. **单元/服务测试**：文字切分、关键词、评分、权限、摘要和时间格式。
2. **接口测试**：登录、文档、问答、图谱、管理、分类和错误结构。
3. **安全测试**：越权、开放重定向、失败限流、密码存储和测试数据库隔离。
4. **系统测试**：健康检查、主链路、新数据库初始化和演示数据。
5. **前端人工巡检**：登录、空状态、错误、移动端、弹窗 Esc、未保存提示。

### 7.3 完成定义

一个任务只有同时满足以下条件才算完成：

- 代码可运行或文档可通过审阅；
- 主路径有验证结果；
- 异常和权限边界有处理；
- 必要测试已补充并回归；
- 相关文档、截图或接口说明已同步；
- 无新增阻断级缺陷或密钥泄露。
