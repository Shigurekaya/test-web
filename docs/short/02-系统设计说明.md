# 智慧企业知识财富库系统——系统设计说明（精简版）

| 项目 | 内容 |
|---|---|
| 架构风格 | 前后端分离、单体后端、分层服务 |
| 前端 | Vue 3 + Vite + Vue Router + ECharts |
| 后端 | Flask 3 + Flask-Login + SQLAlchemy |
| 数据库 | SQLite，可通过 `DATABASE_URL` 切换 |
| 质量基线 | pytest、Ruff、Vite 生产构建、Playwright 页面巡检 |

## 1 设计目标与原则

设计目标：

1. 打通登录、文档、权限、检索、问答、图谱和审计主链路。
2. 服务端权限是唯一可信边界，前端状态不作为授权依据。
3. RAG 回答可解释，展示来源、片段、模式和降级原因。
4. 文档、知识片段和图谱在保存后保持同步。
5. 依赖、构建、测试和启动均可复现。

设计原则：

- 简单优先：单体 Flask + SQLite 覆盖课程规模，不引入无法验证的分布式组件。
- 权限先行：先认证、再授权、后检索。
- 契约稳定：REST API 返回中文标签和统一错误结构。
- 渐进增强：外部大模型可选，失败时回退本地摘要。

## 2 总体架构

```text
Vue 3 SPA
  ├─ 页面、路由与状态
  ├─ ECharts 图表与图谱
  └─ /api 客户端
          │
Flask 应用
  ├─ Flask-Login 会话与角色
  ├─ REST API 与 Jinja 兼容层
  ├─ 文档、权限、RAG、图谱与审计服务
  └─ SQLAlchemy
          │
       SQLite
```

| 组成 | 职责 |
|---|---|
| Vue 3 SPA | 页面渲染、路由守卫、表单、图表和响应式交互 |
| Flask 应用工厂 | 配置、扩展、蓝图、错误页和种子数据初始化 |
| Flask-Login | 会话身份、登录状态和当前用户 |
| REST API | 认证、文档、问答、图谱、管理和系统信息 |
| SQLAlchemy | 数据模型、查询、关系与事务 |
| SQLite | 单机持久化；测试使用独立临时库 |

一次典型请求：

1. 浏览器进入 `/ui/`，Flask 返回 Vue 生产入口。
2. 前端调用 `/api/auth/session` 判断登录状态。
3. 业务页面请求 `/api/*`。
4. 后端校验会话、角色和文档权限。
5. 业务层读写数据库，并按需记录审计。
6. 前端统一处理响应、错误和页面状态。

## 4 模块与数据模型

| 模块 | 主要职责 |
|---|---|
| 认证与权限 | 登录、退出、会话、角色、登录限流 |
| 文档 | CRUD、分类、标签、版本、状态和收藏 |
| 检索 | 标题、摘要、正文、标签检索与筛选分页 |
| RAG | 切分、关键词、片段评分、Top-K、来源和降级 |
| 图谱 | 节点/关系同步、权限过滤和管理员维护 |
| 工作台 | 权限内统计、图表和最近动态 |
| 审计 | 登录、文档、问答等关键行为 |
| 管理 | 用户目录、分类、图谱和审计 |

| 表 | 关键字段 | 关系 |
|---|---|---|
| `users` | 用户名、密码哈希、显示名、角色、部门 | 一对多文档、问答、收藏、审计 |
| `categories` | 名称、说明 | 一对多文档 |
| `documents` | 标题、正文、摘要、部门、密级、状态、版本、标签 | 关联分类和作者 |
| `knowledge_chunks` | 文档、序号、正文、关键词 | 多对一文档 |
| `graph_nodes` | 名称、类型、说明、文档关联 | 名称唯一 |
| `graph_edges` | 起点、终点、关系名称 | 连接节点 |
| `favorites` | 用户、文档、时间 | 同一用户与文档唯一 |
| `qa_history` | 用户、问题、回答、来源、模式、时间 | 仅本人可见 |
| `audit_logs` | 用户、动作、明细、时间 | 管理员查询 |

数据一致性：

- 保存文档时重建知识片段并同步图谱；
- 删除文档时清理知识片段、收藏和关联图谱对象；
- 分类、部门和关键词使用幂等同步；
- API 输出中文标签，时间统一格式化；
- 测试数据库与演示数据库隔离。

## 5 权限与安全

权限执行链：

```text
请求 → 登录校验 → 角色校验 → 文档可见性 → 发布状态 → 业务处理 → 审计 → 响应
```

可见性规则：

```text
管理员
或作者本人
或已发布且密级为公开/内部
或已发布、密级为机密且同部门
```

安全措施：

- 密码使用哈希保存，不在 API 中返回；
- 登录失败按来源限流并写入审计；
- 未登录返回 401，越权返回 403；
- 登录回跳只允许站内路径，阻止开放重定向；
- 设置 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` 和权限策略头；
- API 响应设置 `Cache-Control: no-store`；
- `.env` 不进入 Git；
- 模型密钥只允许通过服务端环境变量注入。

## 6 核心流程

### 6.1 登录

1. 前端提交用户名和密码。
2. 后端校验限流、密码哈希和用户状态。
3. 成功后建立会话，失败时记录审计并返回统一错误。
4. 前端读取角色并跳转到站内安全地址。
5. 管理员菜单只在会话用户为管理员时显示，服务端仍再次校验。

### 6.2 文档保存

1. 前端校验标题和正文，展示未保存状态。
2. 提交元数据，后端再次校验。
3. 保存文档后重建知识片段、提取关键词并同步图谱。
4. 返回文档 ID，前端跳转详情页。
5. 成功或失败均提供明确反馈。

### 6.3 RAG 问答

1. 用户提交问题。
2. 后端先过滤可见、已发布文档。
3. 加载知识片段，分词并计算相关度。
4. 按 Top-K 聚合片段和来源，限制同文档片段数量。
5. 有模型配置时尝试生成回答；未配置或失败时生成本地摘要。
6. 保存历史和审计，返回模式、回答、来源和片段。
7. 前端展示来源、模式和历史记录。

### 6.4 图谱与审计

- 文档变化后同步节点和关系；
- 普通用户只获得可见文档及其相邻节点/关系；
- 管理员可查看完整图谱并维护节点/关系；
- 关键业务动作成功后写入审计；
- 管理员按操作类型、账号、明细和页码查询审计。

## 7 前端与接口设计

### 7.1 路由

| 路径 | 页面 | 权限 |
|---|---|---|
| `/login` | 登录 | 公开 |
| `/dashboard` | 工作台 | 登录 |
| `/documents` | 文档列表 | 登录 |
| `/documents/new` | 新建文档 | 登录 |
| `/documents/:id` | 文档详情 | 登录且文档可见 |
| `/documents/:id/edit` | 编辑文档 | 作者或管理员 |
| `/qa` | 智能问答 | 登录 |
| `/graph` | 知识关系图 | 登录 |
| `/admin/users` | 用户管理 | 管理员 |
| `/admin/audits` | 审计日志 | 管理员 |
| `/about` | 系统说明 | 登录 |

### 7.2 状态与交互

- `session` store 管理会话用户和系统元信息；
- `toast` store 管理成功、错误、警告和普通提示；
- `AppShell` 统一桌面侧栏、移动导航、搜索、新建入口和退出；
- `PageHeader` 统一页面标题与操作区；
- `BaseChart` 统一 ECharts 生命周期、窗口变化和点击事件；
- 表格、空状态、错误提示和危险操作使用统一样式与反馈。

响应式与可用性：

- 桌面侧栏在窄屏切换为抽屉，底部提供高频入口；
- 用户和审计表格在手机端转为字段明确的卡片；
- 文档编辑页提供大编辑区、预览、保存快捷键和未保存离开确认；
- 问答欢迎页不在手机端自动聚焦输入框，建议问题与输入框互不遮挡；
- 收藏、删除等操作有明确文本或无障碍名称；
- 弹窗提供对话框语义并支持 Esc 关闭；
- 支持 `prefers-reduced-motion`，降低动画影响。

### 7.3 REST API

| 分组 | 端点示例 |
|---|---|
| 系统 | `/api/health`、`/api/meta` |
| 认证 | `/api/auth/login`、`/api/auth/logout`、`/api/auth/session` |
| 工作台 | `/api/dashboard` |
| 文档 | `/api/documents`、`/api/documents/{id}` |
| 收藏 | `/api/documents/favorites`、`/api/documents/{id}/favorite` |
| 分类 | `/api/categories` |
| 问答 | `/api/qa`、`/api/qa/ask`、`/api/qa/history/{id}` |
| 图谱 | `/api/graph`、`/api/graph/manage`、`/api/graph/nodes`、`/api/graph/edges` |
| 管理 | `/api/admin/users`、`/api/admin/audits` |
| 关于 | `/api/about` |

错误约定：

| 状态码 | 含义 | 前端处理 |
|---|---|---|
| 400 | 参数缺失或格式错误 | 显示校验提示 |
| 401 | 未登录或会话失效 | 跳转登录页 |
| 403 | 角色或文档权限不足 | 显示无权限，不展示正文 |
| 404 | 资源不存在 | 显示不存在并返回列表 |
| 409 | 唯一性或冲突 | 提示修改后重试 |
| 429 | 登录尝试过多 | 提示稍后重试 |
| 500 | 服务端异常 | 显示通用错误，不暴露堆栈 |

## 8 部署与运行

本地主系统：

```powershell
cd frontend
npm install
npm run build
cd ..
.\.venv\Scripts\python.exe run.py
```

访问：

- 主界面：`http://127.0.0.1:5000/ui/`
- API：`http://127.0.0.1:5000/api/`
- 健康检查：`http://127.0.0.1:5000/api/health`

环境配置：

| 配置 | 必填 | 说明 |
|---|---|---|
| `SECRET_KEY` | 生产必填 | 会话签名密钥，不得提交真实值 |
| `DATABASE_URL` | 可选 | 默认 SQLite，测试使用独立临时库 |
| `OPENAI_API_KEY` | 可选 | 不配置时使用本地检索摘要 |
| `OPENAI_BASE_URL` | 可选 | 兼容 OpenAI 协议的服务地址 |
| `OPENAI_MODEL` | 可选 | 模型或端点标识 |

## 9 性能、限制与验证

当前策略：

- 前端使用路由级异步组件；
- 图表实例由 `BaseChart` 管理，避免重复初始化；
- 后端按权限先过滤再检索；
- 课程数据量下使用分页返回。

当前限制与改进方向：

| 位置 | 现状 | 改进方向 |
|---|---|---|
| 检索 | Python 内计算相关度 | FTS、向量索引、混合检索与重排 |
| 文档 | 版本为字段，无历史快照 | 版本表、差异和回滚 |
| 数据库 | SQLite + `create_all` | Alembic 迁移、PostgreSQL |
| 安全 | 会话 CSRF 未显式实现 | CSRF Token、持久化限流、细粒度 RBAC |
| 运维 | 请求内同步处理 | 任务队列、指标、结构化日志和备份 |
| 前端 | ECharts 形成较大异步包 | 图表按需加载和性能预算 |
| 问答 | 关键词检索为主 | 语义召回、重排和无答案识别 |

验证方式：

| 需求 | 验证 |
|---|---|
| 登录与角色 | 登录安全与 API 测试 |
| 文档与密级 | CRUD、权限矩阵和跨部门访问 |
| 检索问答 | RAG 单元/接口测试与来源核对 |
| 知识图谱 | 图谱接口、核心/完整视图和维护 |
| 审计与管理 | 筛选分页和角色拒绝测试 |
| 构建 | `npm run build` 和页面巡检 |
