# 用例描述：登录系统

| 项 | 内容 |
|----|------|
| 用例名称 | 登录系统 |
| 用例编号 | UC-AUTH-01 |
| 参与者 | 管理员、普通员工（主要参与者：用户） |
| 用例目标 | 校验用户身份，建立受保护的会话，并留下可追溯的登录记录 |
| 优先级 | 高 |
| 前置条件 | 系统已启动；用户拥有合法账号；数据库可用 |
| 后置条件 | 成功：建立会话并记录 `login` 审计；失败：不建立会话并记录 `login_failed` 审计 |
| 关联需求 | UR-AUTH-01 / 05 / 06 / 07；SR-AUTH-001 / 002 / 007 / 008 / 009 |
| 关联 UML | `docs/uml/02-登录时序图.puml` |
| 触发条件 | 用户打开登录页并提交凭据，或在未登录状态下访问受保护页面被重定向而来 |

## 基本事件流

| 步骤 | 参与者 | 系统动作 |
|------|--------|----------|
| 1 | 用户打开登录页 | 展示登录表单与演示账号说明；若已登录则直接跳转工作台 |
| 2 | 输入用户名与密码，点击登录 | 接收 `POST /auth/login`，读取 `username` / `password` / `next` |
| 3 | — | 取客户端来源地址，查询限流器：窗口内失败次数是否已达阈值 |
| 4 | — | 按用户名查询 `users` 表 |
| 5 | — | 用 scrypt 哈希比对口令（**先**判定锁定，**再**校验密码） |
| 6 | — | 口令匹配成功：清零该来源的失败计数 |
| 7 | — | 建立登录会话，写入 `login` 审计日志 |
| 8 | — | 计算回跳地址：仅接受站内相对路径，拒绝站外链接与协议相对 URL |
| 9 | — | 302 跳转工作台（或安全回跳地址），提示「登录成功」 |
| 10 | 用户进入工作台 | 展示个人可见范围统计、最近文档与最近提问 |

## 备选事件流

| 编号 | 条件 | 系统行为 |
|------|------|----------|
| 3a | 窗口内失败已达阈值 | 返回 429 与「登录失败次数过多，请 N 秒后再试」；**不再校验密码**，因此即便凭据正确也拒绝放行 |
| 4a | 用户名不存在 | 走与 5a 相同的失败分支，且不提示「用户名不存在」，避免账号枚举 |
| 5a | 口令不匹配 | 记录一次失败；写入 `login_failed` 审计（含用户名）；提示「用户名或密码错误」并停留在登录页 |
| 8a | `next` 为站外地址 | 丢弃该值，回落到工作台，防止登录后开放重定向 |
| 2a | 用户已登录 | 直接跳转工作台或安全回跳地址，不重复写审计 |

## 业务规则

1. 口令使用 Werkzeug `scrypt`（带盐慢哈希）存储与比对，**不明文落库**（SR-AUTH-008）。  
2. 登录失败必须留痕：只看成功记录的审计日志无法发现爆破行为（SR-AUTH-007）。  
3. 防爆破：默认同一来源 5 分钟内失败 8 次即锁定；窗口过期自动解锁；成功后清零（SR-AUTH-009）。  
4. 错误提示统一为「用户名或密码错误」，不区分是用户名错误还是密码错误。  
5. 回跳地址必须是站内相对路径，`//evil.com`、`https://...`、反斜杠开头等一律拒绝。  
6. 会话由 Flask-Login 维护，退出时清除会话。

## 特殊需求

- 性能：单次登录校验在演示数据规模下应 < 1 秒（scrypt 成本参数为固定值）。  
- 安全：锁定判定必须发生在密码校验**之前**，否则攻击者可在锁定后继续试探。  
- 可维护：阈值与窗口通过 `LOGIN_MAX_ATTEMPTS` / `LOGIN_WINDOW_SECONDS` 配置注入。
