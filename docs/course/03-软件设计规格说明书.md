## 1 引言

### 1.1 编写目的

本文档在《系统需求说明书》与《用户需求说明书》的基础上，对 V2.0 系统的总体架构、分层职责、模块边界、关键流程、数据模型、REST API、安全控制、异常降级、性能和部署方式给出可实施、可检查的设计说明。文档重点回答以下问题：

1. 前后端如何分工，Vue 3 单页应用与 Flask 服务端页面如何共存；
2. 认证、角色、部门与文档密级如何共同决定访问范围；
3. 文档保存后如何生成知识片段、关键词与图谱节点；
4. RAG 问答如何做到权限先过滤、检索可解释、来源可追溯、外部模型失败可降级；
5. 数据表、接口、错误码与测试如何形成可追踪的工程闭环。

本文档既可作为开发实现的核对依据，也可作为测试用例设计、答辩演示和后续维护的基线。

### 1.2 设计范围

设计范围覆盖当前工作区中的可运行系统，包括：

- Vue 3、Vite、Vue Router、原生 CSS 与 ECharts 构成的前端；
- Flask 3 提供、挂载于 `/api` 的 REST API；
- Flask-Login 会话鉴权、SQLAlchemy ORM 与 SQLite 持久化；
- 文档管理、分类、收藏、RAG 问答、知识关系图、审计与只读用户管理；
- 原 Jinja 页面、Bootstrap 页面样式与 Flask 蓝图兼容层；
- 单机启动脚本、前端构建、健康检查、自动化测试与课程演示部署。

本期明确不包含完整向量数据库、生产级模型运维、微服务治理、Redis 共享缓存或限流、消息队列、容器编排、真实 OA/HR/AD/LDAP 接口、在线协同编辑和真实附件解析。代码中的 `uploads/`、文件扩展名白名单和 `documents.filename` 属于附件能力预留，当前新增与编辑文档以文本正文为主，尚不构成完整的上传解析链路。

### 1.6 设计约束与假设

1. **部署形态**：面向单机或局域网课程演示，默认监听 `127.0.0.1:5000`。
2. **持久化**：默认使用 SQLite 文件 `instance/knowledge.db`，通过 SQLAlchemy 访问；可由环境变量 `DATABASE_URL` 替换连接串，但当前未提供数据库迁移工具。
3. **进程模型**：当前运行方式是 Flask 自带服务器，通常为单进程；登录限流器保存在进程内存中。
4. **前端交付**：开发时 Vite 运行于 `5173` 并代理 `/api`；生产构建输出到 `frontend/dist`，由 Flask 在 `/ui/` 提供。
5. **兼容策略**：REST API 与 Jinja 页面共享模型、RAG、图谱和权限判定逻辑，但保留两套控制器入口。
6. **演示数据**：首次建表由 `seed_all()` 创建演示用户、分类、文档、问答和审计数据；演示账号与内容均为虚构。
7. **外部模型可选**：未配置 `OPENAI_API_KEY` 时仅使用本地检索摘要；配置后才调用 OpenAI 兼容的 Chat Completions 接口。
8. **规模假设**：以课程演示与中小规模知识库为目标，不承诺互联网级并发、海量向量检索或多实例一致性。

## 2 设计目标与原则

### 2.1 设计目标

| 目标 | 设计落点 |
|---|---|
| 权限正确 | 文档列表、详情、问答、图谱、收藏和历史均以当前用户身份判定；机密文档不进入其他部门用户的检索候选集 |
| 前后端清晰 | Vue 通过 JSON API 访问后端；Jinja 页面保留为兼容入口；共享业务服务不复制算法 |
| 知识可追溯 | 问答返回文档来源、部门、片段摘要和相关度，并保存到 `qa_history` |
| 结果可解释 | 本地 RAG 使用分词重叠、关键词、标题、覆盖率和短语命中打分，不伪造大模型调用 |
| 失败可降级 | 没有大模型密钥时使用本地摘要；大模型失败时回退本地摘要并标记为本地模式 |
| 可演示、可复现 | 单机启动、自动建表、种子数据、健康检查、自动化测试与启停脚本齐备 |
| 易维护 | 应用工厂、蓝图、服务层、模型层与前端组件边界明确；配置走环境变量 |
| 诚实表达边界 | 不把预留能力描述为已实现，不在架构中虚构 Redis、向量库或微服务 |

### 2.2 设计原则

1. **最小权限原则**：访问控制在后端执行，前端隐藏菜单只承担界面提示，不作为安全边界。
2. **权限先于检索**：问答与图谱先计算当前用户可见文档集合，再在可见范围内读取片段或图结构。
3. **单一事实来源**：角色、密级、状态、动作标签集中定义；文档权限统一使用 `can_view_document()`。
4. **先可用后扩展**：用 SQLite、进程内限流和本地检索满足课程规模，同时通过接口和服务边界保留演进空间。
5. **显式优于隐式**：API 返回稳定字段与错误码；未命中、无权限、未登录分别返回明确结果。
6. **渐进式分离**：V2.0 引入 SPA 与 REST API，但不立即删除旧页面，降低迁移风险。
7. **安全默认值**：密码只保存哈希；生产配置启用 Secure Cookie；会话 Cookie 默认 HttpOnly、SameSite=Lax。
8. **可验证性**：关键规则应有自动化测试，测试使用独立数据库，不污染演示库。

## 3 总体架构

### 3.1 运行拓扑

```text
┌──────────────────────────────────────────────────────────────┐
│ 浏览器                                                       │
│  ├─ /ui/  Vue 3 SPA（Vue Router + 原生 CSS + ECharts）      │
│  └─ 旧入口 Jinja 页面（Bootstrap + 服务端模板）              │
└──────────────────────────────┬───────────────────────────────┘
                               │ HTTP / JSON / Cookie Session
┌──────────────────────────────▼───────────────────────────────┐
│ Flask 应用工厂 create_app()                                  │
│  ├─ /api       REST API 蓝图（Vue 前端主要边界）             │
│  ├─ /auth      Jinja 登录兼容入口                            │
│  ├─ /knowledge Jinja 文档兼容入口                            │
│  ├─ /qa        Jinja 问答兼容入口                            │
│  ├─ /graph     Jinja 图谱兼容入口                            │
│  ├─ /admin     Jinja 管理兼容入口                            │
│  └─ /ui        SPA 静态资源与 history fallback               │
├──────────────────────────────────────────────────────────────┤
│ 业务与权限：services.rag / services.graph / utils             │
├──────────────────────────────────────────────────────────────┤
│ 数据访问：SQLAlchemy ORM + SQLite                            │
│ 本地文件：instance/knowledge.db、uploads/                     │
└──────────────────────────────┬───────────────────────────────┘
                               │ 仅在配置 API Key 时
                    ┌──────────▼──────────┐
                    │ OpenAI 兼容大模型 API │
                    └─────────────────────┘
```

### 3.2 运行时组成

| 组成 | 当前实现 | 职责 |
|---|---|---|
| 主前端 | `frontend/` 下 Vue 3 源码；构建产物位于 `frontend/dist` | 页面渲染、路由、交互、图表、调用 REST API |
| SPA 容器 | `app/spa.py`，前缀 `/ui` | 返回构建后的 `index.html`、静态资源；前端 history 路由回退 |
| REST API | `app/api.py`，前缀 `/api` | 为 Vue 提供 JSON 资源接口、鉴权与错误码 |
| 兼容页面 | `app/blueprints/*.py` 与 `app/templates/` | 保留原有服务端页面、表单提交与旧地址 |
| 应用工厂 | `app/__init__.py` | 加载配置、初始化扩展、注册蓝图、错误页、过滤器与种子数据 |
| 业务服务 | `app/services/rag.py`、`app/services/graph.py` | 文档切分、检索、问答、图谱同步与过滤 |
| 数据模型 | `app/models.py` | 九张核心表的 ORM 映射与关系 |
| 扩展 | `SQLAlchemy`、`LoginManager` | ORM、会话加载、登录保护 |
| 运行脚本 | `run.py`、`start.ps1`、`stop.ps1`、`run_tests.ps1` | 前台/后台启动、停止、测试 |
| 外部服务 | OpenAI 兼容 Chat Completions | 可选生成式回答，不是系统启动必需依赖 |

### 3.3 架构特征

1. **同源部署**：生产演示中 Vue、API、旧页面与静态资源都由同一 Flask 进程提供，浏览器请求天然同源，会话 Cookie 可直接随请求发送。
2. **双控制器、共享领域逻辑**：REST API 与 Jinja 蓝图分别适配 JSON 和 HTML，但二者复用 `models`、`services.rag`、`services.graph` 与 `utils`。
3. **无独立前端服务器依赖**：开发环境需要 Vite；生产运行只需要已构建的 `frontend/dist` 与 Flask。
4. **无跨服务事务**：系统没有微服务，数据库、文件与业务逻辑均在同一进程内；唯一外部写依赖是可选的模型 API，且模型调用不改变核心数据。
5. **有状态会话**：认证状态保存在 Flask Session Cookie 中，服务端通过签名 Cookie 读取当前用户，不采用 JWT。

### 3.5 一次请求的典型路径

以 Vue 文档详情为例：

1. 浏览器访问 `/ui/documents/17`，`app/spa.py` 检测静态文件不存在后返回 `frontend/dist/index.html`。
2. Vue Router 匹配 `document-detail`，路由守卫先调用 `session.bootstrap()`。
3. `session.bootstrap()` 请求 `/api/meta` 与 `/api/auth/session`，确认登录态。
4. `DocumentDetailView.vue` 请求 `/api/documents/17`。
5. Flask 的 `api_login_required` 检查会话，`document_detail()` 读取文档并调用 `can_view_document()`。
6. 若允许访问，组装文档、相关文档、收藏状态和 `can_edit`；必要时写入查看审计。
7. 前端使用 Vue 模板插值渲染正文与来源，不把正文或模型回答当作未转义 HTML 注入。

## 4 前后端分层设计

### 4.1 分层总览

系统在逻辑上划分为表现层、接口/控制层、业务服务层、数据访问层和基础设施层。V2.0 同时存在 Vue SPA 与 Jinja 兼容页面，因此“表现层”包含两种渲染方式，但二者共享后端业务与数据规则。

| 层次 | 主要文件 | 主要职责 | 禁止事项 |
|---|---|---|---|
| Vue 表现层 | `frontend/src/views`、`components`、`style.css` | 路由页面、表单、交互、ECharts、可访问性 | 不自行决定机密文档权限，不伪造后端成功结果 |
| Jinja 兼容表现层 | `app/templates`、`app/static` | 旧页面的服务端渲染、表单、Bootstrap 样式 | 不在模板中实现检索与权限算法 |
| 接口/控制层 | `app/api.py`、`app/blueprints/*.py`、`app/spa.py` | JSON 接口、HTML 路由、参数读取、状态码与响应编排 | 不复制 RAG/图谱核心逻辑 |
| 业务服务层 | `app/services/rag.py`、`app/services/graph.py`、`app/utils.py` | 可见性过滤、切分、评分、回答、图谱同步、登录限流 | 不依赖具体 Vue 组件或 Jinja 模板 |
| 数据访问层 | `app/models.py`、`app/extensions.py` | 表映射、关系、查询、会话 | 不拼接页面文案或前端路由 |
| 基础设施层 | `config.py`、`__init__.py`、启动脚本、SQLite、可选模型 API | 配置、应用生命周期、持久化、日志、部署 | 不隐藏不可用依赖或越权开放数据 |

### 4.2 前端分层

| 子层 | 当前设计 |
|---|---|
| 入口 | `main.js` 创建 Vue 应用，安装 `router`，挂载 `App.vue` |
| 根组件 | `App.vue` 输出 `RouterView` 与全局 `ToastHost` |
| 路由 | `router/index.js` 定义懒加载页面、公共页、管理员页和全局守卫 |
| 布局 | `AppShell.vue` 提供侧栏、顶部搜索、新建文档入口、角色菜单和退出 |
| 页面 | `views/*.vue` 管理各自数据加载、表单状态、错误与交互 |
| 复用组件 | `PageHeader`、`BaseChart`、`EmptyState`、`StatCard`、`ToastHost`、`AppIcon` |
| 客户端 API | `api/client.js` 封装 `fetch`、JSON 序列化、`credentials: include` 与 `ApiError` |
| 全局轻量状态 | `stores/session.js` 管理用户与元信息；`stores/toast.js` 管理通知 |
| 样式 | `style.css` 原生 CSS；未引入 Vue UI 组件库 |
| 图表 | ECharts 按需注册 Bar、Graph、Pie、Grid、Legend、Tooltip 与 Canvas 渲染器 |

前端没有使用 Pinia、Vuex 或持久化状态插件。会话信息由一个 `reactive` 对象维护，页面数据主要保存在各页面的 `ref`/`reactive` 中。该设计适合当前页面数量与状态复杂度，降低依赖；若未来出现跨页面草稿、复杂缓存或离线能力，再考虑引入正式状态管理。

### 4.3 后端分层

1. **应用工厂**：`create_app()` 负责加载 `.env`、配置类、扩展、蓝图、错误处理、模板过滤器、数据库目录、上传目录及演示数据。
2. **API 控制器**：`app/api.py` 以 `/api` 为前缀返回 JSON；通过 `api_login_required`、`api_admin_required` 提供统一的 401/403 响应。
3. **兼容控制器**：`auth`、`main`、`knowledge`、`qa`、`graph`、`admin` 蓝图继续渲染 Jinja 页面，并保留原有表单语义和重定向。
4. **领域服务**：RAG 服务负责文档可见性、切分、评分、检索、回答、来源分组；图谱服务负责节点/边生成、同步、删除与 payload 组装。
5. **模型与扩展**：`db` 为全局 `SQLAlchemy` 实例，`login_manager` 为 Flask-Login 实例；用户加载器通过 `db.session.get(User, id)` 恢复当前用户。
6. **SPA 服务**：`spa` 蓝图只处理 `/ui`，不接管 `/api` 或旧页面；找不到静态文件时返回 `index.html` 以支持前端 history 路由。

### 4.4 依赖规则

```text
Vue View / Jinja Template
          │
          ▼
REST API Controller / Jinja Blueprint
          │
          ├──────────────► utils（鉴权、限流、格式化）
          ▼
services.rag / services.graph
          │
          ▼
SQLAlchemy Models ──► SQLite
          │
          └──────────────► 可选 OpenAI 兼容 API（仅 RAG 生成）
```

允许控制器调用服务、服务调用模型；不允许模型反向依赖控制器，不允许模板直接执行数据库查询。REST API 与 Jinja 控制器可以共享服务函数，但应避免把 HTML 跳转、Flash 消息等页面语义放入共享服务。

### 4.5 SPA 与兼容层共存策略

| 入口 | 路径 | 渲染方式 | 状态 |
|---|---|---|---|
| Vue 主界面 | `/ui/` | 静态 `index.html` + Vue 路由 | V2.0 主入口 |
| REST API | `/api/*` | JSON | Vue 使用的稳定边界 |
| 旧首页与业务页 | `/`、`/dashboard`、`/knowledge/*`、`/qa/*`、`/graph/*`、`/admin/*` | Jinja 服务端渲染 | 兼容保留 |
| 健康检查 | `/api/health`、`/health` | JSON | 新旧入口均可检查 |
| 静态资源 | `/ui/assets/*`、`/static/*` | Flask `send_from_directory` / 静态目录 | 分别服务 Vue 与旧页面 |

兼容层不是第二套数据库或第二套权限规则。文档、问答、图谱和审计继续写入同一数据库；文档可见性继续调用 `can_view_document()`。迁移时的主要风险是两个控制器入口的参数校验和响应格式可能出现差异，因此本次将 REST API 作为主要测试对象，同时对旧页面保留回归测试。

### 5.2 关键技术选择说明

#### 5.2.1 为什么使用 Flask 而非微服务

课程项目功能规模有限，REST API、旧页面、静态文件、业务服务和数据库可在同一 Flask 应用内完成。单进程部署减少网络边界、服务发现、配置分发和分布式追踪成本，也便于在 Windows 本机一键演示。当前没有独立认证服务、文档服务或 RAG 服务，不应在文档中声称已经采用微服务架构。

#### 5.2.2 为什么使用 SQLite

SQLite 文件天然适合课程演示：无需安装数据库服务，便于复制、备份和测试；SQLAlchemy 仍保留切换其他关系库的接口。系统规模较小时，列表、问答和图谱在 Python 层过滤均可接受。若数据量或并发增长，应优先增加数据库索引、全文检索或独立检索服务，而不是直接假设 SQLite 永久适用。

#### 5.2.3 为什么使用关键词检索而非向量数据库

当前 RAG 使用 jieba 分词、关键词、标题、覆盖率和短语命中计算相关度，所有中间结果可解释，且不需要 embedding 模型、向量索引或额外基础设施。对于课程演示中的制度文本，这种轻量方案能够展示“权限过滤—片段检索—来源追溯—可选生成”的完整链路。它不擅长同义词、跨语种和深层语义匹配，这是明确的性能与效果边界。

#### 5.2.4 为什么保留 Jinja 兼容层

V2.0 的目标是完成前后端分离，但项目原有页面、测试、演示脚本和内部链接已存在。通过保留 Jinja 页面，可以降低迁移期间的系统不可用风险，并为新旧实现对照提供依据。兼容层的代价是维护两套控制器；因此本次将共享服务、模型和权限函数集中，避免关键规则分叉。

#### 5.2.5 为什么没有引入 Redis

登录限流当前使用模块级 `RateLimiter` 字典，适合单机、单进程课程环境。引入 Redis 会增加安装、配置、故障模式和演示复杂度，而当前没有多实例部署需求。代码注释已明确：多进程或多机部署必须改用共享存储，但该能力尚未实现，因此本文档不将其列为当前特性。

## 6 模块设计

### 6.1 认证、角色与权限模块

#### 6.1.1 模块职责

认证权限模块负责用户名密码登录、会话建立与恢复、退出、角色判断、文档密级判断、管理员保护以及登录失败限流。REST 与 Jinja 共用同一个 `User` 模型和 `can_view_document()` 规则，但分别返回 JSON 错误或 HTML 错误页。

#### 6.1.2 身份模型

| 属性 | 设计含义 |
|---|---|
| `username` | 登录标识，唯一且建立索引 |
| `password_hash` | 仅保存密码哈希，不保存明文 |
| `display_name` | 界面展示名称 |
| `role` | `admin` 或 `employee` |
| `department` | 用于机密文档部门隔离 |
| `is_admin` | ORM 属性，判断 `role == "admin"` |

角色只分管理员和员工，不在数据库中建立独立角色表、权限表或策略表。部门不是角色，而是用户属性，与文档 `department` 一起参与机密文档判定。

#### 6.1.3 权限矩阵

| 操作 | 未登录 | 普通员工 | 管理员 |
|---|---:|---:|---:|
| 查看公共/内部文档 | 否 | 是 | 是 |
| 查看同部门机密文档 | 否 | 是 | 是 |
| 查看其他部门机密文档 | 否 | 否（作者除外） | 是 |
| 查看已发布文档列表 | 否 | 仅可见范围 | 全部 |
| 查看草稿/归档详情 | 否 | 仅本人作者 | 全部 |
| 新建文档 | 否 | 是 | 是 |
| 编辑/删除文档 | 否 | 仅本人作者 | 任意文档 |
| 收藏文档 | 否 | 仅可见文档 | 任意可见文档 |
| 查看个人问答历史 | 否 | 仅本人 | 本人或任意 |
| 查看图谱 | 否 | 可见文档范围 | 全量文档范围 |
| 新增图谱节点/边 | 否 | 否 | 是 |
| 查看分类 | 否 | 是 | 是 |
| 新增分类 | 否 | 否 | 是 |
| 查看用户列表 | 否 | 否 | 是 |
| 查看审计日志 | 否 | 否 | 是 |

#### 6.1.4 文档可见性规则

`can_view_document(user, doc)` 的当前实现为：

```text
若 user 为空：拒绝
若 user.is_admin：允许
若 doc.visibility == "secret"：
    允许当且仅当 doc.department == user.department 或 doc.author_id == user.id
若 doc.visibility == "internal"：允许
若 doc.visibility == "public"：允许
```

“公开”和“内部”都要求用户已经登录。系统的公开不是匿名公开；“public”表示登录用户之间均可访问，“internal”同样对所有登录员工开放，差别主要体现为业务标签和展示分组。若需要更细的部门内网、项目组或岗位级规则，需要扩展模型并修改统一判定函数。

#### 6.1.5 已发布状态与访问状态的组合

列表和 RAG 检索使用 `searchable_documents(user)`：先只取 `status="published"` 的文档，再应用可见性过滤。详情接口在可见性检查之后，额外允许管理员或作者查看非发布文档；其他用户查看草稿或归档时返回 403。因此判断顺序为：

1. 文档是否存在；
2. 当前用户是否满足密级规则；
3. 文档是否已发布，或当前用户是否为作者/管理员。

#### 6.1.6 会话与保护包装

- Flask-Login 使用 `login_user()` 建立会话，使用 `logout_user()` 清除会话；
- 用户加载器从 Session 中的用户 ID 调用 `db.session.get(User, int(user_id))`；
- API 的 `api_login_required` 未登录返回 HTTP 401 与 `AUTH_REQUIRED`；
- API 的 `api_admin_required` 未登录返回 401，已登录但非管理员返回 403 与 `FORBIDDEN`；
- Jinja 页面使用 `@login_required`，未登录由 Flask-Login 跳转登录页；
- 旧页面的管理员保护使用 `admin_required`，普通员工访问返回 403 错误页。

#### 6.1.7 登录限流

`RateLimiter` 以客户端 `remote_addr` 为键维护时间窗口内的失败时间戳。默认阈值为 8 次、窗口 300 秒，可由 `LOGIN_MAX_ATTEMPTS` 与 `LOGIN_WINDOW_SECONDS` 配置。处理顺序是“先检查锁定，再校验密码”，因此锁定期间即使输入正确密码也会被拒绝。登录成功后清空该来源的失败计数。

当前限流器是模块级进程内单例，适用于单机演示；它不跨进程共享，也不在数据库中持久化。重启 Flask 会清空限流状态。多实例部署必须引入共享限流存储，或把限流迁移到网关层。

#### 6.1.8 统计口径

权限不仅影响文档正文，也影响统计数字。当前实现的口径如下：

| 统计项 | 口径 |
|---|---|
| 工作台可见文档数、部门分布、分类分布 | 当前用户可见的已发布文档 |
| 工作台收藏数、问答总数、近 7 天问答 | 当前用户个人数据 |
| 工作台近期审计 | 仅管理员返回最近记录 |
| 关于页文档数、Chunk 数 | 当前用户可见的已发布文档及其片段 |
| 关于页问答数 | 当前用户个人问答数 |
| 关于页节点/边数 | 当前为全库结构概览数字 |
| REST 图谱节点/边 | 以当前用户可见文档节点为起点进行邻接过滤 |
| 分类接口的 `document_count` | 当前为全库分类计数，不是按用户权限重算 |

上述统计口径需要在测试和演示时区分，避免把“全库结构概览”误解为“图谱接口没有权限过滤”。

### 6.2 知识文档模块

#### 6.2.1 模块职责

文档模块负责列表、筛选、排序、分页、详情、新增、编辑、删除、收藏和分类读取。文档保存后还会触发知识片段重建、图谱同步与审计写入。

#### 6.2.2 查询与筛选

REST 列表接口支持以下查询参数：

| 参数 | 默认值 | 规则 |
|---|---|---|
| `q` | 空 | 关键词检索标题、摘要、正文、标签 |
| `category_id` | 空 | 按分类 ID 过滤 |
| `department` | 空 | 按文档部门精确过滤 |
| `visibility` | 空 | 按 `public` / `internal` / `secret` 过滤 |
| `sort` | `updated` | `updated`、`title`、`department` |
| `page` | `1` | 最小为 1，超过总页数时夹到最后一页 |
| `per_page` | `9` | 最小 1、最大 50 |

先对 `searchable_documents(current_user)` 结果应用分类、部门和密级过滤，再执行关键词排序或普通排序。因为当前可见文档在 Python 列表中处理，所以过滤、排序和分页是应用层完成，未使用数据库全文索引。

关键词列表排序 `rank_documents()` 的权重为：

| 命中位置 | 加分 |
|---|---:|
| 完整查询串命中标题 | +20 |
| 完整查询串命中标签 | +12 |
| 完整查询串命中摘要 | +8 |
| 完整查询串命中正文 | +4 |
| 查询词与标题分词重叠 | 每项 +3 |
| 查询词与标签分词重叠 | 每项 +2 |
| 查询词与摘要分词重叠 | 每项 +1 |

同分时按 `updated_at` 倒序。由于查询命中为 0 的文档不会进入结果，关键词检索是相关性筛选，而不是简单地把所有文档原顺序返回。

#### 6.2.3 详情与相关阅读

详情接口返回文档正文、摘要、分类、部门、密级、状态、版本、标签、作者、时间、字数、片段数、收藏状态和 `can_edit`。同时调用 `related_documents()` 按同分类、同部门、标签重叠计分，取最多 4 篇可见的已发布文档作为相关阅读：

| 相关度信号 | 加分 |
|---|---:|
| 同分类 | +5 |
| 同部门 | +2 |
| 共同标签 | 每个 +3 |

相关文档候选先取最近更新的 40 篇，再检查权限，避免先返回无权内容再由前端隐藏。

#### 6.2.4 新增与编辑

REST 新增和更新共用 `_apply_document_payload()`：

1. `title` 与 `content` 去空白后必须非空；
2. `category_id` 必须为数字或空，若提供则分类必须存在；
3. 摘要优先使用请求值，截断到 500 字；为空则从正文自动截取；
4. 部门必须在固定部门列表内，否则保留原部门或回退当前用户部门；
5. 密级只接受 `public` / `internal` / `secret`，未知或空值回退 `internal`；
6. 状态只接受 `draft` / `published` / `archived`，未知或空值回退 `published`；
7. 版本为空时回退 `1.0`；
8. 标签可以传数组或逗号分隔字符串，最终存为逗号拼接文本；
9. 分类为空时允许“未分类”。

`PUT /api/documents/<id>` 采用全量更新语义：标题和正文必须重新提交，未提交的密级、状态等字段会按默认规则处理。Vue 编辑器会提交完整表单，因此正常使用不受影响；外部调用方必须按全量资源理解该接口。

#### 6.2.5 保存后的派生数据

`_finalize_document()` 的顺序为：

1. `db.session.flush()` 获取新文档 ID；
2. `rebuild_chunks_for_document()` 删除旧片段、重新切分、提取关键词并提交；
3. `sync_document_graph()` 同步文档节点、部门、分类与关键词关系并提交；
4. 写入 `create_document` 或 `edit_document` 审计；
5. 最后再次提交并返回文档。

这种设计保证正常路径下片段和图谱与文档同步更新，但也意味着多个服务函数各自提交事务。当前没有跨步骤的补偿任务：若文档提交成功后图谱或审计阶段抛出异常，可能出现文档、片段、图谱与审计的短暂不一致。演示规模下可通过重新保存文档触发幂等重建；生产化时应收紧事务边界、增加重试或一致性检查任务。

#### 6.2.6 删除与收藏

- 删除前检查当前用户是管理员或文档作者；
- 调用 `remove_document_graph()` 删除文档节点及所有关联边；
- 由 Document 的 ORM 关系级联删除 `knowledge_chunks` 与 `favorites`；
- 写入 `delete_document` 审计后删除文档；
- 删除为硬删除，不进入回收站。

收藏采用“切换”语义：若当前用户已有收藏则删除，否则新增。数据库对 `(user_id, document_id)` 建立唯一约束，防止重复记录。收藏列表在读取时再次检查文档可见性，因此文档密级变化后，用户不会继续看到无权文档的收藏卡片。

#### 6.2.7 分类

分类字段包括名称和说明。名称全局唯一。REST 接口提供分类读取和管理员新增分类；Jinja 兼容页也提供分类列表和新增表单。当前没有分类编辑、删除或合并 API，分类被文档引用时也不提供级联迁移操作。

#### 6.2.8 附件与上传边界

配置中存在 `UPLOAD_FOLDER`、`MAX_CONTENT_LENGTH=16 MB`、`ALLOWED_EXTENSIONS={txt, md, pdf, docx}` 与 `Document.filename` 字段，但当前 REST 新增/编辑主要接收 `content` 文本，没有实现 PDF/DOCX 解析、文件上传端点或附件下载端点。因此本设计不把“附件管理”列为已完成能力。

### 6.3 RAG 问答模块

#### 6.3.1 模块职责

RAG 模块负责把文档正文转换为知识片段、为片段提取关键词、按用户权限检索、计算相关度、提供本地摘要或可选大模型回答、返回来源并持久化问答历史。

#### 6.3.2 文档切分

`chunk_text()` 的规则为：

1. 去除首尾空白，空文本返回空片段；
2. 以两个及以上换行符切分段落；
3. 段落合并到不超过 `CHUNK_SIZE`（默认 400）的缓冲区；
4. 单个超长段落按窗口切片；
5. 超长段落的相邻窗口使用 `CHUNK_OVERLAP`（默认 50）重叠；
6. 所有片段按顺序写入 `knowledge_chunks`，`chunk_index` 从 0 开始。

保存文档时会先删除该文档旧片段，再重新生成，因此重复编辑不会累积重复索引。`knowledge_chunks.keywords` 保存 jieba `extract_tags` 提取的前 8 个关键词，用逗号分隔。

#### 6.3.3 分词与领域词

检索分词组合三类信号：

1. `jieba.lcut()` 得到的词典词；
2. 注册到 jieba 的领域补充词，如“年假”“差旅”“密钥轮换”“采购”“知识财富库”等；
3. 当分词结果为空时，使用连续汉字的相邻二字组作为兜底。

单个汉字会被过滤，以减少“的”“了”“是”等噪声。纯单字查询可能没有 token，此时仍可依赖完整短语子串命中。

#### 6.3.4 片段评分

对每个候选片段，先计算：

```text
content_hit = |问题词集合 ∩ 片段内容词集合|
kw_hit      = |问题词集合 ∩ 片段关键词集合|
title_hit   = |问题词集合 ∩ 标题词集合|
coverage    = content_hit / |问题词集合|（问题词集合为空时为 0）
```

基础得分为：

```text
score = 1.0 × content_hit
      + 1.8 × kw_hit
      + 3.2 × title_hit
      + 2.0 × coverage
```

再叠加短语信号：

| 条件 | 加分 |
|---|---:|
| 完整问题串出现在片段正文 | +10 |
| 问题长度 ≥ 4 且前半部分出现在正文 | +4 |
| 完整问题串出现在标题 | +6 |
| 去掉句末疑问助词后的核心短语出现在正文 | +5 |

评分逻辑的意图是“标题强相关、关键词次之、正文命中为基础、覆盖率奖励多词同时命中、完整短语作为强信号”。它不是 TF-IDF、BM25 或向量相似度，不应在论文或答辩中混淆表述。

#### 6.3.5 权限先过滤

`retrieve()` 的执行顺序为：

1. 调用 `searchable_documents(user)` 得到当前用户可见的已发布文档；
2. 提取允许的 `document_id` 集合；
3. 只查询这些文档的 `knowledge_chunks`；
4. 对候选片段评分、排序；
5. 同一文档最多保留 2 个片段；
6. 截取 `TOP_K`（默认 5）个最终片段。

机密文档不会先进入候选再被前端隐藏，因此接口、日志和响应中都不会返回其他部门机密正文。

#### 6.3.6 片段合并与来源

`group_hits_by_document()` 把片段按文档聚合，文档相关度取该文档命中片段的最高分，片段列表保留原文和 `fragment_no`/`fragment_total`。响应包含：

- `fragments`：按全局得分排序的片段数组；
- `sources`：按文档聚合的来源数组；
- `document_id`、`title`、`department`、`score`；
- 每个来源下的片段内容。

#### 6.3.7 回答生成模式

| 模式 | 触发条件 | 回答生成 | `qa_history.mode` |
|---|---|---|---|
| 本地检索摘要 | 未配置 API Key，或无检索命中 | 拼接命中标题、摘要、来源、部门、相关度 | `local` |
| 大模型生成 | 配置 API Key 且有命中，调用成功 | 将命中片段作为上下文，调用 `/chat/completions` | `llm` |
| 大模型失败降级 | 调用异常 | 返回失败说明并拼接本地摘要 | `local` |

本地回答会明确提示“当前为本地检索摘要模式”，不会伪装成大模型输出。系统提示词要求模型“只能依据给定资料回答，资料不足要说明，并指出依据文档标题”，但模型输出仍需用户核对来源。

外部请求使用标准库 `urllib.request`，向配置的 `OPENAI_BASE_URL + /chat/completions` 发送 Bearer Token，模型名由 `OPENAI_MODEL` 配置，`temperature=0.2`。当前实现调用超时为 60 秒；配置中的 `OPENAI_TIMEOUT` 尚未接入该调用参数，属于后续维护项。

#### 6.3.8 问答历史

每次问答都写入 `qa_history`，保存用户、问题、回答、来源 JSON 字符串、模式和创建时间。`sources` 在数据库中是 TEXT，API 返回时尝试 `json.loads()`，解析失败则返回空数组。用户只能读取自己的历史，管理员可读取任意历史；越权返回 403。

### 6.4 知识关系图模块

#### 6.4.1 图谱模型

图谱由 `graph_nodes` 和 `graph_edges` 两张表组成。节点名称全局唯一，类型包括：

| 类型 | 当前来源 |
|---|---|
| `document` | 文档自动同步，名称格式为 `文档:<标题>` |
| `department` | 文档所属部门或种子数据 |
| `keyword` | 文档标签或正文关键词 |
| `concept` | 分类节点、手工概念节点及默认类型 |
| `project` | 种子数据或管理员手工维护 |

分类在业务上作为“分类节点”使用，但当前代码实际把其 `node_type` 设为 `concept`，没有单独的 `category` 枚举值。文档保存触发 `sync_document_graph()` 时：

1. 查找或创建文档节点；
2. 创建/复用部门节点，并建立“属于”边；
3. 若文档有分类，创建/复用分类名称的 `concept` 节点，并建立“分类为”边；
4. 读取文档标签；若没有标签，则从正文提取最多 5 个关键词并回填 `doc.tags`；
5. 最多取 8 个标签建立 `keyword` 节点和“含有”边；
6. 对同名节点复用，对同一三元组边通过应用层查询去重。

#### 6.4.2 节点变更与删除

- 文档节点以 `document_id` 关联文档，标题变化时同步节点名称并清理旧名称冲突节点；
- 删除文档前显式删除其文档节点与所有入边/出边；
- `ensure_edge()` 在应用层检查 `(source, target, relation)` 是否已存在，但数据库没有对应唯一约束；
- `cleanup_orphan_document_nodes()` 可清理 `document_id` 指向不存在文档的节点，但当前启动流程未自动调用该清理函数；
- 管理端新增边时，如果起点或终点名称不存在，会以 `concept` 类型自动创建节点。

#### 6.4.3 图谱权限过滤

REST `/api/graph` 的过滤算法为：

1. 读取完整节点和边；
2. 计算当前用户可见的已发布文档 ID；
3. 只把 `document_id` 位于可见集合的文档节点作为起始节点；
4. 保留任一端连接可见文档节点的边；
5. 把这些边的另一端部门、分类或关键词节点加入可见集合；
6. 最后只返回两端都在可见集合中的边。

这样不会把其他部门机密文档的标题、部门关系或关键词直接暴露给当前用户。过滤在应用层完成，不是数据库行级安全，也不保证全库图结构统计按用户隔离。

#### 6.4.4 管理端维护

管理员可读取最近 60 个节点和 60 条边，新增节点或新增边。Vue 在 GraphView 中以模态框完成维护，避免单独的管理路由；Jinja 页面仍保留 `/graph/manage`。节点类型由前端提供 5 种选项，但后端新增节点时不会对 `node_type` 做严格白名单校验。

#### 6.4.5 前端可视化

`BaseChart.vue` 按需注册 ECharts 模块，`GraphView.vue` 使用 `graph` 系列的 `force` 布局，支持拖拽、缩放、悬停邻接高亮、点击文档节点跳转详情。节点大小按类型区分，文档节点为 42，其余为 28；节点颜色由图谱服务返回。ECharts 图表在组件卸载时销毁并断开 `ResizeObserver`，降低内存泄漏风险。

### 6.5 审计模块

#### 6.5.1 审计目标

审计模块用于回答“谁在什么时间对什么对象做了什么”。它覆盖登录、失败登录、退出、文档查看、文档创建、文档编辑、文档删除和智能问答。审计不作为业务数据的备份，也不能替代应用日志；它记录的是面向管理员追查的业务事件。

#### 6.5.2 动作字典

| `action` | 中文标签 | 触发点 | 关键明细 |
|---|---|---|---|
| `login` | 登录 | 密码校验成功并建立会话后 | 用户名 |
| `login_failed` | 登录失败 | 用户不存在或密码错误 | 输入的用户名（可为空） |
| `logout` | 退出 | 已登录用户主动退出 | 用户名 |
| `view_document` | 查看文档 | 文档详情成功访问 | 文档 ID 与标题 |
| `create_document` | 创建文档 | 文档保存事务完成 | 文档 ID 与标题 |
| `edit_document` | 编辑文档 | 编辑保存事务完成 | 文档 ID 与标题 |
| `delete_document` | 删除文档 | 删除提交前 | 文档 ID 与标题 |
| `ask_qa` | 智能问答 | 问答结果写入后 | 问题摘要 |

`audit_detail()` 统一拼接明细格式，例如“查看文档 #17 《员工年休假管理办法》”或“提问：员工年假有几天？”问题文本截断到 80 字，避免审计列表被超长问题撑开。

#### 6.5.3 写入与去重

- 登录失败时即使用户名不存在也写入 `login_failed`，其中 `user_id` 为空；
- 同一用户对同一文档的重复打开，在 2 分钟内最多记录一次查看审计；查询最近 5 条 `view_document` 明细进行判断；
- 文档增删改在业务操作提交前后写入，明细包含文档 ID 与标题，便于文档删除后仍能追溯；
- 问答在 `ask()` 保存历史后写入审计；
- 退出先写审计再清除会话，确保退出事件不丢失。

#### 6.5.4 查询与展示

管理员审计接口支持按动作、用户名、明细关键字筛选，固定每页 25 条，按 `created_at DESC, id DESC` 排序，并返回动作统计。动作筛选只接受动作字典中的值，未知动作被忽略，避免任意字段查询。普通员工访问管理接口返回 403。

审计详情中的用户名通过外连接关联 `users` 表；若用户不存在或匿名失败登录，展示“匿名/未知”。当前没有日志防篡改、哈希链、归档分区或保留期自动清理机制。

### 6.6 管理模块

#### 6.6.1 用户管理

当前“用户管理”是只读列表：管理员可查看用户总数、管理员数、员工数，以及每个用户的文档数量。REST 接口为 `GET /api/admin/users`，Jinja 页面为 `/admin/users`。系统没有用户新增、编辑、停用、重置密码或角色变更接口；用户由种子数据或数据库级维护产生。

#### 6.6.2 分类管理

管理员可新增分类，分类名称必填且不得重复。REST 为 `POST /api/categories`，旧页面为 `/knowledge/categories` 的 POST。当前无分类更新、删除、排序和批量迁移功能。

#### 6.6.3 图谱维护

管理员可新增节点与边，查看最近节点/边列表。REST 为 `/api/graph/manage`、`/api/graph/nodes`、`/api/graph/edges`，旧页面为 `/graph/manage`。节点名称和边端点不能为空，边关系为空时默认“关联”。

#### 6.6.4 审计管理

管理员可查看筛选后的审计列表、统计和分页。Vue 通过 `AuditsView.vue` 调用 `GET /api/admin/audits`，旧页面通过 `/admin/audits` 服务端渲染。

#### 6.6.5 管理边界

管理功能以“课程演示可操作”为目标，不构建完整后台 RBAC 平台。用户不能在前端自助注册；管理员也不能在界面中创建用户。这样的取舍降低了用户生命周期管理的复杂度，但与生产系统的账号治理能力有明显差距。

#### 6.7.2 路由守卫

`router.beforeEach()` 每次导航前执行：

1. 调用 `session.bootstrap()`；首次加载时请求 `/api/meta` 与 `/api/auth/session`；
2. 若目标不是公共页且没有用户，跳转 `/login?redirect=<当前路径>`；
3. 若目标是登录页但已有用户，跳转工作台；
4. 若目标声明 `meta.admin` 且用户不是管理员，跳转工作台；
5. 导航完成后设置浏览器标题。

前端守卫用于改善体验，不是权限边界；后端仍会对每个业务接口做身份和角色校验。

#### 6.7.3 状态管理

| 状态 | 位置 | 生命周期 | 说明 |
|---|---|---|---|
| 当前用户、元信息、加载状态 | `stores/session.js` | 应用运行期 | `reactive` 对象；`bootstrap()` 去重并发初始化 |
| Toast 通知 | `stores/toast.js` | 应用运行期 | 数组状态，定时移除 |
| 文档列表筛选与分页 | `DocumentsView.vue` | 页面实例 | 与 URL query 同步，刷新可恢复 |
| 文档表单 | `DocumentEditorView.vue` | 页面实例 | `reactive` 表单，提交前转换为 API payload |
| 问答对话流 | `QaView.vue` | 页面实例 | 当前会话内消息数组，历史通过 API 读取 |
| 图谱数据与维护弹窗 | `GraphView.vue` | 页面实例 | 图谱 payload、管理节点/边表单 |
| 工作台、审计、用户、关于数据 | 各 View 的 `ref` | 页面实例 | 每次加载重新请求，不做跨页缓存 |

状态设计避免把敏感文档正文长期放进全局 store。页面卸载后正文引用随组件释放；浏览器历史、URL query 只保存筛选条件，不保存正文。

#### 6.7.4 API 客户端与错误传播

`api/client.js` 统一执行：

- 基础路径 `/api`；
- `credentials: 'include'`，使同源会话 Cookie 随请求发送；
- 有请求体时自动设置 `Content-Type: application/json` 并 `JSON.stringify()`；
- 根据 `Content-Type` 解析 JSON；
- 非 2xx 响应抛出 `ApiError`，保留 `status` 与 `payload`；
- 页面捕获错误后展示内联提示或 Toast。

当前没有全局 401 自动重定向拦截。页面导航依赖路由守卫；业务请求若在登录过期后返回 401，通常在页面内显示后端错误信息，用户可重新进入受保护页面触发守卫。

#### 6.7.5 开发与生产路径

- 开发：`npm run dev` 启动 Vite，`vite.config.js` 把 `/api` 代理到 `http://127.0.0.1:5000`；
- 生产：`npm run build` 使用 `base: '/ui/'` 生成资源；
- Flask 的 `/ui` 蓝图返回 `dist/index.html` 与静态文件；
- 对 `/ui/documents/17` 等深层路径，找不到同名静态文件时回退 `index.html`，由 Vue Router 处理；
- `dist/index.html` 不存在时返回 HTTP 503 和构建提示，而不是空白页。

## 7 关键流程设计

### 7.1 登录流程

对应 UML：[02-登录时序图](../uml/rendered/02-登录时序图.png)、[源文件](../uml/02-登录时序图.puml)。

#### 7.1.1 主流程

1. 用户访问 `/ui/login`，前端读取 `/api/meta` 获取演示账号与系统信息；
2. 用户输入用户名、密码并提交；
3. `POST /api/auth/login` 先检查当前客户端地址是否被限流；
4. 若被锁定，返回 429、错误文字和 `retry_after`；
5. 若未被锁定，按用户名查询用户并调用 `check_password()`；
6. 验证失败：记录失败计数与 `login_failed` 审计，返回 401 和统一错误“用户名或密码错误”；
7. 验证成功：清空限流计数，调用 `login_user()` 建立会话；
8. 写入 `login` 审计；
9. 返回用户信息，前端切换到工作台；
10. 若存在 `redirect` query，前端只在前端路由内替换到站内路径。

#### 7.1.2 异常分支

| 分支 | 行为 |
|---|---|
| 用户名为空或密码为空 | 前端本地提示；后端按无效凭据处理 |
| 用户不存在 | 不区分用户名与密码，返回 401，同时写失败审计 |
| 密码错误 | 返回 401，累计失败次数 |
| 达到阈值 | 后续请求优先返回 429，即使密码正确也不校验 |
| 会话已存在 | 登录页守卫直接转向工作台 |
| 旧页面登录 | `safe_next_url()` 仅允许站内相对路径，拒绝 `http://`、`//host`、反斜杠、换行与空字符 |

### 7.2 文档创建/编辑流程

对应 UML：[04-文档发布活动图](../uml/rendered/04-文档发布活动图.png)、[05-文档状态图](../uml/rendered/05-文档状态图.png)。

1. 用户打开新建或编辑页面；
2. 新建时请求分类列表；编辑时先请求文档详情并检查 `can_edit`；
3. 用户填写标题、正文、摘要、分类、部门、密级、状态、版本和标签；
4. 前端做必填校验并转换标签数组；
5. API 再次校验标题和正文，不信任前端；
6. 校验分类存在、部门合法、密级和状态属于白名单；
7. 新建文档时写入作者 ID；编辑时校验当前用户为作者或管理员；
8. `flush()` 后重建知识片段；
9. 同步图谱节点与边；
10. 写审计并返回文档；
11. Vue 跳转详情页；旧页面通过重定向进入详情页并显示 Flash 消息。

#### 7.2.1 状态流转

| 当前状态 | 操作 | 目标状态 | 约束 |
|---|---|---|---|
| 无 | 新建并选择 `draft` | 草稿 | 作者或管理员可见 |
| 无 | 新建并选择 `published` | 已发布 | 进入列表与 RAG 检索 |
| 草稿 | 编辑为 `published` | 已发布 | 作者或管理员 |
| 已发布 | 编辑为 `draft` | 草稿 | 立即退出普通用户的列表与检索 |
| 已发布/草稿 | 编辑为 `archived` | 已归档 | 普通用户不再从列表/检索访问 |
| 任意 | 删除 | 记录删除 | 硬删除，图谱边同步清理 |

状态是由编辑表单显式选择的字段，不是审批工作流。系统没有发布审批人、定时发布、版本快照或回滚功能；“版本”目前只是文本字段，不会自动递增或保存历史版本。

### 7.3 RAG 问答流程

对应 UML：[03-RAG 问答时序图](../uml/rendered/03-RAG问答时序图.png)。

1. 用户在 QaView 输入问题或点击示例问题；
2. 前端 `POST /api/qa/ask`；
3. API 校验问题非空；
4. `ask()` 调用 `retrieve()`；
5. `retrieve()` 先计算当前用户可见的已发布文档 ID；
6. 只查询这些文档的 `knowledge_chunks`；
7. jieba 分词并计算每个片段得分；
8. 排序后同一文档最多保留 2 个片段，截取 Top-K；
9. 若配置 API Key 且有命中，构造上下文调用大模型；
10. 若无 Key、无命中或调用失败，生成本地摘要；
11. 写入 `qa_history`，保存问题、回答、来源、模式；
12. 写入 `ask_qa` 审计；
13. 返回回答、模式、来源分组与原始片段；
14. 前端显示回答、来源折叠卡片和相关度；历史详情从 `/api/qa/history/<id>` 读取。

### 7.4 图谱同步与过滤流程

1. 文档保存成功后，`sync_document_graph(doc)` 被调用；
2. 以 `doc.id` 查找现有文档节点，没有则创建；
3. 标题改变时更新节点名称；
4. 复用/创建部门节点，建立“属于”边；
5. 有分类时复用/创建分类概念节点，建立“分类为”边；
6. 读取标签；无标签时从正文提取关键词并回填文档标签；
7. 为最多 8 个标签复用/创建关键词节点，建立“含有”边；
8. 图数据接口读取完整图后，以当前用户可见文档节点为起点过滤；
9. 返回节点、边、类型分类与样式信息给 ECharts；
10. 用户点击文档节点时，前端按 `document_id` 进入文档详情，后端再次校验权限。

### 7.5 审计写入流程

审计写入不是一个独立异步服务，而是业务控制器在关键节点同步写入 `audit_logs` 并随业务提交。登录和多文档保存流程中存在多个提交点；设计上以“关键事件尽量不丢失”为目标，以同步简单性换取分布式事务的缺失。管理员查询审计时按动作、用户和明细筛选并分页，动作统计从全量 `audit_logs` 聚合。

## 8 数据库设计

### 8.1 数据库设计概述

数据库由 SQLAlchemy ORM 映射到 SQLite。核心表共 9 张：`users`、`categories`、`documents`、`knowledge_chunks`、`graph_nodes`、`graph_edges`、`favorites`、`audit_logs`、`qa_history`。所有主键为 SQLite 自增整数，时间字段使用 Python 本地时间 `datetime.now()` 写入无时区 `DATETIME`，展示格式统一为 `YYYY-MM-DD HH:MM:SS`。

数据库表在启动或种子初始化时通过 `db.create_all()` 创建，没有 Alembic 等迁移脚本；字段变更需要开发者在现有库上手工处理。ER 图见 [07-ER图](../uml/rendered/07-ER图.png)。

### 8.2 通用约定

| 约定 | 说明 |
|---|---|
| 命名 | 表名和字段名使用小写蛇形命名 |
| 主键 | `id INTEGER PRIMARY KEY` 自增 |
| 空值 | 除显式 `nullable=False` 外，多数可选字段允许 NULL；创建 API 通常写入空字符串默认值 |
| 枚举 | 角色、密级、状态、模式以字符串存储，当前由应用层字典校验，不使用数据库 CHECK 约束 |
| 时间 | `created_at`、`updated_at` 默认本地时间；`updated_at` 在文档更新时自动刷新 |
| 布尔 | SQLite 中以整数/布尔映射；实际业务主要用属性判断 |
| 删除 | ORM 关系负责部分级联；图谱删除由服务显式清理；无软删除字段 |
| 外键 | ORM 模型声明外键；SQLite 连接未显式执行 `PRAGMA foreign_keys=ON`，删除一致性主要依赖 ORM 和显式清理 |

### 8.3 `users` 用户表

| 字段 | 类型/长度 | 可空 | 默认/约束 | 说明 |
|---|---|---:|---|---|
| `id` | INTEGER | 否 | 主键 | 用户 ID |
| `username` | VARCHAR(64) | 否 | 唯一、索引 | 登录名 |
| `password_hash` | VARCHAR(255) | 否 | — | Werkzeug 密码哈希 |
| `display_name` | VARCHAR(64) | 否 | — | 展示名 |
| `role` | VARCHAR(20) | 否 | `employee` | `admin` / `employee` |
| `department` | VARCHAR(64) | 否 | `综合部` | 部门名称 |
| `created_at` | DATETIME | 是 | 当前本地时间 | 创建时间 |

关系：一个用户可创建多篇文档、拥有多条收藏、产生多条审计和问答历史。用户名唯一索引是登录查询的主要索引。

### 8.4 `categories` 分类表

| 字段 | 类型/长度 | 可空 | 默认/约束 | 说明 |
|---|---|---:|---|---|
| `id` | INTEGER | 否 | 主键 | 分类 ID |
| `name` | VARCHAR(64) | 否 | 唯一 | 分类名称 |
| `description` | VARCHAR(255) | 是 | 空字符串 | 分类说明 |

关系：一个分类可关联多篇文档；文档的 `category_id` 可为空。分类删除没有专门接口，若直接删除会留下引用问题，需人工先处理文档引用。

### 8.5 `documents` 文档表

| 字段 | 类型/长度 | 可空 | 默认/约束 | 说明 |
|---|---|---:|---|---|
| `id` | INTEGER | 否 | 主键 | 文档 ID |
| `title` | VARCHAR(200) | 否 | — | 标题 |
| `content` | TEXT | 否 | 空字符串 | 正文 |
| `summary` | VARCHAR(500) | 是 | 空字符串 | 摘要 |
| `department` | VARCHAR(64) | 否 | `综合部` | 所属部门，用于机密隔离 |
| `visibility` | VARCHAR(20) | 否 | `internal` | `public` / `internal` / `secret` |
| `status` | VARCHAR(20) | 否 | `published` | `draft` / `published` / `archived` |
| `version` | VARCHAR(20) | 是 | `1.0` | 文本版本号 |
| `filename` | VARCHAR(255) | 是 | 空字符串 | 附件预留字段，当前未启用上传链路 |
| `tags` | VARCHAR(255) | 是 | 空字符串 | 逗号分隔标签 |
| `category_id` | INTEGER | 是 | 外键 `categories.id` | 分类 |
| `author_id` | INTEGER | 是 | 外键 `users.id` | 作者 |
| `created_at` | DATETIME | 是 | 当前本地时间 | 创建时间 |
| `updated_at` | DATETIME | 是 | 当前时间，更新时刷新 | 更新时间 |

关系：文档属于一个分类和一个作者；拥有多个知识片段、收藏、图谱文档节点。文档标题和正文是必填字段，摘要超长由应用截断。

### 8.6 `knowledge_chunks` 知识片段表

| 字段 | 类型/长度 | 可空 | 默认/约束 | 说明 |
|---|---|---:|---|---|
| `id` | INTEGER | 否 | 主键 | 片段 ID |
| `document_id` | INTEGER | 否 | 外键 `documents.id`，索引 | 所属文档 |
| `chunk_index` | INTEGER | 否 | 0 | 文档内序号 |
| `content` | TEXT | 否 | — | 片段正文 |
| `keywords` | VARCHAR(500) | 是 | 空字符串 | 逗号分隔关键词 |

关系：多个片段属于一篇文档，Document 关系配置 `cascade="all, delete-orphan"`。当前没有对 `(document_id, chunk_index)` 建唯一约束，重复重建时先删除旧记录，因此正常情况下索引有序且不重复。

### 8.7 `graph_nodes` 与 `graph_edges` 图谱表

#### 8.7.1 `graph_nodes`

| 字段 | 类型/长度 | 可空 | 默认/约束 | 说明 |
|---|---|---:|---|---|
| `id` | INTEGER | 否 | 主键 | 节点 ID |
| `name` | VARCHAR(100) | 否 | 唯一 | 节点显示名称 |
| `node_type` | VARCHAR(40) | 否 | `concept` | 文档/部门/关键词/概念/项目 |
| `description` | VARCHAR(255) | 是 | 空字符串 | 说明 |
| `document_id` | INTEGER | 是 | 外键 `documents.id` | 文档节点关联；非文档节点为空 |

#### 8.7.2 `graph_edges`

| 字段 | 类型/长度 | 可空 | 默认/约束 | 说明 |
|---|---|---:|---|---|
| `id` | INTEGER | 否 | 主键 | 边 ID |
| `source_id` | INTEGER | 否 | 外键 `graph_nodes.id` | 起点 |
| `target_id` | INTEGER | 否 | 外键 `graph_nodes.id` | 终点 |
| `relation` | VARCHAR(64) | 否 | `关联` | 关系名称，如属于、分类为、含有 |

关系：节点分别通过 `out_edges` 与 `in_edges` 关联边，删除节点时 ORM cascade 删除相关边；服务层在删除文档节点时还会显式删除入边/出边。`(source_id, target_id, relation)` 当前没有数据库唯一约束，去重由 `ensure_edge()` 应用层完成。

### 8.8 `favorites` 收藏表

| 字段 | 类型/长度 | 可空 | 默认/约束 | 说明 |
|---|---|---:|---|---|
| `id` | INTEGER | 否 | 主键 | 收藏 ID |
| `user_id` | INTEGER | 否 | 外键 `users.id` | 收藏用户 |
| `document_id` | INTEGER | 否 | 外键 `documents.id` | 收藏文档 |
| `created_at` | DATETIME | 是 | 当前本地时间 | 收藏时间 |

唯一约束 `uq_user_doc_fav`：`(user_id, document_id)`。该约束保证一个用户不会重复收藏同一文档；收藏/取消收藏通过存在性查询切换。

### 8.9 `audit_logs` 审计表

| 字段 | 类型/长度 | 可空 | 默认/约束 | 说明 |
|---|---|---:|---|---|
| `id` | INTEGER | 否 | 主键 | 审计 ID |
| `user_id` | INTEGER | 是 | 外键 `users.id` | 操作者；失败登录可能为空 |
| `action` | VARCHAR(64) | 否 | — | 动作代码 |
| `detail` | VARCHAR(500) | 是 | 空字符串 | 业务明细 |
| `created_at` | DATETIME | 是 | 当前本地时间 | 发生时间 |

关系：审计属于可选用户。当前没有时间、动作、用户的复合索引；审计列表按时间倒序查询，在演示数据量下可接受，数据量增长后应增加 `(created_at, id)` 或 `(action, created_at)` 索引。

### 8.10 `qa_history` 问答历史表

| 字段 | 类型/长度 | 可空 | 默认/约束 | 说明 |
|---|---|---:|---|---|
| `id` | INTEGER | 否 | 主键 | 历史 ID |
| `user_id` | INTEGER | 是 | 外键 `users.id` | 提问用户 |
| `question` | TEXT | 否 | — | 问题原文 |
| `answer` | TEXT | 否 | — | 回答原文 |
| `sources` | TEXT | 是 | 空字符串 | JSON 字符串形式来源列表 |
| `mode` | VARCHAR(20) | 是 | `local` | `local` / `llm` |
| `created_at` | DATETIME | 是 | 当前本地时间 | 提问时间 |

关系：一个用户可拥有多条问答历史。来源以 JSON 文本保存，未建立单独来源表；这简化了演示，但不便于按文档统计问答引用次数。

### 8.11 索引与约束汇总

| 表 | 主键 | 唯一/唯一索引 | 普通索引 | 外键 |
|---|---|---|---|---|
| `users` | `id` | `username` | `username` | — |
| `categories` | `id` | `name` | — | — |
| `documents` | `id` | — | — | `category_id`、`author_id` |
| `knowledge_chunks` | `id` | — | `document_id` | `document_id` |
| `graph_nodes` | `id` | `name` | — | `document_id` |
| `graph_edges` | `id` | — | — | `source_id`、`target_id` |
| `favorites` | `id` | `(user_id, document_id)` | — | `user_id`、`document_id` |
| `audit_logs` | `id` | — | — | `user_id` |
| `qa_history` | `id` | — | — | `user_id` |

### 8.12 数据关系说明

```text
users 1 ─── * documents
categories 1 ─── * documents
documents 1 ─── * knowledge_chunks
documents 1 ─── * favorites
users 1 ─── * favorites
users 1 ─── * audit_logs
users 1 ─── * qa_history
graph_nodes 1 ─── * graph_edges（source）
graph_nodes 1 ─── * graph_edges（target）
documents 0..1 ─── 0..1 graph_nodes（document_id，逻辑关联）
```

`graph_nodes.document_id` 是普通外键，不是数据库强制的一对一约束；服务层通过“先按 `document_id` 查找”通常保证一个文档节点，但理论上仍可能出现多个节点。节点名称全局唯一，因此同名部门、关键词和概念会复用同一节点，这是图谱聚合的设计选择，也意味着不同业务语义同名时不能共存。

### 8.13 数据生命周期

1. 首次启动执行 `db.create_all()` 并通过 `seed_all()` 创建演示数据；
2. 新增文档先保存主记录，再生成片段、图谱与审计；
3. 编辑文档重建片段并同步图谱；
4. 删除文档删除主记录、片段、收藏、文档图谱节点及边；
5. 问答与审计持续追加，不自动归档；
6. 当前没有数据库备份、恢复、迁移或定期清理任务；演示环境通过复制 SQLite 文件实现最基础的备份。

## 9 REST API 设计

### 9.1 通用约定

| 项目 | 约定 |
|---|---|
| 基础路径 | `/api`；`/api` 与 `/api/` 等价 |
| 数据格式 | 请求和响应以 `application/json` 为主；表单请求也可通过 `request.form` 被 `_json_body()` 接收 |
| 字符编码 | UTF-8；Flask JSON 设置 `ensure_ascii=False`，中文直接输出 |
| 命名 | 字段使用 snake_case，如 `display_name`、`document_id`、`per_page` |
| 认证 | 浏览器同源 Session Cookie；Vue `fetch` 使用 `credentials: 'include'` |
| 时间 | 字符串格式 `YYYY-MM-DD HH:MM:SS` |
| 成功 | 查询 200，创建 201，删除/切换等返回 200 与提示信息 |
| 错误 | 主要返回 `{"error": "...", "code": "..."}`；限流响应额外返回 `retry_after` |
| 分页 | 文档使用 `page`、`per_page`；审计固定每页 25 条 |
| 权限 | 业务接口默认要求登录；管理接口要求 `admin`；资源接口还会做资源级检查 |

### 9.2 端点总表

### 9.7 状态码与错误码

| HTTP | `code` | 场景 | 前端处理 |
|---:|---|---|---|
| 200 | — | 查询、更新、删除、切换、登录成功 | 使用响应数据 |
| 201 | — | 新建文档、分类、图谱节点/边成功 | 显示成功提示并刷新 |

| 401 | `INVALID_CREDENTIALS` | 用户名或密码错误 | 登录页内联提示 |
| 403 | `FORBIDDEN` | 角色不足、文档/历史无权、未发布文档 | 展示无权提示，不显示正文 |
| 404 | `NOT_FOUND` | 文档、问答记录不存在 | 展示不存在提示或返回列表 |
| 405 | — | HTTP 方法不支持 | 由 Flask 返回方法不允许 |
| 429 | — | 登录失败次数达到阈值 | 展示重试秒数 |
| 500 | — | 未捕获的服务端异常 | 前端使用通用“请求失败（500）” |

## 10 安全设计

### 10.1 安全边界与威胁模型

本系统的安全目标依次是：防止未登录访问、防止跨部门读取机密文档、防止问答和关系图绕过文档权限、防止密码明文存储、降低登录爆破风险，并避免因开放跳转或模板注入导致客户端风险。系统主要面向课程演示与受控局域网环境，不宣称达到生产级安全合规要求。

主要信任边界如下：

```text
不可信输入：浏览器参数、表单、JSON、导入的演示数据、外部模型回答
可信边界：Flask 服务端身份与权限判定、SQLAlchemy 参数化查询
外部依赖：OpenAI 兼容模型 API（可选、不可信返回）
```

### 10.2 会话安全

| 控制项 | 当前设计 |
|---|---|
| 会话技术 | Flask 签名 Session Cookie + Flask-Login |
| 会话密钥 | `SECRET_KEY` 从环境变量读取；开发默认值仅用于本地演示 |
| HttpOnly | `SESSION_COOKIE_HTTPONLY=True`，脚本不能直接读取 Cookie |
| SameSite | `SESSION_COOKIE_SAMESITE="Lax"` |
| Secure | 生产配置 `SESSION_COOKIE_SECURE` 默认启用；开发默认不强制 HTTPS |
| 有效期 | `PERMANENT_SESSION_LIFETIME` 默认 43200 秒（12 小时） |
| 用户恢复 | Session 中用户 ID 经 `user_loader` 从数据库重新加载 |
| 退出 | `logout_user()` 清除登录态，并写退出审计 |

生产部署必须替换默认 `SECRET_KEY`，并在 HTTPS 下启用 Secure Cookie。由于当前没有 Refresh Token、JWT 黑名单或服务端会话表，会话撤销依赖 Cookie 清除和密钥管理；多实例部署也不共享 Session，需另行规划。

### 10.3 密码存储

用户密码通过 `generate_password_hash()` 写入 `password_hash`，通过 `check_password_hash()` 校验。Werkzeug 3.0.3 默认使用带盐的 `scrypt` 方案。代码不会把明文密码写入数据库，演示账号密码只出现在种子定义与公开演示元信息中，属于课程展示便利，不应作为生产账号策略。

密码策略当前没有最小长度、复杂度、失败次数冻结账户、密码过期或历史密码校验。生产化时应补充口令强度策略、密码重置流程和哈希参数升级机制。

### 10.4 授权与文档密级

权限判定采用“身份 + 角色 + 部门 + 文档属性”的组合：

- 未登录用户不能访问业务 API 和页面；
- 普通员工可以访问所有 `public` / `internal` 文档；
- `secret` 文档只允许管理员、同部门员工或文档作者访问；
- 草稿/归档只在详情处对作者或管理员开放，普通列表和 RAG 只取已发布文档；
- 编辑、删除只允许作者本人或管理员；
- 收藏切换先校验文档可见性；
- 问答历史只允许本人或管理员；
- 管理接口通过 `api_admin_required` 或 `admin_required` 再次检查角色。

前端菜单隐藏和路由 `meta.admin` 只影响界面体验，不构成授权。任何用户都可以直接构造 HTTP 请求，因此所有敏感操作必须在后端重复判定。

### 10.5 检索与图谱的权限过滤

这是系统最关键的防泄漏设计：

1. **先计算文档集**：`searchable_documents(current_user)` 只返回已发布且 `can_view_document` 为真的文档；
2. **再查询片段**：RAG 只对允许的 `document_id` 查询 `knowledge_chunks`；
3. **再评分排序**：禁止把无权片段送入评分、模型上下文或响应；
4. **图谱从文档节点出发**：只把有权限文档节点作为起点，再纳入直接相连的部门、分类、关键词节点；
5. **前端不作为安全边界**：即使前端隐藏来源，后端也不会返回无权内容。

该规则由 `tests/test_security.py`、`tests/test_rag.py` 与 `tests/test_api.py` 覆盖，包括“其他部门机密不可检索”“同部门可见”“作者可见”“管理员可见”等场景。

### 10.6 登录防爆破

登录限流采用按 IP 的滑动窗口：

- 默认 300 秒窗口、8 次失败；
- 达到阈值后返回 429，并给出 `retry_after`；
- 锁定判断先于密码校验；
- 登录成功清除当前来源计数；
- 失败登录写审计，便于管理员发现异常。

限制与风险：

1. 进程内字典不跨进程共享，多进程会形成各进程独立阈值；
2. 只按 `remote_addr` 计数，部署在反向代理后必须正确配置可信代理头，否则所有用户可能共享代理 IP；
3. 没有验证码、账户冻结或全局 IP 黑名单；
4. 当前无 Redis，不能宣称支持分布式限流。

### 10.7 防开放重定向

旧登录页支持 `next` 参数，`safe_next_url()` 的安全规则为：

1. 空值返回 `None`；
2. 必须以单个 `/` 开头；
3. 拒绝 `//` 开头的协议相对 URL；
4. 拒绝反斜杠、换行、回车和空字符；
5. 通过 `urlparse()` 再拒绝带 `scheme` 或 `netloc` 的地址；
6. 拒绝路径再次以 `//` 开头。

Vue 登录页的 `redirect` 只提交给 `router.replace()`，并检查以 `/` 开头；后端认证接口不直接执行浏览器跳转，因此不会形成服务端开放重定向。前端仍不应把任意外部 URL 当作路由目标。

### 10.8 注入、XSS 与模板安全

| 风险 | 当前措施 | 剩余风险 |
|---|---|---|
| SQL 注入 | SQLAlchemy ORM 参数绑定；仅健康检查使用固定 `SELECT 1` | 手写 SQL 扩展时仍需使用绑定参数 |
| Jinja XSS | Jinja 默认自动转义；页面不直接输出未转义用户 HTML | 具体模板若使用 `safe` 需单独审查 |
| Vue XSS | 正文和模型回答使用模板插值，按文本渲染 | ECharts tooltip 对节点名进行 HTML 字符串拼接，生产需转义 |
| 路径穿越 | SPA 只通过 `send_from_directory` 返回 `dist` 内文件 | 上传目录尚未提供下载接口 |
| 外部模型注入 | 系统提示词限定“仅依据资料回答”，来源随回答返回 | 模型回答仍可能被恶意文档诱导，需人工核对 |
| CSRF | 同源 SPA、SameSite=Lax、JSON 请求 | 当前没有独立 CSRF Token；生产需补充 |

### 10.9 CSRF 与跨域

Vue 使用 `credentials: 'include'` 发送会话 Cookie。开发时 Vite 代理使 `/api` 与前端同源；生产时 Flask 同时提供 `/ui` 与 `/api`，也是同源。系统没有配置 Flask-CORS，不主动允许跨域携带 Cookie。

SameSite=Lax 能降低多数跨站 POST 请求携带 Cookie 的风险，但不能替代 CSRF Token。当前 API 没有 Flask-WTF 或自定义 CSRF 校验；如果未来把前端与 API 分域部署，或引入第三方页面调用，应在所有状态变更接口增加 CSRF 防护、严格 Origin 校验和显式 CORS 白名单。

### 10.10 会话、密钥与部署安全

1. 生产环境通过 `.env` 或系统环境变量提供 `SECRET_KEY`、`DATABASE_URL`、模型密钥；
2. 不把 `.env`、数据库文件、日志或上传文件提交到公共仓库；
3. 生产配置启用 Secure Cookie，演示 HTTP 环境不要误开；
4. 反向代理应终止 HTTPS，限制请求体大小，并设置安全响应头；
5. `MAX_CONTENT_LENGTH` 为 16 MB，可降低超大请求的风险，但当前并没有完整附件端点；
6. 公开 `/api/meta` 会返回演示账号名称和密码，这是课程演示功能，生产部署应移除或加环境开关。

### 10.11 审计与隐私

审计包含用户名、文档标题、问题摘要等业务信息。管理员可以查看审计，普通用户不能访问审计列表。问答历史与审计均未实现自动脱敏、加密存储和保留期删除。对于真实企业数据，应评估个人信息、机密标题和模型上下文外发的隐私影响。

### 10.12 安全测试关注点

- 未登录访问 `/api/documents`、`/api/qa`、`/api/graph` 返回 401；
- 普通员工访问 `/api/admin/*` 返回 403；
- 其他部门机密文档的列表、详情、RAG 和图谱均不可见；
- 作者可查看自己的草稿，非作者不可查看；
- 连续失败达到阈值后，正确密码仍被 429 拒绝；
- 失败登录写入审计，且用户名不存在时也留痕；
- `safe_next_url()` 拒绝 `//evil.example`、`https://evil.example`、反斜杠、换行；
- 密码字段不是明文，哈希可由 `check_password_hash()` 校验；
- 访问不存在的文档返回 404，不泄露标题或正文。

## 11 异常与降级设计

### 11.1 异常处理原则

1. **输入错误尽早返回**：空标题、空正文、空问题、非法分类在控制器层直接返回 400/JSON 或表单提示；
2. **权限错误不降级为成功**：无权限返回 403，不能返回空列表假装成功；
3. **资源不存在返回 404**：避免用 500 暴露内部异常；
4. **外部依赖失败可降级**：大模型不可用时回退本地摘要；
5. **页面与 API 分开处理**：Jinja 使用 Flash + 错误模板；REST 使用 JSON 错误码；
6. **异常信息不无限扩散**：生产模式不应把堆栈返回给用户。

### 11.2 异常场景表

| 场景 | 检测点 | 当前行为 | 恢复方式 |
|---|---|---|---|
| 登录用户名/密码错误 | `check_password()` | 401 + 统一提示 + 失败审计 | 重试；次数过多等待窗口 |
| 登录被限流 | `is_locked_from_request()` | 429 + `retry_after` | 等待窗口结束或重启演示进程 |
| 未登录访问 API | `api_login_required` | 401 + `AUTH_REQUIRED` | 登录后重试 |
| 非管理员访问管理 API | `api_admin_required` | 403 + `FORBIDDEN` | 使用管理员账号 |
| 无权读取机密文档 | `can_view_document()` | 403，不返回正文 | 申请同部门权限或联系管理员 |
| 文档不存在 | `db.session.get()` | 404 + `NOT_FOUND` | 返回列表 |
| 标题/正文为空 | `_apply_document_payload()` | 400 + `VALIDATION_ERROR` | 补齐字段 |
| 分类重复 | 查询唯一名称 | 400 + 分类名称已存在 | 使用现有分类 |
| 问答无命中 | `retrieve()` | 本地回答说明未检索到内容 | 换问法或补充文档 |
| 未配置模型 Key | `call_llm_answer()` | 本地摘要，`mode=local` | 无需处理 |
| 模型调用失败 | `except Exception` | 回答中附失败说明并回退本地摘要，`mode=local` | 检查网络/密钥/模型地址 |
| 来源 JSON 损坏 | `json.loads()` | API 返回空来源列表，页面仍可看回答 | 修复历史数据 |
| 数据库不可用 | `/api/health`、`/health` | 返回 `status=degraded`、`database=false` | 检查文件权限与连接串 |
| Vue dist 不存在 | `/ui` 检查 `index.html` | 503 + 构建提示 | 在 `frontend` 执行构建 |
| 未知前端路径 | SPA fallback | 返回 `index.html`，由 Vue 404 视图处理 | 返回有效页面 |
| Flask 未捕获异常 | Flask 默认处理 | 生产返回通用 500/HTML；前端显示请求失败 | 查看服务端日志 |

### 11.3 大模型降级设计

外部模型是可选增强，不是系统主路径。降级逻辑必须满足：

- 没有 `OPENAI_API_KEY`：不发起外部请求；
- 没有命中片段：不调用模型，直接返回本地无结果说明；
- 调用超时、网络错误、返回结构异常：捕获异常，生成“失败说明 + 本地摘要”；
- 模式标记为 `local`，前端显示“本地检索摘要模式”；
- 不把失败回答标记为 `llm`；
- 不因模型失败回滚已完成的文档检索或问答历史。

当前实现会把异常文本拼入回答，这在课程演示中便于排错，但生产环境可能泄露内部网络地址或服务端信息。正式部署应将详细异常写入服务端日志，只向用户返回通用降级提示。

### 11.4 SPA 与 API 分离状态下的异常

Vue 客户端用 `ApiError` 统一承载 HTTP 状态和 JSON payload。页面处理策略为：

| 场景 | 页面表现 |
|---|---|
| 列表加载失败 | 内联错误面板或 Toast |
| 409/400 保存失败 | 表单错误提示，不跳转 |
| 403 详情 | 错误提示，不显示正文 |
| 401 会话过期 | 页面显示登录提示；重新导航触发路由守卫 |
| 404 | 返回文档列表或显示不存在 |
| 图表无数据 | 空状态，不显示空 canvas 假象 |

前端没有全局自动刷新 token，因为系统不使用 JWT/Refresh Token；会话过期需要用户重新登录。

### 11.5 事务与一致性异常

当前文档保存链路包含多次 `commit()`，不是严格的单一原子事务。异常恢复策略为：

1. 若主文档未提交，数据库回滚后无残留；
2. 若主文档已提交但片段/图谱阶段失败，重新保存同一文档可触发片段重建和图谱同步；
3. 若审计写入失败，业务数据可能已写入，需通过应用日志和服务端检查补齐；
4. 删除文档前先清理图谱，若数据库失败，需要人工检查 `graph_nodes` 与 `graph_edges` 是否残留；
5. `cleanup_orphan_document_nodes()` 已存在但未自动执行，可作为人工维护工具。

生产化建议将“文档主记录、片段、图谱、审计”放入同一事务或引入补偿任务，但本次不虚构已实现的分布式事务。

## 12 性能设计

### 12.1 性能目标

系统主要面向课程演示与中小规模知识库，目标不是互联网级高并发。可接受的目标为：

| 场景 | 目标 | 依据 |
|---|---|---|
| 登录、工作台首屏 | 本机演示下快速返回 | 数据量小，查询简单 |
| 文档列表 | 演示规模下 ≤ 3 秒 | Python 过滤与分页；单页最多 50 |
| 文档详情 | 演示规模下 ≤ 3 秒 | 单文档 + 相关文档 + 片段计数 |
| 本地 RAG | 演示规模下 ≤ 5 秒 | jieba 首次加载较慢，后续缓存分词词典 |
| 关系图 | 首次可交互，允许布局抖动 | ECharts force 布局 |
| 单页数据量 | 文档默认 9，最大 50；审计固定 25 | 控制 DOM 与响应体 |

### 12.2 后端性能机制

1. **索引**：用户名唯一索引、分类名称唯一、图谱节点名称唯一、收藏联合唯一、Chunk 文档索引；
2. **限制结果**：文档 `per_page` 上限 50；问答 Top-K 默认 5；同文档最多 2 个片段；审计每页 25；
3. **权限过滤前置**：问答只查询可见文档的片段，避免无关片段进入评分；
4. **不加载全量历史**：问答页只取最近 20 条，详情单独请求；
5. **ECharts 前端渲染**：关系图不在后端计算布局；
6. **健康检查轻量**：执行固定 `SELECT 1`，只判断连接是否可用。

### 12.3 当前性能瓶颈

| 环节 | 现状 | 影响 |
|---|---|---|
| 文档列表 | 先加载所有已发布可见文档，再在 Python 过滤/排序/分页 | 数据量增大后内存与排序成本上升 |
| 关键词检索 | 列表层逐文档分词与字符串匹配 | 文档多时 CPU 消耗增加 |
| RAG 检索 | 对可见文档的全部片段加载并逐个评分 | 片段数大时耗时明显 |
| 图谱过滤 | 先读取全图，再在 Python 过滤 | 节点/边多时首屏和内存成本较高 |
| 审计查询 | 只有主键和用户外键，时间与动作无复合索引 | 大数据量分页需要优化 |
| jieba 初始化 | 首次分词需加载词典、注册领域词 | 首个问答/检索请求延迟较高 |
| ECharts | 力导向布局与大量节点交互 | 节点过多时掉帧；当前未设置节点上限 |
| 文档保存 | 同步重建片段、图谱和审计 | 保存响应受分词与图同步耗时影响 |

### 12.4 前端性能机制

- 路由级动态 `import()`，按页面拆分；
- ECharts 按需注册图表与组件，避免引入完整包的所有能力；
- `BaseChart` 使用 `ResizeObserver` 自适应容器，卸载时 `dispose()`；
- 文档列表每页 9 条，避免一次渲染大量卡片；
- 页面对请求状态设置加载/错误状态，避免重复提交；
- 图形交互使用 Canvas 渲染，适合较多节点；
- 长文本详情只在当前页面展示，不进入全局状态。

### 12.5 性能测试建议

| 测试 | 方法 | 关注指标 |
|---|---|---|
| 登录响应 | 连续发起登录与失败登录 | 平均耗时、429 触发 |
| 文档列表 | 分页 1/10/100，关键词查询 | 返回时间、内存、页数夹取 |
| 本地 RAG | 10～50 个问题、不同命中数 | Top-K、来源准确性、响应时间 |
| 同文档去重 | 构造长文档多片段 | 每篇最多 2 片段 |
| 图谱渲染 | 100/500/1000 节点 | 首屏、拖拽、缩放流畅度 |
| 保存同步 | 长文本新建/编辑 | 切分数量、图谱边变化、耗时 |

### 12.6 扩展方向（未实现）

如未来数据规模增长，可考虑：为文档状态、部门、密级和审计时间增加索引；引入 SQLite FTS5 或独立全文检索；将评分迁移到数据库或检索服务；为图谱接口增加服务端分页/子图查询；增加缓存或任务队列。上述均为演进方向，不是当前已实现能力。

## 13 部署设计

### 13.1 部署形态

V2.0 采用单机部署：一个 Flask 进程同时提供 Vue 构建后的静态 SPA、REST API、旧 Jinja 页面和 SQLite 数据库文件。该形态适合课程演示、单机开发和局域网功能验证，不采用容器编排、反向代理集群或独立前端服务器。

```text
客户端浏览器
   │ HTTP :5000
   ▼
Flask 应用（单进程）
   ├─ /ui/*       frontend/dist
   ├─ /api/*      REST API
   ├─ 旧页面       Jinja 模板
   ├─ SQLAlchemy  instance/knowledge.db
   └─ uploads/    预留文件目录
```

### 13.2 目录与运行产物

| 路径 | 作用 |
|---|---|
| `run.py` | 前台启动入口，默认 `127.0.0.1:5000` |
| `start.ps1` | 后台启动；检查虚拟环境、必要时构建前端、写入 PID 和日志 |
| `stop.ps1` | 停止后台进程 |
| `run_tests.ps1` | 运行 pytest |
| `frontend/` | Vue 源码、依赖与 Vite 配置 |
| `frontend/dist/` | 生产静态构建产物，由 Flask `/ui` 提供服务 |
| `app/` | Flask 应用、模板、静态资源、模型与服务 |
| `instance/` | SQLite 数据库、PID、启动输出与错误日志 |
| `uploads/` | 文件上传预留目录 |
| `docs/` | 需求、设计、UML、用例、测试与项目管理文档 |
| `tests/` | 自动化测试与公共夹具 |

后端：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe run.py
```

前端：

```powershell
cd frontend
npm install

```

### 13.4 课程演示/单机运行

```powershell
.\start.ps1
# 或指定端口与绑定地址
.\start.ps1 -Port 5000 -BindHost 127.0.0.1
```

`start.ps1` 的关键行为：

1. 检查 `.venv\Scripts\python.exe`；
2. 若 `frontend/dist/index.html` 不存在且系统有 `npm.cmd`，自动执行 `npm install` 与 `npm run build`；
3. 检查端口占用与已有 PID；
4. 生成仅供启动使用的 `instance/_boot_server.py`，设置 `debug=False`、`use_reloader=False`；
5. 以隐藏窗口后台启动 Flask；
6. 将进程 ID 写入 `instance/server.pid`；
7. 标准输出和标准错误分别写入 `instance/server.out.log`、`instance/server.err.log`；
8. 默认入口提示为 `http://127.0.0.1:5000/ui/`。

停止：

```powershell
.\stop.ps1
```

该启动方式是“课程演示单机服务”，不是生产级进程管理器。当前依赖中没有安装 Gunicorn、Waitress、Nginx 或容器运行时，因此不能声称已经具备生产 WSGI 部署。

### 13.7 数据库与文件部署

- 首次启动 `seed_all()` 调用 `db.create_all()`，创建表并补充种子数据；
- SQLite 文件位于 `instance/knowledge.db`，需确保进程对目录有读写权限；
- 演示数据可以通过复制数据库文件带走，但复制前应停止写入；
- `uploads/` 当前为预留目录，不是完整附件存储；
- 若需要迁移到其他主机，应同时复制数据库和应用配置，避免只复制代码导致密钥变化、会话失效；
- 当前没有自动备份、恢复、迁移或数据库压缩任务。

### 13.8 可选模型服务的部署要求

只有在设置 `OPENAI_API_KEY` 后才需要外部网络。调用地址由 `OPENAI_BASE_URL` 决定，运行时向 `${BASE_URL}/chat/completions` 发送 POST。部署时需考虑：

1. 出口网络和 DNS 是否可达；
2. API Key 不写入源码或前端；
3. 调用失败是否允许回退本地摘要；
4. 数据是否允许发送到第三方模型服务；
5. 超时、限流和费用是否可接受。

未配置密钥时，系统不需要任何外部 AI 服务即可完成登录、文档管理、本地检索、问答、图谱和审计。

### 13.9 生产化差距

| 差距 | 当前状态 | 生产化建议 |
|---|---|---|
| WSGI 服务器 | 使用 Flask 自带服务器 | 使用成熟 WSGI 服务器或容器平台 |
| 反向代理与 HTTPS | 未内置 | Nginx/Ingress 终止 TLS，配置安全头 |
| 多进程 Session | Cookie 可工作，但限流不共享 | 使用共享 Session/限流存储 |
| 数据库 | SQLite 单文件 | 按规模评估 PostgreSQL 等 |
| 迁移 | `create_all` | 引入版本化迁移工具 |
| 可观测性 | 文件日志 + health | 指标、追踪、集中日志与告警 |
| 备份 | 手工复制 | 定时备份、恢复演练与保留策略 |
| 附件 | 目录与字段预留 | 上传校验、杀毒、解析、权限下载 |

## 14 可维护性与测试支持

### 14.1 可维护性设计

1. **应用工厂**：`create_app(config_class)` 可注入测试、生产或默认配置，便于测试隔离与部署差异；
2. **蓝图划分**：认证、主页面、文档、问答、图谱、管理、SPA 各自有明确前缀；
3. **共享服务**：RAG 与图谱逻辑集中在 `services`，REST 和 Jinja 共用，减少规则漂移；
4. **集中字典**：部门、角色、密级、状态、动作、模式等标签集中在 `utils.py`；
5. **配置外置**：密钥、数据库、模型、切分参数走配置类与环境变量；
6. **组件化前端**：页面、布局、图表、空状态、Toast 分离，路由懒加载；
7. **文档与测试同步**：需求编号、接口路径、UML 文件和测试文件可相互追踪。

### 14.4 测试支持设计

- Flask 应用日志写入标准输出/错误，`start.ps1` 重定向到 `instance/server.out.log` 与 `instance/server.err.log`；
- `/api/health` 与 `/health` 提供数据库连通性；
- 启动脚本记录 PID，便于停止和排障；
- 审计日志记录业务事件，不替代系统运行日志；

### 14.6 已知实现边界与技术债

| 项目 | 当前事实 | 影响与建议 |
|---|---|---|
| `AUTO_SEED` | 配置存在，但 `create_app()` 未按开关短路 | 生产需先修正调用逻辑，再依赖该开关 |
| 数据库迁移 | 仅 `create_all()` | 字段升级需手工迁移，建议引入 Alembic |
| 保存事务 | 片段/图谱/审计多次提交 | 异常时可能短暂不一致，建议统一事务或补偿 |
| 图谱边唯一性 | 仅应用层去重 | 并发下可能重复，建议唯一约束 |
| 图谱统计 | 部分统计为全库口径 | 需在 UI 标注范围或改为权限内统计 |
| 分类管理 | 无更新/删除接口 | 完整分类治理需补齐 |
| 附件 | 目录/字段/扩展名预留 | 未实现上传解析，不应在答辩中宣称完成 |
| 模型异常 | 失败详情拼入回答 | 可能泄露内部信息，生产应改为通用提示 |
| 模型超时 | `OPENAI_TIMEOUT` 未接入 | 实际 `urlopen` 使用 60 秒 |
| CSRF | 无独立 Token | SameSite Lax 仅为基础缓解 |
| 全局错误 | API 无统一 500 JSON 包装 | 前端可能只能显示通用错误 |
| ECharts tooltip | HTML 字符串拼接节点名 | 生产需转义节点名或使用安全 formatter |
| 全文检索 | 无 FTS/向量索引 | 规模增大后性能与召回受限 |

## 16 关键设计决策与取舍

### 16.1 设计决策表

| 编号 | 决策 | 选择 | 理由 | 代价/限制 |
|---|---|---|---|---|
| D1 | 前端形态 | Vue 3 SPA + Jinja 兼容层 | 满足前后端分离，同时降低旧页面迁移风险 | 两套控制器需同步维护 |
| D2 | API 边界 | Flask `/api` JSON | 与 Vue 解耦，便于测试和后续替换客户端 | 需要统一错误码与序列化 |
| D3 | 持久化 | SQLAlchemy + SQLite | 零安装、易演示、模型清晰 | 并发和大数据量能力有限 |
| D4 | 认证 | Session + Flask-Login | 同源部署简单，服务端可撤销会话 | 多实例 Session 共享未实现 |
| D5 | 密码 | Werkzeug scrypt 哈希 | 官方依赖、带盐慢哈希 | 无密码策略与升级流程 |
| D6 | 限流 | 进程内滑动窗口 | 无额外基础设施，适合单机演示 | 不跨进程、不持久化 |
| D7 | 检索 | jieba 词项、关键词、标题与覆盖率打分 | 可解释、无向量服务、演示完整链路 | 语义召回有限 |
| D8 | 片段策略 | 默认 400 字窗、50 字重叠、每文最多 2 片段 | 平衡上下文覆盖与来源多样性 | 长文可能丢失远距离上下文 |
| D9 | 生成 | 本地摘要默认，OpenAI 兼容接口可选 | 离线可用，外部失败可降级 | 外部接口需网络、费用和隐私评估 |
| D10 | 图谱 | 文档/部门/分类/关键词关系 + ECharts force | 直观展示知识关联，易于同步 | 全图过滤在应用层，规模受限 |
| D11 | 权限 | 角色 + 部门 + 文档密级 | 与需求直接对应，规则简单 | 缺乏项目组、岗位级细粒度策略 |
| D12 | 前端状态 | reactive store + 页面局部状态 | 不引入额外状态库，降低复杂度 | 跨页面共享与缓存能力有限 |
| D13 | 数据同步 | 文档保存同步切分/建图 | 保存后立即可检索、可看图 | 写请求较慢，异常一致性需补偿 |
| D14 | 部署 | 单 Flask 进程 + 静态 SPA | 一键演示、同源 Cookie、路径简单 | 不是生产高可用架构 |

### 16.2 为什么不做“看起来更先进”的方案

课程答辩中容易把“可扩展方向”误写成“已实现能力”。本项目的设计原则是：

- 没有向量索引，就不声称使用向量数据库；
- 没有 Redis，就不声称支持分布式缓存或共享限流；
- 没有拆分服务，就不声称采用微服务；
- 没有附件解析端点，就不声称支持 PDF/DOCX 导入；
- 没有迁移工具，就不声称支持无缝数据库升级；
- 没有实际压测数据，就不承诺生产并发指标。

这种“诚实设计”有利于评审人员区分“当前实现”“课程预留”和“未来演进”，也便于后续开发者从代码中验证每条设计说明。

### 16.3 后续演进优先级建议

1. **先修正配置一致性**：让 `AUTO_SEED` 真正控制种子灌入，接入 `OPENAI_TIMEOUT`，将模型异常转为安全提示；
2. **改进事务边界**：统一文档、片段、图谱与审计提交，或增加一致性修复任务；
3. **补齐数据库索引与迁移**：为状态/部门/密级、审计时间和图边增加索引，引入迁移；
4. **增强检索**：在保持当前可解释基线的前提下，评估 BM25、FTS5 或向量检索；
5. **完善权限策略**：项目组、岗位、文档共享与撤销机制；
6. **补充安全**：CSRF Token、Origin 校验、安全响应头、密码策略与生产密钥管理；
7. **完善管理能力**：分类编辑/删除、用户生命周期、附件上传与解析；
8. **增加可观测性**：结构化日志、指标、错误追踪、备份与恢复演练。

## 17 结论与实现边界

### 17.1 设计结论

本文档给出的 V2.0 设计已经覆盖当前系统的主链路：

- Vue 3 SPA 通过 Vue Router 组织页面，通过 REST API 与 Flask 交互，生产构建由 `/ui/` 提供；
- Flask 应用工厂、REST 蓝图、兼容蓝图、共享服务与 SQLAlchemy 模型形成清晰分层；
- Session + Flask-Login 鉴权、角色和部门密级规则在服务端执行；
- 文档保存触发片段切分、关键词提取、图谱同步和审计；
- RAG 采用权限先过滤、jieba 分词、可解释评分、每文最多两片段和 Top-K；
- 无模型密钥时使用本地摘要，配置兼容接口后可生成回答，失败时回退；
- 图谱包含文档、部门、分类/概念、关键词等节点，并按用户可见文档过滤；
- 九张核心表、REST 端点、错误码、测试夹具与 10 张 UML 图形成需求—设计—实现—测试的追踪链路。

### 17.3 验收与维护建议

设计与实现的一致性检查应至少包括：

1. 新端点是否在 `/api` 下并遵循统一 JSON 错误结构；
2. 新查询是否先应用 `can_view_document()` 或明确的权限条件；
3. 文档写操作是否同步片段、图谱与审计；
4. 前端路由是否同时在 Vue Router 和后端 SPA fallback 下可达；
5. 新增配置是否有默认值、环境变量入口和文档说明；
6. 新增业务规则是否有对应测试与需求追踪；
7. 不把未来规划写入“已实现”栏。
