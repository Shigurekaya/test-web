# 竞品调研报告

**项目名称**：智慧企业知识财富库系统  
**文档版本**：V1.3  
**日期**：2026-10-17

---

## 1. 调研目的

在立项前明确企业知识管理类产品的共性能力与常见缺口，为本系统「可鉴权文档库 + 检索增强问答 + 知识关系图」切口提供依据，避免做成：

- 普通网盘（只存文件、无问答、无部门密级）；  
- 个人笔记（缺企业权限与审计）；  
- 空壳 AI 聊天框（无知识来源、无权限隔离）。

## 2. 调研对象

| 竞品 / 对照 | 类型 | 调研角度 |
|-------------|------|----------|
| 飞书知识库 / Wiki | 企业协作知识库 | 文档树、权限、搜索体验 |
| Notion AI | 知识库 + AI | AI 问答、写作辅助、协作 |
| 有道云笔记等笔记类 | 个人/轻协作笔记 | 记录与同步（反例：偏个人） |
| 企业内部「文档库 + 检索」实践 | 业务知识注入检索/生成 | 「先取知识再回答」模式 |

> 说明：本组不做大厂产品对标级功能，只抽取可落地到单机 Flask 演示的能力切片。

## 3. 功能对比

| 能力维度 | 飞书知识库 | Notion AI | 笔记类 | **本系统** |
|----------|------------|-----------|--------|------------|
| 文档分类与检索 | 强 | 强 | 中 | 分类 / 标签 / 关键词全文检索 |
| 角色与部门权限 | 强 | 中 | 弱 | 公开 / 内部 / 机密 + 同部门隔离 + 登录防爆破与失败留痕 |
| AI 问答带来源 | 部分支持 | 支持 | 弱 | 轻量 RAG：分词检索 + 摘要/可选 LLM + 来源卡 |
| 知识关系可视化 | 弱 | 弱 | 无 | 文档—部门—关键词等力导向图 |
| 审计留痕 | 企业版较强 | 中 | 弱 | 登录 / 浏览 / 问答 / 写操作审计 |
| 单机可演示成本 | 高（云端） | 高（云端） | 中 | 低：Python + SQLite 本机可跑 |

## 4. 用户痛点（归纳）

1. **找不到、版本乱**：制度散落在邮件附件、群文件、个人网盘，新人不知道「以哪份为准」。  
2. **搜得到词、答不了问**：关键词搜索命中标题，但回答不了「年假有几天」「两万采购谁批」这类业务问句。  
3. **看不清关系**：不知道某制度归属哪个部门、关联哪些关键词/项目，知识组织靠口头传。  
4. **机密易越权**：网盘链接一发就全员可读，缺少「同部门或管理员」级隔离与操作留痕。

## 5. 本系统差异化定位

> **一句话**：做「可鉴权的企业知识财富库」——文档管理为底座，检索增强问答为智能点，知识关系图为组织视角，审计为治理支撑。

差异点：

| 相对对象 | 取舍 |
|----------|------|
| 相对笔记类 | 强调企业角色、部门密级与审计，而非个人日记 |
| 相对纯 Wiki | 增加权限内 RAG 问答与图谱，而不是只做目录树 |
| 相对大厂产品 | 范围收敛到 6 大模块；技术栈 Flask MVC，便于本机/局域网交付与维护 |

明确不做（调研结论驱动的范围冻结）：完整向量库运维、生产级 LLM 平台、移动原生 App、
AD/LDAP、在线协同编辑、工作流审批引擎、多进程共享限流存储。

## 6. 对本系统需求的启示

| 调研发现 | 落入本系统的需求/设计 |
|----------|------------------------|
| 权限是企业知识库底线 | SR-AUTH-005/006、机密同部门隔离 |
| 问答必须可核对 | SR-QA-005 来源列表；禁止伪称已调用大模型 |
| 关系视图有差异化价值 | 图谱自动同步 + 管理员手工补边 |
| 演示必须可跑通 | 本地摘要降级、种子数据、启停与自动化测试 |

## 7. 结论

竞品验证了「知识管理 + 智能问答」方向成立。本系统选取 **权限可控的文档库** 为根基，以 **RAG / 知识图谱** 作为智能与洞察切口，并补齐收藏与审计，形成可运行、可测试、文档齐全的完整交付。
