# 用例描述：智能问答

| 项 | 内容 |
|----|------|
| 用例名称 | 智能问答（检索增强） |
| 用例编号 | UC-QA-01 |
| 参与者 | 已登录用户（管理员、普通员工） |
| 用例目标 | 用自然语言提问，在**本人权限范围内**检索知识片段并给出带来源的回答 |
| 优先级 | 高 |
| 前置条件 | 知识库中存在已发布文档；用户已登录；文档已切分建索引 |
| 后置条件 | 生成回答；保存问答历史；写入 `ask_qa` 审计日志 |
| 关联需求 | UR-QA-01～04；SR-QA-001～009 |
| 关联 UML | `docs/uml/03-RAG问答时序图.puml` |
| 触发条件 | 用户在问答页输入问题并提交，或点击示例问题 |

## 基本事件流

| 步骤 | 参与者 | 系统动作 |
|------|--------|----------|
| 1 | 用户进入「站内问答」页 | 展示提问框、示例问题列表与本人最近提问 |
| 2 | 输入问题并提交 | 接收 `POST /qa/` 与问题文本 |
| 3 | — | 对问题分词（jieba + 领域词表补充 + 二字组兜底） |
| 4 | — | **先**按可见性规则圈定可访问且已发布的文档集合 |
| 5 | — | 仅在上述文档的片段内打分，取 Top-K（默认 5） |
| 6 | — | 同一文档最多贡献 2 条来源，保证来源多样性 |
| 7 | — | 判断是否配置了大模型 Key |
| 8 | — | 未配置：将高分片段摘要拼接为回答，并标注来源文档、部门与相关度 |
| 9 | — | 展示回答、来源卡与「当前为本地模式」说明 |
| 10 | 用户点击来源 | 进入对应文档详情（详情页仍会再鉴权一次） |
| 11 | — | 持久化问答历史（问题、回答、来源 JSON、模式）并写 `ask_qa` 审计 |

## 备选事件流

| 编号 | 条件 | 系统行为 |
|------|------|----------|
| 4a | 用户无权访问某机密文档 | 该文档**不进入候选集**，其片段不会出现在来源里，答案中也不会引用其内容 |
| 5a | 无任何片段命中 | 明确告知「未在可访问的知识库中检索到相关内容」，并建议换问法或确认权限，**不伪装成已回答** |
| 7a | 已配置 Key 且调用成功 | 以命中片段为上下文调用大模型生成回答，模式记为 `llm`，仍附带来源 |
| 7b | 已配置 Key 但调用失败 | 回退本地摘要并说明调用失败，**不声称已调用大模型** |
| 2a | 用 GET 带 `?q=` 打开 | 仅预填问题，不触发提问、不写历史，避免刷新页面重复写入 |
| 6a | 片段数不足 Top-K | 有多少返回多少，不补足凑数 |

## 打分规则（摘要）

| 信号 | 权重 |
|------|------|
| 问题原串整段出现在片段正文 | +10 |
| 问题原串出现在标题 | +6 |
| 去掉疑问助词后的短句再次命中正文 | +5 |
| 分词后与标题重合 | 3.2 / 词 |
| 分词后与片段关键词重合 | 1.8 / 词 |
| 分词与正文重合 | 1.0 / 词 |
| 命中词占提问词比例（覆盖率） | 2.0 × 比例 |

分词使用 jieba；「年假」这类默认词典缺失的业务词通过领域词表补全，
未收录词用相邻二字组兜底，避免分词结果为空导致加权全部失效。

## 业务规则

1. 权限过滤必须**先于**检索打分，机密内容不得进入候选集（SR-QA-008）。  
2. 回答必须可核对：给出来源文档标题、部门与相关度。  
3. 不得伪称调用过大模型：模式字段如实记录 `local` / `llm`。  
4. 问答历史仅本人可见（管理员可查看他人）。  
5. 示例问题点击只填表单，不重复写历史。

## 特殊需求

- 性能：演示数据规模下本地模式响应目标 < 5 秒。  
- 可靠性：大模型不可用时整站仍可正常使用。  
- 安全：机密隔离与文档列表、文档详情共用同一套 `can_view_document` 判定。
