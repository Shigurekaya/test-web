# 1 引言

## 1.1 编写目的

本文档定义《智慧企业知识财富库系统》V2.0 的软件需求基线，用于：

1. 明确系统的业务目标、功能边界、权限规则和可验收标准；
2. 为架构设计、接口设计、数据库设计、前端实现、后端实现和测试用例设计提供统一依据；
3. 向课程指导教师和验收组说明系统“已实现什么、如何验证、哪些不在本期范围”；
4. 建立业务目标、功能需求、主要用例、自动化测试和最终验收之间的可追踪关系。

本文档既是需求说明，也是验收依据。需求中使用的“必须”表示验收必须满足，“应”表示正常情况下必须满足、例外需有明确说明，“可”表示允许的增强能力。未列入本期范围的能力不得在验收时被解释为已交付。

## 1.2 项目背景与建设目标

企业内部制度、产品资料、项目经验和安全规范通常分散在邮件、即时通讯、个人网盘及不同部门目录中。员工查找一条规定需要反复询问，新员工上手成本较高；同时，机密材料若仅依赖链接转发或人工提醒，容易出现跨部门越权访问。课程项目需要在一个可运行、可演示、可测试的系统中完整体现需求分析、权限设计、检索问答、知识关联和工程管理过程。

V2.0 的建设目标如下：

| 目标编号 | 目标 | 成功判据 |
| --- | --- | --- |
| G-01 | 建立统一的知识文档库 | 登录用户可在权限范围内浏览、检索、查看和维护制度及业务资料 |
| G-02 | 实现权限可控的知识访问 | 角色、部门、密级和发布状态共同约束列表、详情、检索、问答和图谱 |
| G-03 | 提供可追溯的检索增强问答 | 回答基于用户有权访问的知识片段，并展示文档来源与相关度 |
| G-04 | 建立可理解的知识关系 | 通过文档、部门、分类、关键词节点和关系边呈现知识结构 |
| G-05 | 形成可治理、可审计的管理闭环 | 管理员可查看用户、维护分类与图谱、按条件分页查询审计日志 |
| G-06 | 形成可构建、可启动、可测试的工程交付 | 前后端可构建运行，健康检查可用，自动化测试基线可重复执行 |

# 2 总体描述

## 2.1 产品视图与系统上下文

系统采用前后端分离的 B/S 结构。Vue 3 + Vite 构建的单页应用负责页面路由、表单交互、状态呈现和 ECharts 可视化；Flask 3 提供 REST API，负责会话认证、权限判定、业务规则、数据持久化和审计；SQLAlchemy 负责对象关系映射，默认以 SQLite 文件保存数据；jieba 负责中文分词、关键词提取和检索信号构造；pytest 负责自动化回归。

| 层次 | 主要技术 | 职责 |
| --- | --- | --- |
| 表现层 | Vue 3、Vue Router、ECharts、Vite | 登录、工作台、文档、问答、图谱、管理页面及交互反馈 |
| 接口层 | Flask 3 REST API | HTTP 路由、JSON 请求响应、会话、认证、状态码和错误结构 |
| 业务层 | Flask 服务/蓝图、权限与 RAG/图谱服务 | 可见性判定、文档检索、片段排序、问答、图谱同步、审计 |
| 数据层 | SQLAlchemy、SQLite | 用户、文档、分类、片段、图谱、收藏、问答历史和审计持久化 |
| 质量保障 | pytest | 权限矩阵、API、RAG、登录安全、系统主路径回归 |

系统上下文关系如下：

1. 用户通过桌面浏览器访问 Vue 前端；
2. 前端以同源会话 Cookie 调用 /api 下的 REST 接口；
3. 后端先完成身份认证，再按角色、部门、密级、作者和状态执行授权；
4. 授权通过后，后端从 SQLite 读取或写入业务数据，并生成审计记录；
5. 问答模块在授权后的文档片段集合中检索并生成带来源回答；
6. 图谱模块从文档元数据和关键词同步节点/关系，再按当前用户可见范围返回图数据；
7. 管理员通过受保护接口查看用户、维护分类和图谱、筛选分页查看审计日志；
8. 运维人员通过健康检查确认服务和数据库可用性。

## 2.2 用户角色与职责

| 角色 | 系统标识 | 关键属性 | 职责与能力 |
| --- | --- | --- | --- |
| 管理员 | admin | 角色为管理员，通常归属综合部 | 查看全部文档与图谱；维护文档、分类、图谱；查看用户列表和审计日志；执行全部普通员工功能 |
| 员工 | employee | 角色为员工，必须归属一个部门 | 查看权限范围内文档；执行搜索、问答、收藏；新建文档；编辑/删除本人文档；查看本人问答历史 |
| 文档作者 | 非独立角色 | 由文档 author_id 标识 | 在员工权限基础上，可访问本人草稿/归档文档，可编辑/删除本人文档；对本人机密文档具有作者例外权 |
| 匿名访问者 | 未登录 | 无有效会话 | 仅可访问登录页、系统元信息、会话探测和健康检查；不得访问业务数据 |
| 运维/验收人员 | 非业务角色 | 具备运行环境访问条件 | 执行启动、健康检查、日志查看、构建、自动化测试和验收操作 |

> 角色说明：本期只实现管理员和员工两种角色；“文档作者”是文档级身份，不是第三种系统角色。前端菜单隐藏仅用于改善体验，不能替代服务端授权。

## 2.4 设计与实现约束

1. **架构约束**：前端必须是 Vue 3 + Vite 单页应用；后端必须提供 Flask 3 REST API；业务数据通过 SQLAlchemy 持久化到 SQLite。
2. **接口约束**：前端业务调用统一位于 /api 前缀；JSON 使用 UTF-8；认证使用服务端会话 Cookie，不采用前端自造权限状态。
3. **权限约束**：所有业务接口必须执行服务端鉴权；列表、详情、检索、问答和图谱必须复用一致的可见性判定规则。
4. **数据约束**：用户名、分类名和收藏关系必须满足唯一性；删除文档必须同步清理知识片段、收藏和文档关联图谱节点/边。
5. **问答约束**：核心验收以本地分词检索与摘要式回答为准；不得在无命中时伪造答案，不得泄露无权限文档标题或正文。
6. **图谱约束**：普通用户只能获得基于其可见文档及其相邻节点/关系形成的图谱；管理员可查看完整图谱并执行受控维护。
7. **部署约束**：本期按单机/单进程演示环境设计；登录限流状态保存在进程内，多进程或多机部署不在此期能力承诺内。
8. **安全约束**：密码不得明文存储或返回；生产部署必须配置独立 SECRET_KEY，公网环境必须在前置代理或部署层启用 HTTPS。
9. **课程交付约束**：单人独立完成，但必须保留需求、设计、实现、测试、验收之间的完整追踪证据。

# 3 功能需求

本章按模块给出可设计、可实现、可测试的功能需求。每条需求均包含描述、输入、输出、业务规则、优先级和验收标准。接口路径以第 8 章为准；权限规则以第 4 章为准。

## 3.1 账户与权限 FR-AUTH

### FR-AUTH-001 用户登录

| 属性 | 内容 |
| --- | --- |
| 描述 | 用户使用用户名和密码登录系统；认证成功后建立服务端会话并返回用户身份信息。 |
| 输入 | JSON 或表单字段：username（必填）、password（必填）、remember（可选布尔值）。 |
| 输出 | 成功：HTTP 200，返回 user 对象和“登录成功”消息；失败：HTTP 401，返回统一错误信息；锁定：HTTP 429，返回 retry_after。 |
| 业务规则 | 用户名去除首尾空白后精确匹配；密码使用哈希校验；用户名不存在与密码错误统一提示“用户名或密码错误”，避免账号枚举；成功后清除该来源的失败计数并写入登录审计；失败时写入脱敏后的登录失败审计。 |
| 优先级 | P0 |
| 验收标准 | 正确账号可进入工作台；错误密码不能建立会话；登录成功和失败均可在审计日志中查询；响应中不出现密码哈希。 |

### FR-AUTH-002 退出与会话管理

| 属性 | 内容 |
| --- | --- |
| 描述 | 已登录用户可主动退出；系统可返回当前会话用户，未登录时返回空用户而不将其视为异常。 |
| 输入 | 退出：已认证的 POST 请求；会话探测：GET /api/auth/session。 |
| 输出 | 退出成功：HTTP 200 并清除会话，随后访问受保护接口返回 401；会话探测：user 为用户对象或 null。 |
| 业务规则 | 退出前写入 logout 审计；退出后旧会话不得继续访问受保护资源；默认会话有效期为 12 小时，Cookie 设置 HttpOnly 和 SameSite=Lax。 |
| 优先级 | P0 |
| 验收标准 | 退出后再次请求文档、问答或管理接口均被拒绝；刷新页面后前端能正确识别未登录状态并跳转登录页。 |

### FR-AUTH-003 角色与菜单授权

| 属性 | 内容 |
| --- | --- |
| 描述 | 系统根据管理员/员工角色控制菜单展示和服务端操作权限。 |
| 输入 | 当前会话用户、请求资源和方法。 |
| 输出 | 允许：继续执行并返回业务结果；未登录：401；已登录但无角色权限：403。 |
| 业务规则 | 管理员可访问全部业务和管理接口；员工不可访问用户列表、审计日志、分类新增、图谱维护接口；前端可隐藏管理员入口，但服务端必须再次校验；员工编辑/删除文档时还必须满足作者或管理员条件。 |
| 优先级 | P0 |
| 验收标准 | 员工请求 /api/admin/users 或 /api/admin/audits 返回 403；管理员请求成功；员工不能通过直接构造 URL 绕过页面限制。 |

### FR-AUTH-004 登录防爆破

| 属性 | 内容 |
| --- | --- |
| 描述 | 对同一客户端地址的连续登录失败实施滑动窗口计数和临时锁定。 |
| 输入 | 登录请求的客户端 IP、失败事件时间、配置 LOGIN_MAX_ATTEMPTS 与 LOGIN_WINDOW_SECONDS。 |
| 输出 | 锁定前：登录失败 401；达到阈值后：429，返回剩余等待秒数；成功后：失败计数清零。 |
| 业务规则 | 默认阈值为 8 次/300 秒；先判定锁定再校验密码，锁定期间即使密码正确也不得登录；窗口外旧失败事件自动过期；不同 IP 的计数相互独立；失败事件写入审计；本期限流为进程内实现。 |
| 优先级 | P0 |
| 验收标准 | 连续失败达到阈值后返回 429；锁定期间正确密码仍被拒绝；等待窗口结束可恢复；成功登录后计数清零；多进程共享限流不在本期验收范围。 |

### FR-AUTH-005 密码安全存储

| 属性 | 内容 |
| --- | --- |
| 描述 | 用户密码只保存带盐慢哈希，不保存明文，不通过接口返回。 |
| 输入 | 用户设置密码或演示数据初始化时的密码。 |
| 输出 | 数据库中仅存在 password_hash；认证时进行哈希校验。 |
| 业务规则 | 使用 Werkzeug 提供的带盐慢哈希机制（当前运行环境为 scrypt 系列）；任何管理列表、会话、审计和错误响应不得包含 password_hash；日志不得记录明文密码。 |
| 优先级 | P0 |
| 验收标准 | 检查数据库和 API 响应均未出现明文密码或哈希原文；错误密码不能通过哈希校验；自动化安全用例覆盖密码存储检查。 |

### FR-AUTH-006 登录后安全回跳

| 属性 | 内容 |
| --- | --- |
| 描述 | 登录后可回到站内原目标页面，但必须拒绝站外和危险回跳地址。 |
| 输入 | 可选 next 参数。 |
| 输出 | 安全站内相对路径；非法值丢弃并回到工作台或默认页。 |
| 业务规则 | 仅接受以单个斜杠开头的站内相对路径；拒绝包含协议、域名、双斜杠、反斜杠、换行、回车或空字符的地址；不得通过回跳泄露登录态。 |
| 优先级 | P1 |
| 验收标准 | 常见恶意 next 值被拒绝；合法站内路径可正常回跳；未登录访问业务页时能携带安全的目标路径到登录页。 |

## 3.2 知识文档 FR-DOC

### FR-DOC-001 文档列表与权限过滤

| 属性 | 内容 |
| --- | --- |
| 描述 | 登录用户可分页浏览其权限范围内的已发布文档。 |
| 输入 | 页码 page、每页数量 per_page、可选筛选条件。 |
| 输出 | items 文档摘要数组、pagination、categories、departments、当前 filters。 |
| 业务规则 | 默认每页 9 条，API 每页上限 50；只展示 published 文档；列表总数和分页必须在权限过滤后计算；管理员可看到全部已发布文档，员工按公开、内部、机密规则过滤；默认按更新时间倒序。 |
| 优先级 | P0 |
| 验收标准 | 员工列表不出现无权限机密文档；分页总数与该用户可见集合一致；管理员可见全量已发布文档；列表不会因分页或筛选泄露被过滤文档的数量。 |

### FR-DOC-002 关键词检索、筛选与排序

| 属性 | 内容 |
| --- | --- |
| 描述 | 用户可按关键词检索标题、摘要、标签和正文，并按分类、部门、密级和排序方式筛选。 |
| 输入 | q、category_id、department、visibility、sort、page、per_page。 |
| 输出 | 按相关度或指定排序返回的文档摘要及分页信息。 |
| 业务规则 | 检索前先执行权限过滤；关键词命中标题、标签、摘要和正文时综合评分，标题与标签优先；有 q 时按相关度排序，无 q 时支持最近更新、标题顺序、部门分组；分类、部门、密级条件可组合；不存在或非法参数使用安全默认值。 |
| 优先级 | P0 |
| 验收标准 | 搜索“年假”能命中相关制度并优先展示；正文中的关键词可被检索；分类、部门、密级筛选结果正确；越权文档不进入候选集。 |

### FR-DOC-003 文档详情与相关推荐

| 属性 | 内容 |
| --- | --- |
| 描述 | 用户可查看有权访问的文档详情，并获得权限范围内的相关文档建议。 |
| 输入 | 文档 ID、当前用户。 |
| 输出 | document 对象（含正文、分类、作者、版本、密级、状态、标签、字符数、片段数）、related 最多 4 篇、can_edit 布尔值。 |
| 业务规则 | 不存在的文档返回 404；无权限返回 403；草稿和归档文档仅作者或管理员可直接访问；published 文档按密级判定；相关文档按同分类、同部门、标签重叠综合筛选，且必须再次执行可见性过滤；同一用户 2 分钟内重复打开同一文档最多写入一次 view_document 审计。 |
| 优先级 | P0 |
| 验收标准 | 同部门机密可查看，异部门机密返回 403；作者可查看本人草稿；相关推荐不含越权文档；查看审计可查询且不会因反复刷新无限增长。 |

### FR-DOC-004 新建文档

| 属性 | 内容 |
| --- | --- |
| 描述 | 登录用户可创建知识文档并立即进入可检索、可建图的已发布或草稿状态。 |
| 输入 | title、content（均为必填）；summary、category_id、department、visibility、status、version、tags（可选）。 |
| 输出 | HTTP 201；返回完整 document 对象和“文档已创建”消息。 |
| 业务规则 | 标题和正文去空白后必须非空；摘要为空时从正文自动截取；分类必须存在；部门必须来自系统部门词表，否则使用当前用户部门；visibility 缺省为 internal，status 缺省为 published，version 缺省为 1.0；tags 可为数组并规范化为逗号分隔文本；创建后重建知识片段、同步图谱并写入 create_document 审计；整个过程在事务保护下完成。 |
| 优先级 | P0 |
| 验收标准 | 合法文档创建成功并可按权限检索；空标题或空正文返回 400；不存在的分类返回 400；新文档片段和图谱关系自动生成；审计可见创建记录。 |

### FR-DOC-005 编辑文档

| 属性 | 内容 |
| --- | --- |
| 描述 | 文档作者或管理员可修改文档内容和元数据。 |
| 输入 | 文档 ID、与新建基本一致的字段集合。 |
| 输出 | HTTP 200；返回更新后的 document 对象和“文档已更新”消息。 |
| 业务规则 | 仅作者或管理员可编辑，其他用户返回 403；校验规则同新建；更新后必须重建知识片段并重新同步图谱，避免旧正文继续被问答检索；写入 edit_document 审计；变更提交失败时不得留下半更新状态。 |
| 优先级 | P0 |
| 验收标准 | 作者可编辑并立即检索到新正文；非作者员工编辑返回 403；分类不存在时拒绝更新；编辑审计可查询；图谱节点标题和关系随更新同步。 |

### FR-DOC-006 删除文档

| 属性 | 内容 |
| --- | --- |
| 描述 | 文档作者或管理员可删除文档。 |
| 输入 | 文档 ID。 |
| 输出 | HTTP 200 和“文档已删除”消息。 |
| 业务规则 | 仅作者或管理员可删除；删除文档时级联清理知识片段和收藏关系，并清理关联图谱节点及边；写入 delete_document 审计；删除后不得再出现在列表、检索、问答历史和新的图谱查询中（历史问答记录本身按历史口径保留）。 |
| 优先级 | P0 |
| 验收标准 | 作者删除成功；其他员工删除返回 403；删除后检索不再命中；图谱无残留文档节点；审计保留删除记录。 |

### FR-DOC-007 文档元数据与发布状态

| 属性 | 内容 |
| --- | --- |
| 描述 | 文档支持分类、标签、版本、部门、密级和发布状态等元数据。 |
| 输入 | category_id、tags、version、department、visibility、status。 |
| 输出 | 文档列表和详情中的标准化标签、密级文案、状态文案和版本号。 |
| 业务规则 | 密级取值仅允许 public、internal、secret；状态取值仅允许 draft、published、archived；标签以逗号分隔并去除空项；版本使用字符串表达，默认 1.0；普通用户只能选择系统部门词表中的部门；非法枚举值回退到安全默认值或被拒绝。 |
| 优先级 | P1 |
| 验收标准 | 三个密级和三个状态在界面与 API 中文案一致；非法值不能写入；标签、版本和分类正确回显；状态对列表、检索、问答和图谱的影响符合第 4 章矩阵。 |

### FR-DOC-008 收藏与取消收藏

| 属性 | 内容 |
| --- | --- |
| 描述 | 用户可收藏或取消收藏其有权查看的文档，并查看个人收藏列表。 |
| 输入 | 文档 ID、当前用户。 |
| 输出 | is_favorite 布尔值和“已收藏/已取消收藏”消息；收藏列表返回当前用户可见的收藏文档。 |
| 业务规则 | 同一用户与同一文档最多一条收藏记录；操作按切换语义执行；不可收藏无权限文档；收藏列表必须再次过滤权限，避免文档密级变化后泄露；收藏为个人数据，不向其他员工展示。 |
| 优先级 | P1 |
| 验收标准 | 收藏后出现在“我的收藏”；再次操作取消；重复数据不产生；异部门机密不能收藏；其他用户看不到该用户的收藏。 |

### FR-DOC-009 知识片段与图谱同步

# 4 权限矩阵

## 4.1 权限判定原则

1. **默认拒绝**：未建立有效会话的请求不得访问任何业务数据。
2. **服务端为准**：前端菜单、路由守卫和按钮显示只改善体验，最终授权以 Flask API 的服务端会话和角色判定为准。
3. **最小必要**：用户只能看到完成当前任务所需的数据；无权限文档不得进入列表总数、检索候选、问答来源、图谱节点或统计口径。
4. **统一口径**：文档列表、详情、问答检索、相关推荐、收藏过滤和图谱过滤必须复用一致的可见性规则。
5. **多层约束**：文档访问同时考虑登录状态、角色、部门、密级、作者和发布状态；满足一个条件不代表自动满足全部条件。
6. **管理隔离**：管理员能力通过独立接口和统一管理员校验保护；员工即使知道路径也不能操作。

## 4.5 权限执行链

一次受保护 API 请求按以下顺序处理：

1. 解析会话，判断是否已登录；未登录返回 401；
2. 判断接口是否要求管理员；不满足返回 403；
3. 读取资源并判断存在性；不存在返回 404；
4. 判断文档密级、部门、作者和状态；不满足返回 403；
5. 在候选数据集合上执行检索、问答、图谱或统计；
6. 写入必要的审计或业务记录；
7. 以统一 JSON 结构返回结果。

该顺序必须在所有相关接口中保持一致，尤其禁止“先检索全库、再由前端隐藏结果”的实现方式。

# 6 数据需求

## 6.1 数据原则

1. 业务数据使用 SQLAlchemy 模型映射到 SQLite；默认数据库文件为 instance/knowledge.db。
2. 认证凭据只保存密码哈希，不保存明文密码；敏感配置通过环境变量注入。
3. 文档、知识片段、分类、图谱、收藏、问答历史和审计日志必须保持可追溯关系。
4. 写操作应使用事务；对文档、片段和图谱的联动更新必须保持原子性。
5. 演示数据必须明确为虚构内容，不得写入真实企业机密或个人信息。
6. 自动化测试使用隔离数据库，不读写演示库；最终验收数据以演示库为样本但不以测试数据充当真实业务数据。

## 6.2 核心数据实体

| 实体 | 关键字段 | 业务约束与说明 |
| --- | --- | --- |
| 用户 User | id、username、password_hash、display_name、role、department、created_at | 用户名唯一且索引；角色仅为 admin/employee；部门为受控词表；密码只存哈希 |
| 分类 Category | id、name、description | 分类名唯一；用于文档归类和图谱概念节点 |
| 文档 Document | id、title、content、summary、department、visibility、status、version、tags、category_id、author_id、created_at、updated_at | 标题和正文必填；密级三枚举；状态三枚举；删除时级联清理片段和收藏 |
| 知识片段 KnowledgeChunk | id、document_id、chunk_index、content、keywords | 属于文档；正文按配置切分；编辑时重建，删除时清理 |
| 图谱节点 GraphNode | id、name、node_type、description、document_id | 名称唯一；node_type 为 document/department/project/keyword/concept；文档节点可关联 document_id |
| 图谱边 GraphEdge | id、source_id、target_id、relation | 两端引用图谱节点；同一源、目标、关系不重复；删除节点时清理关联边 |
| 收藏 Favorite | id、user_id、document_id、created_at | 用户和文档组合唯一；只对有权访问文档展示 |
| 问答历史 QAHistory | id、user_id、question、answer、sources、mode、created_at | 保存问题和回答；sources 为来源 JSON；普通用户只查看本人，管理员可查看详情 |
| 审计日志 AuditLog | id、user_id、action、detail、created_at | user_id 可为空以记录未知账号失败；动作和明细不可由普通用户修改 |

## 6.3 数据关系

| 关系 | 基数 | 说明 |
| --- | --- | --- |
| 用户—文档 | 1:N | 一个用户可创建多篇文档；文档作者用于作者例外和编辑/删除权限 |
| 分类—文档 | 1:N | 一个分类可包含多篇文档；文档可暂不分类 |
| 文档—知识片段 | 1:N | 一篇文档切分为多个可检索片段；片段随文档重建或删除 |
| 用户—收藏—文档 | M:N | 通过 Favorite 建立；同一用户和文档最多一条 |
| 用户—问答历史 | 1:N | 每条问答绑定提交用户；用于个人历史追溯 |
| 用户—审计日志 | 1:N | 审计可绑定用户；未知用户名登录失败可保留空用户引用 |
| 文档—图谱节点 | 1:0..1（逻辑） | 文档节点可关联文档 ID；部门、分类和关键词概念节点可被多篇文档共享 |
| 图谱节点—图谱边 | 1:N（两端） | 节点可作为源或目标；删除节点时清理相关边 |

## 6.4 文档生命周期与数据联动

| 阶段 | 数据动作 | 可检索性 | 审计 |
| --- | --- | --- | --- |
| 创建 | 写入文档、摘要、片段和图谱；提交事务 | 已发布文档立即可检索；草稿不进入普通检索 | create_document |
| 编辑 | 更新文档、重建片段、同步图谱 | 新正文立即生效，旧片段不再作为检索依据 | edit_document |
| 发布 | 状态改为 published | 进入权限内列表、搜索、问答和图谱候选 | 编辑动作 |
| 归档 | 状态改为 archived | 退出普通列表、搜索、问答和图谱候选 | 编辑动作 |
| 收藏 | 写入或删除 Favorite | 不影响文档内容；收藏列表重新校验权限 | 本期不单独记审计 |
| 删除 | 删除文档、片段、收藏，清理图谱节点/边 | 不再可检索或展示 | delete_document |
| 问答 | 写入 QAHistory 和 sources | 历史保留问题、回答和来源；不改变文档内容 | ask_qa |
| 查看 | 读取详情；2 分钟内同文档去重记录 | 只对有权用户可见 | view_document |

## 6.5 数据质量、保留与安全

1. **完整性**：文档必须具有标题、正文、密级、状态和作者；分类引用必须存在；图谱边端点必须存在。
2. **一致性**：编辑文档后片段与图谱必须同步；删除文档后不得留下可访问的孤儿片段或文档节点。
3. **唯一性**：用户名、分类名、收藏“用户—文档”组合和图谱节点名称必须满足唯一约束。
4. **时效性**：问答历史、审计日志和文档更新时间以本地演示时区展示；时间格式统一到秒，不展示微秒。
5. **保密性**：密码哈希、SECRET_KEY、外部服务密钥不得进入前端、审计或错误响应。
6. **保留策略**：本期未实现自动清理和归档策略；验收演示数据随演示库保留。部署方如需长期使用，应另行制定备份、归档和审计留存制度。
7. **数据规模**：本期按课程演示规模验收，不承诺百万级文档、高并发写入或跨地域复制。

# 9 异常处理

## 9.1 HTTP 状态与错误约定

| 条件 | HTTP 状态 | 错误标识/表现 | 客户端处理 |
| --- | --- | --- | --- |
| 未登录访问受保护接口 | 401 | AUTH_REQUIRED | 清理会话状态并跳转登录页 |
| 用户名或密码错误 | 401 | INVALID_CREDENTIALS | 显示统一错误，不透露账号是否存在 |
| 登录失败达到阈值 | 429 | 返回 error 和 retry_after | 显示剩余等待时间，禁用重复提交 |
| 已登录但角色或数据权限不足 | 403 | FORBIDDEN | 显示无权限提示，不展示资源内容 |
| 文档、历史或资源不存在 | 404 | NOT_FOUND | 显示不存在提示并提供返回入口 |
| 必填项为空、枚举非法、分类不存在、名称重复 | 400 | VALIDATION_ERROR | 在表单或提示条显示可修正信息 |
| 问答无命中 | 200 | 正常回答结构中的无命中提示 | 显示建议换问法或确认权限 |
| 外部增强服务不可用 | 200 或受控降级结果 | 本地模式或明确失败说明 | 保留本地问答结果，不展示密钥或堆栈 |
| 数据库不可用 | 健康检查 degraded；业务请求可能 500 | 统一错误响应 | 提示服务异常，运维查看日志 |
| 未处理服务器异常 | 500 | 通用错误文本 | 不展示裸堆栈；记录服务端日志并允许重试 |

## 9.2 主要业务异常

| 异常场景 | 业务处理 |
| --- | --- |
| 登录锁定期间提交正确密码 | 仍返回 429，不校验通过，不建立会话 |
| 登录失败后用户不存在 | 写入匿名登录失败审计，返回统一凭据错误 |
| 编辑或删除他人文档 | 返回 403，文档内容不变 |
| 查看他部门机密文档 | 返回 403；列表、检索、问答和图谱均不返回该文档 |
| 草稿/归档被普通用户访问 | 返回 403；作者/管理员允许 |
| 文档标题或正文为空 | 拒绝保存并返回 400 |
| 分类 ID 不存在 | 拒绝新建/更新文档并返回 400 |
| 分类名重复 | 拒绝新增分类并返回 400 |
| 图谱节点名为空 | 拒绝新增并返回 400 |
| 图谱关系端点为空 | 拒绝新增并返回 400 |
| 删除文档 | 清理片段、收藏、图谱节点和边；写入审计；失败则事务回滚 |
| 问答空问题 | 返回 400，不写入历史 |
| 问答无命中 | 返回明确无命中回答，不伪造来源 |
| 问答历史越权 | 普通用户访问他人记录返回 403 |
| 审计页码越界 | 自动收敛到最后有效页，返回有效分页信息 |
| 前端请求网络失败 | 显示错误提示，保留当前页面可重试状态 |

## 9.3 事务、审计与日志要求

1. 文档保存、片段重建、图谱同步和审计写入应在可回滚的事务边界内完成；任一步骤失败不得返回成功。
2. 审计日志是业务追溯记录，不由普通用户编辑或删除；本期不提供审计修改接口。
3. 登录失败、登录成功、退出、文档查看、文档创建/编辑/删除和问答均应有对应审计动作。
4. 同一用户 2 分钟内重复打开同一文档可去重 view_document 审计，避免刷新导致日志无限膨胀。
5. 服务端异常应记录到运行日志；面向用户的错误响应不得包含堆栈、文件绝对路径、数据库连接字符串和密钥。
6. 前端收到 401 后应清理本地会话状态并引导重新登录；收到 403 不得继续尝试展示缓存中的无权限正文。

## 9.4 容错与降级边界

1. 无外部大模型配置时，本地检索摘要模式是正常模式，不是系统故障。
2. 外部增强服务失败时，本地检索与摘要仍应可工作；若无法降级，应明确告知失败原因类别，不伪装成功。
3. 图谱无数据时返回空节点/关系集合，页面显示空状态，不返回 500。
4. 健康检查仅证明服务和数据库基本可访问，不证明所有业务功能、权限和问答质量均正常。
5. 登录限流状态在进程重启后清空属于当前单机实现边界，应在部署说明中明确。

## 11.5 阻断性验收条件

出现以下任一情况，应判定本轮验收不通过：

1. 未登录或无权限用户能够读取机密文档正文、标题、问答来源或图谱节点；
2. 员工能够通过直接请求管理 API 获得用户、审计、分类新增或图谱维护能力；
3. 密码明文存储、密码哈希被 API 返回，或错误响应泄露 SECRET_KEY；
4. 文档列表、搜索、问答或图谱对同一机密文档产生互相矛盾的权限结果；
5. 前端无法构建、后端无法启动、健康检查不可用，导致主流程无法演示；
6. 新建/编辑文档后索引未同步，使问答继续使用旧正文；
7. 问答无命中时伪造来源，或将无权限文档作为来源；
8. 验收执行时自动化测试存在未说明的失败，且影响 P0 需求。
