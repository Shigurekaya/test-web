# 用户需求说明书

**项目名称**：智慧企业知识财富库系统  
**文档版本**：V1.3

---

## 1. 引言

### 1.1 编写目的

定义本系统的用户需求，作为后续系统需求、设计、实现与测试的依据。读者包括：项目组及产品、测试、运维相关干系人。

### 1.2 项目背景

企业内部制度、产品手册与项目经验常散落在邮件、即时通讯与个人网盘：员工查一条规定成本高，新人上手慢，机密材料又容易因链接转发而越权。本项目建设轻量可运行的「智慧企业知识财富库」：在权限可控的文档库之上，提供自然语言问答与知识关系浏览。

### 1.3 定义与缩略语

| 术语 | 说明 |
|------|------|
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| 知识片段 | 文档切分后的可检索单元（Chunk） |
| 可见性 | public / internal / secret 三级 |

### 1.4 参考资料

- 本项目《竞品调研报告》《系统需求说明书》及 UML 图  
- Flask / SQLAlchemy / ECharts / jieba 等相关技术文档

## 2. 项目概述

### 2.1 产品愿景

帮助企业员工快速查找制度与经验，并通过问答获得带来源的答案，同时理解知识之间的组织关系。

### 2.2 用户角色

| 角色 | 描述 | 典型诉求 |
|------|------|----------|
| 管理员 | 系统运维与内容治理 | 分类、图谱维护、审计、用户查看 |
| 普通员工 | 各部门业务人员 | 查文档、提问、收藏 |
| 部门敏感岗位 | 如信息部 | 访问本部门机密文档 |

### 2.3 运行环境（用户侧）

- 桌面浏览器（Chrome / Edge 近两年版本）  
- 局域网或本机访问 Web 服务  

---

## 3. 业务需求

### BR-01 知识沉淀
员工可将制度、手册、培训资料录入系统并分类管理。

### BR-02 安全可控
不同密级文档对可见范围不同，机密文档按部门隔离。

### BR-03 智能问答
用户可用自然语言提问，系统基于知识库作答并提示来源。

### BR-04 关系洞察
用户可浏览文档与部门、关键词等实体的关联图。

### BR-05 可追溯
关键操作可审计，个人可收藏常用文档。

## 5. 非功能需求

| 编号 | 类别 | 描述 |
|------|------|------|
| NFR-01 | 可用性 | 核心页面 3 次点击内可达 |
| NFR-02 | 性能 | 演示数据规模下问答响应通常 &lt; 3 秒（本地模式） |

| NFR-05 | 兼容 | 支持 Windows 本地部署 |

## 6. 典型使用场景（用户故事摘要）

1. **人事同事**：登录后搜索「年假」，阅读管理办法；再在问答里问「员工年假有几天」，核对来源是否指向同一制度。  
2. **财务同事**：按分类筛选差旅/采购相关文档；对「两万元采购谁审批」提问，查看命中片段。  
3. **信息部同事**：用本部门账号打开机密安全规范；确认其他部门账号会被拒绝。  
4. **管理员**：维护分类与图谱补边，并在审计中核对登录、浏览、问答记录，以及异常登录失败尝试。

## 7. 验收标准（用户视角）

1. 能登录并看到工作台统计与建议试用路径。  
2. 提问「年假几天」能得到与年休假制度相关的回答及来源。  
3. 图谱页能看到节点连线并可交互。  
4. 人事账号无法打开信息部机密文档，信息部账号可以。  
5. 管理员能看到审计记录；普通员工能使用收藏。  
6. 未配置外部大模型时，系统仍能以本地摘要方式回答，且不伪装成已调用大模型。  
7. 连续输错密码达到阈值后被临时锁定，即便之后密码正确也须等待解锁。  
8. 管理员可在审计日志中看到登录失败记录；普通员工看不到他人记录。
