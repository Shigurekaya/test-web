## 1 概述

### 1.1 目标

#### 1.1.1 背景

企业内部制度、产品手册、项目模板与安全规范往往分散在邮件附件、即时通讯群文件与个人网盘中。员工查询一条规定（例如年假天数、差旅住宿上限）需要反复询问同事，新人上手成本高；同时，机密类规范若缺乏按部门隔离，存在越权阅读风险。本项目建设「智慧企业知识财富库系统」，以可鉴权的文档库为底座，提供检索增强问答与知识关联（关系图）能力，并配套完整需求、设计、UML 与测试文档。

#### 1.1.2 目标

本文档在《用户需求说明书》基础上，给出可设计、可实现、可测试的**系统需求**，明确：

- 系统功能模块边界与优先级；  
- 主要业务流程与系统侧处理规则；  
- 技术约束、数据与接口要求；  
- 非功能指标（本机 / 局域网演示环境口径）。  

编号约定：系统需求统一使用 `SR-模块-序号`；与用户需求 `UR-*` 对应关系见第 4 章。

### 1.2 范围

#### 1.2.1 业务系列范围

本系统属于企业内部知识管理类 Web 应用（B/S），面向在职员工与系统管理员，提供制度与经验的归档、检索、问答与关系浏览。不属于对外 SaaS 商业产品，不接入真实 HR/OA 生产库。

#### 1.2.2 功能模块范围

| 模块名称 | 功能说明 | 优先级 | 类型 |
|----------|----------|--------|------|
| 用户认证与授权模块 | 登录登出、会话、角色菜单、文档密级鉴权 | 高 | 核心 |
| 知识文档模块 | 分类、检索、详情、新建编辑删除、发布状态 | 高 | 核心 |
| 站内问答（检索增强）模块 | 分词检索、摘要/可选大模型回答、来源与历史 | 高 | 核心 |
| 知识关系图模块 | 节点边数据、力导向可视化、管理员维护 | 高 | 核心 |
| 收藏与审计模块 | 个人收藏、关键操作审计查询 | 中 | 支撑 |
| 系统运维模块 | 健康检查、关于页、启停与自动化测试入口 | 中 | 支撑 |

**本期明确不做（避免范围膨胀）：** 完整向量数据库与生产级 LLM 运维、移动原生 App、与真实 AD/LDAP 对接、在线协同编辑、工作流引擎审批。

### 1.3 约定、限制及假设

1. **技术约束**：后端采用 Python + Flask，按 MVC（Model / Jinja2 View / Blueprint Controller）组织；持久化默认 SQLite。  
2. **运行约束**：单机或局域网演示；默认监听 `127.0.0.1:5000`。  
3. **安全约束**：密码使用 Werkzeug 哈希；会话由 Flask-Login 维护；机密文档按「同部门或管理员」判定。演示环境可不启用 HTTPS。  
4. **问答约束**：未配置 `OPENAI_API_KEY` 时，仅使用本地分词 + 片段评分 + 摘要拼接；配置后可在命中片段上下文上调用 Chat Completions。  
5. **数据假设**：启动时自动建表并写入虚构演示账号与制度文本；正文不代表真实企业规章。  
6. **并发假设**：以单人演示与功能验证为主，不做千人并发压测。

### 1.4 适用读者

项目开发与测试人员、产品与运维相关干系人；亦可作为设计说明书与测试用例编写依据。

## 2 功能性需求

### 2.1 概述

本章描述系统侧必须实现的能力：先给出跨模块业务流程，再按模块列出可测试的 `SR` 条目。实现位置见第 4 章追踪表。

### 2.2 业务流程

#### 2.2.1 用户登录流程

1. 用户打开登录页，输入用户名与密码。  
2. 系统校验账号是否存在、密码哈希是否匹配。  
3. 失败：提示错误，不建立会话。  
4. 成功：建立登录会话，写入审计日志（登录），跳转工作台（或 `next` 安全回跳地址）。  
5. 用户点击退出：清除会话，可写登出审计。

（对应 UML：登录时序图）

#### 2.2.2 知识文档发布与检索流程

1. 授权用户填写标题、正文、分类、标签、密级、状态等字段并保存。  
2. 系统持久化文档；若状态为已发布，则按配置切分 Chunk，并同步关系图中的文档/部门/关键词节点与边。  
3. 其他用户在列表页按关键词、分类、部门、密级筛选；系统仅返回其有权访问且已发布的文档。  
4. 打开详情前再次鉴权；无权限返回 403。

（对应 UML：文档发布活动图、文档状态图）

#### 2.2.3 站内问答流程

1. 用户输入自然语言问题并提交。  
2. 系统对问题分词，在**当前用户权限内**的知识片段中评分，取 Top-K。  
3. 无外部 Key：将高分片段摘要拼接为回答，并返回来源列表。  
4. 有外部 Key：将片段作为上下文调用大模型生成回答，仍附带来源。  
5. 持久化问答历史与审计；用户可回顾本人历史（管理员可按策略查看）。

（对应 UML：RAG 问答时序图）

#### 2.2.4 关系图浏览与维护流程

1. 用户打开关系图页，前端请求图数据 JSON。  
2. 系统返回节点（文档/部门/项目/关键词/概念等）与边。  
3. 前端力导向渲染，支持拖拽与缩放。  
4. 管理员可在维护页手工新增节点或关系，用于补全自动同步未覆盖的关联。

### 2.3 业务需求

#### 2.3.1 业务需求 1：用户认证与授权模块

**【需求描述】**  
提供系统安全入口与持续会话，并按角色、部门、文档密级控制菜单与资源访问。

**【功能需求】**

| 需求编号 | 需求描述 |
|----------|----------|
| SR-AUTH-001 | 支持用户名 + 密码登录；校验失败须明确提示且不泄露具体是用户名还是密码错误以外的敏感信息（实现：统一「用户名或密码错误」即可） |
| SR-AUTH-002 | 登录成功后使用服务端会话维持登录态，未登录访问受保护路由应跳转登录页 |
| SR-AUTH-003 | 支持主动退出登录并清除会话 |
| SR-AUTH-004 | 角色至少区分 `admin`（管理员）与 `employee`（普通员工），菜单按角色显示管理入口 |
| SR-AUTH-005 | 文档访问规则：管理员可访问全部；`secret` 文档仅同部门用户或文档作者可访问；`internal`/`public` 对已登录员工可见（公开仍需登录后使用本系统） |
| SR-AUTH-006 | 无权限访问文档详情时返回 HTTP 403，并避免泄露正文 |
| SR-AUTH-007 | 登录等关键动作写入审计日志 |

#### 2.3.2 业务需求 2：知识文档模块

**【需求描述】**  
支撑制度与经验的结构化沉淀，提供列表检索、详情阅读与授权编辑能力。

**【功能需求】**

| 需求编号 | 需求描述 |
|----------|----------|
| SR-DOC-001 | 列表仅返回当前用户可访问且状态为已发布的文档（管理编辑界面可对本人/管理员开放草稿等，以实现为准并在测试中覆盖） |
| SR-DOC-002 | 支持按关键词检索标题、摘要、正文、标签 |
| SR-DOC-003 | 支持按分类、所属部门、密级筛选 |
| SR-DOC-004 | 提供文档详情页，展示正文、摘要、分类、部门、标签、版本、状态、密级、更新时间等 |
| SR-DOC-005 | 授权用户可新建、编辑、删除文档；字段含分类、标签、版本、可见性、状态 |
| SR-DOC-006 | 文档保存后自动切分并写入 `knowledge_chunks`（切分大小与重叠可配置） |
| SR-DOC-007 | 文档保存后同步更新关系图相关节点与边 |
| SR-DOC-008 | 管理员可维护文档分类（增删改名称与说明） |
| SR-DOC-009 | 列表支持分页，避免一次渲染过多卡片 |

#### 2.3.3 业务需求 3：站内问答（检索增强）模块

**【需求描述】**  
允许用户用自然语言提问，在权限约束下检索知识片段并生成带来源的回答。

**【功能需求】**

| 需求编号 | 需求描述 |
|----------|----------|
| SR-QA-001 | 提供问答页，接收用户问题文本 |
| SR-QA-002 | 对问题进行中文分词，并在用户可访问文档对应的 Chunk 中评分排序，取 Top-K |
| SR-QA-003 | 无大模型 Key 时输出本地摘要型回答，不得伪称已调用大模型 |
| SR-QA-004 | 有大模型 Key 时，仅将命中片段作为上下文调用接口生成回答 |
| SR-QA-005 | 回答页展示检索依据（来源文档标题、部门、片段摘要、相关度） |
| SR-QA-006 | 问答结果持久化到 `qa_history`（问题、答案、来源、模式、时间、用户） |
| SR-QA-007 | 用户可查看本人历史问答详情；越权访问应拒绝 |
| SR-QA-008 | 问答过程不得返回当前用户无权阅读的机密片段内容 |
| SR-QA-009 | 提供若干示例问题入口，降低演示与新用户成本 |

#### 2.3.4 业务需求 4：知识关系图模块

**【需求描述】**  
以图形式展示文档与部门、关键词等实体关系，辅助理解知识组织，并允许管理员手工修补。

**【功能需求】**

| 需求编号 | 需求描述 |
|----------|----------|
| SR-KG-001 | 提供关系图页面与 `/graph/data`（或等价路径）JSON 接口，返回 nodes / links |
| SR-KG-002 | 前端使用力导向图渲染，支持拖拽、缩放与关系标签展示 |
| SR-KG-003 | 节点类型至少覆盖文档、部门，并宜包含关键词/项目/概念等扩展类型 |
| SR-KG-004 | 管理员可新增节点与边，用于补全自动同步不足的部分 |
| SR-KG-005 | 文档变更后关系数据应可再次同步，避免长期陈旧 |

#### 2.3.5 业务需求 5：收藏与审计模块

**【需求描述】**  
方便个人沉淀常用文档，并对关键操作留痕，满足可追溯的管理要求。

**【功能需求】**

| 需求编号 | 需求描述 |
|----------|----------|
| SR-FAV-001 | 用户可收藏 / 取消收藏文档 |
| SR-FAV-002 | 收藏表对 `(user_id, document_id)` 唯一，防止重复收藏 |
| SR-FAV-003 | 提供「我的收藏」列表入口 |
| SR-AUD-001 | 对登录、查看文档、问答、文档增删改等动作写入 `audit_logs` |
| SR-AUD-002 | 管理员可按时间倒序浏览审计列表 |

#### 2.3.6 业务需求 6：系统运维与工作台模块

**【需求描述】**  
为日常使用与演示提供汇总入口与运行状态感知。

**【功能需求】**

| 需求编号 | 需求描述 |
|----------|----------|
| SR-OPS-001 | 登录后工作台展示当前用户可访问文档数、近期问答、最近文档等摘要信息 |
| SR-OPS-002 | `/health` 返回应用标识、版本与数据库连通性 |

## 3 非功能性需求

### 3.1 用户界面及易用性需求

1. 界面为中文；导航结构按「工作台 / 知识文档 / 站内问答 / 关系图 / 收藏 / 关于」组织，管理功能收入管理员菜单。  
2. 列表、表单、空状态需有可读提示；问答页提供示例问题。  
3. 布局适配常见桌面浏览器宽度；主要操作无需安装客户端。  
4. 错误页覆盖 403 / 404 / 500 等常见情况，避免向最终用户展示裸堆栈（调试模式除外）。

### 3.2 安全性需求

1. 密码不可明文存储。  
2. 服务端鉴权不可仅依赖前端隐藏按钮。  
3. 问答与列表共用同一套文档可见性判定。  
4. 本机演示可在 HTTP 进行；若部署到公网，须另行启用 HTTPS 与更严的密钥与会话策略（超出本期必做范围，但设计上预留配置项）。  
5. 模板输出应对用户生成内容做转义，降低 XSS 风险。

### 3.3 可靠性需求

1. 数据库文件损坏或缺失时，重启应能重建表结构并重新灌入演示数据（或给出明确修复步骤）。  
2. 外部大模型调用失败时，应降级或提示，避免整站不可用。  
3. 关键写操作使用数据库事务提交，避免半写入状态长期残留。

### 3.4 性能需求（演示环境）

| 指标 | 要求 |
|------|------|
| 普通页面响应 | 本机演示环境下常见列表/详情页目标 ≤ 3 秒 |
| 问答响应（本地模式） | 演示数据规模下目标 ≤ 5 秒 |
| 关系图首屏 | 演示节点规模下可交互加载，允许首次布局抖动 |
| 并发 | 非本期硬性指标；实现上避免明显无索引全表扫描即可 |

### 3.5 可扩展性及可维护性

1. 按 Blueprint / services 分层，问答与图谱逻辑不写入模板。  
2. 切分参数、密钥等通过配置注入，避免硬编码散落。  
3. 提供自动化测试入口，覆盖登录、检索、权限、问答等主路径。  
4. 预留大模型开关：无 Key 本地模式 / 有 Key 增强模式。

### 3.6 外部接口

#### 3.6.1 用户接口

桌面浏览器图形界面（HTML 表单与链接）；关系图为 Canvas/SVG 可视化交互。

#### 3.6.2 软件接口

| 接口名称 | 类型 | 说明 |
|----------|------|------|
| 浏览器 ↔ Flask | HTTP | 页面路由与表单提交 |
| `/graph/data` | HTTP JSON | 关系图数据 |
| `/health` | HTTP JSON | 健康检查 |
| 可选 Chat Completions | HTTPS API | 仅当配置 API Key 时启用 |
| SQLite 文件 | 本地文件 | `instance/knowledge.db` |

#### 3.6.3 硬件接口

无专用硬件依赖；常规 PC 即可运行。

## 附录 B 实现边界说明

1. **能力定位**：本系统采用「可演示的检索增强问答 + 关系图」，而非完整商业向量平台或生产级 RAG 运维方案。  
2. **与可运行系统关系**：本文 SR 条目均可在当前工程中找到对应实现，或已在 1.2.2 明确列为不做项。  
3. **建议重点核对**：密级鉴权规则（SR-AUTH-005/006、SR-QA-008）、问答模式边界（SR-QA-003/004）、本期不做范围（1.2.2）。
