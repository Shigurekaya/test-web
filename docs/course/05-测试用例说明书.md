## 1. 文档说明

### 1.1 编写目的

本文档把 V2.0 的功能需求、非功能需求和安全要求转化为可执行的测试用例，供项目负责人自测、课程验收和后续回归使用。每条用例均包含编号、模块、测试项、前置条件、步骤、预期结果、优先级、类型和自动化关联。

## 3. 用例编号、优先级与自动化关联约定

### 3.1 编号规则

- AUTH：认证、会话、防爆破与安全登录；
- PERM：角色、密级、部门、作者、草稿与统计隔离；
- DOC：文档 CRUD、收藏、检索和分页；
- RAG：知识片段、检索排序、问答、来源、降级和历史；
- GRAPH：图谱数据和维护；
- ADMIN：用户、分类、审计；
- NFR：健康检查、API、建库、隔离、构建、性能、兼容和运维；
- UI：Vue SPA 人工交互。

### 3.2 优先级定义

| 优先级 | 定义 | 准出要求 |
|---|---|---|
| P0 | 核心安全边界、核心主路径、数据隔离；失败会阻断验收 | 必须 100% 通过 |
| P1 | 重要业务功能或关键接口；失败影响主要演示 | 必须通过，或经批准豁免 |
| P2 | 一般功能、体验、边界情况；有合理绕行 | 计划内执行，可评估延期 |
| P3 | 轻微体验或可选检查 | 记录结果，不阻断验收 |

### 3.3 类型定义

| 类型 | 含义 |
|---|---|
| 功能 | 业务功能是否正确 |
| 接口 | REST 状态码、JSON 字段和错误契约 |
| 安全 | 认证、授权、防爆破、跳转、密码和隔离 |
| 集成 | 接口、数据库、服务层与权限的组合 |
| 可靠性 | 建库、隔离、错误恢复、降级 |
| 性能 | 演示规模下的响应烟测 |
| 兼容性 | 浏览器、屏幕宽度和构建产物 |
| 易用性 | 提示、空状态、导航、可理解性 |
| UI | 页面交互和视觉可用性 |

### 3.4 自动化关联说明

- test_system.py：系统冒烟、主路径、路由、建库、时间口径和故事线；
- test_security.py：权限矩阵、检索范围、统计口径、审计筛选分页和文本截断；
- test_rag.py：切分、分词、打分、Top-K、来源分组与降级；
- test_login_security.py：失败阈值、锁定窗口、失败审计、密码哈希和行为文案；
- test_api.py：V2.0 REST API 契约；
- “人工 UI 检查”：在 Chrome/Edge 中按步骤操作并截图；
- “人工 API 检查”：在自动化未覆盖或需核对数据库副作用时执行；
- 表格中的自动化函数名为代表性关联，不表示只执行该函数即可覆盖整条业务用例。

## 8. 用例维护与验收说明

### 8.1 用例维护规则

1. 新增功能必须新增或修改用例，不能只更新实现；
2. 安全边界变化必须同时更新正向和负向用例；
3. 自动化函数改名、删除或拆分时，必须更新关联列；
4. 删除用例需说明理由，不能为“让结果变绿”而删除；
5. 用例通过后仍需保留执行日期、版本和证据路径。

### 8.2 课程验收判定

- P0 用例必须 100% 通过；
- P1 用例原则上全部通过，未通过时必须有明确残留风险和批准；
- 认证、权限、密级、RAG 来源、测试库隔离不得带安全问题通过；
- 自动化基线 136 条以最终 pytest 日志为准，不得只引用历史截图；
- 人工 UI 用例至少覆盖 Chrome 或 Edge 一种主流浏览器，关键场景建议两者对照；
- 最终结论以《测试报告》和验收当日执行记录为准。
