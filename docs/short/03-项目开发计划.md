# 智慧企业知识财富库系统——项目开发计划（精简版）

## 1 项目目标与成功标准

在课程周期内完成一个可运行、可演示、可测试、可复现的企业知识管理数据库应用，覆盖文档权限、检索、RAG 问答、知识关系图、审计和前端展示。

| 编号 | 成功标准 | 验收证据 |
|---|---|---|
| S-01 | 主链路可连续演示 | 登录→文档→问答→来源→图谱→审计 |
| S-02 | 权限边界正确 | 匿名、员工、作者、管理员和跨部门场景测试 |
| S-03 | 自动化测试通过 | pytest 全量测试日志 |
| S-04 | 前端可构建 | `npm run build` |
| S-05 | 交付材料完整 | 文档、UML、截图、报告和提交包清单 |

## 2 项目范围

**范围内：**

- 登录、退出、会话和管理员/员工角色；
- 登录失败限流、密码哈希和失败审计；
- 文档 CRUD、分类、标签、版本和发布状态；
- 公开/内部/机密三级密级和部门隔离；
- 文档搜索、筛选、排序和分页；
- RAG 问答、本地摘要降级、来源和历史；
- 知识图谱同步、浏览和管理员维护；
- 收藏、工作台、用户目录、分类和审计；
- 健康检查、启停脚本和生产构建。

**范围外：**

- 真实 SSO、组织架构同步和细粒度 RBAC；
- 附件上传解析、文档版本快照回滚；
- 向量数据库、语义重排、模型训练和大数据平台；
- 微服务、消息队列、分布式缓存和多租户；
- 移动原生应用、跨设备同步和生产级 SLA。

## 3 单人角色映射

本项目为单人独立项目组，不虚构其他成员。本人按阶段切换不同角色：

| 角色 | 主要职责 |
|---|---|
| 项目经理 | 范围、计划、里程碑、风险和验收统筹 |
| 需求分析 | 场景、角色、功能、权限、异常和验收条件 |
| 架构与设计 | 架构、数据模型、API、权限、RAG、图谱和部署 |
| UI/UX | 页面结构、响应式、反馈和无障碍 |
| 前端开发 | Vue 页面、路由、状态、图表和 API 调用 |
| 后端开发 | Flask API、权限、RAG、图谱、审计和运维 |
| 数据与测试 | 数据模型、演示数据、测试和安全回归 |
| 配置与发布 | Git、依赖、构建、部署和交付包 |
| 文档交付 | 正式文档、精简文档、UML、截图和演示脚本 |

## 4 阶段计划

| 阶段 | 主要工作 | 退出条件 |
|---|---|---|
| 立项与需求 | 明确课程要求、项目边界、角色、主流程和验收条件 | 范围冻结，核心需求均有验证条件 |
| 设计基线 | 架构、数据模型、API、权限、页面和 UML | 需求可追踪到设计 |
| 工程与认证 | Vue/Flask 工程、配置、数据库、登录、会话和角色守卫 | 前后端联通，登录链路可用 |
| 文档与权限 | CRUD、分类、标签、状态、筛选、分页和密级隔离 | 跨部门场景结果一致 |
| RAG 核心 | 切分、分词、权限内检索、评分、来源、历史和降级 | 回答只使用可见文档 |
| 图谱与可视化 | 节点边同步、图谱 API、ECharts 和管理员维护 | 文档变化后图谱可重复同步 |
| 管理与审计 | 收藏、审计、用户、分类、工作台和健康检查 | 关键操作留痕，管理入口受控 |
| 集成与界面 | 路由/API 统一、错误与空状态、响应式和截图 | 主链路可连续演示 |
| 测试强化 | 扩展 pytest、权限、安全、RAG 边界和接口契约 | 全部通过且无阻断缺陷 |
| 文档与预验收 | 文档统稿、UML 校对、截图更新、启动说明和交付清单 | 文档、图片和代码一致 |
| 冻结与验收 | 全新环境复核、测试复跑、演示和提交 | 满足验收标准并完成交付 |

执行规则：

- 每周确认目标、范围和依赖，保留缺陷修复与文档同步时间；
- 以可启动、可调用、可测试、可审阅作为完成标准；
- 认证、权限、文档和 RAG 属于关键路径；
- 延期时先压缩非核心视觉优化，不减少权限、安全或回归测试；
- 冻结阶段只修复验收问题，不新增业务模块。

## 6 质量与交付

质量目标：

- pytest 全量测试通过；
- Ruff 静态检查通过；
- Vue 生产构建通过；
- 生产依赖审计无已知漏洞；
- 跨部门机密访问被拒绝；
- 桌面和手机无页面级横向溢出；
- 核心页面控制台无未处理错误；
- 文档版本、技术栈、接口和路径与冻结代码一致。

质量活动：

1. 单元与服务测试：切分、关键词、评分、权限、摘要和时间格式。
2. 接口测试：登录、文档、问答、图谱、管理和分类。
3. 安全测试：越权、开放重定向、失败限流、密码存储和数据库隔离。
4. 系统测试：健康检查、主链路、新数据库初始化和演示数据。
5. 前端巡检：加载、空状态、错误、移动端、弹窗 Esc 和未保存提示。

主要交付物：

- 前端工程与生产构建；
- 后端工程与启停脚本；
- 自动化测试与运行脚本；
- 正式文档与精简文档；
- UML、页面截图和演示数据；
- 最终报告与提交包。

## 7 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 单人承担全部角色导致时间冲突 | 高 | 关键路径优先，保留缓冲，非核心优化可裁剪 |
| 需求膨胀 | 高 | 冻结范围，新增项进入后续清单，最终阶段不扩展 |
| 前后端字段不一致 | 高 | 固定 JSON 契约，统一 API 客户端，补接口测试 |
| 权限过滤遗漏 | 高 | 共享可见性规则，检索前过滤，执行权限矩阵回归 |
| RAG 召回不稳定 | 中 | 补充领域词，保留可解释评分，覆盖代表问题 |
| 图谱与文档不同步 | 中 | 保存后幂等同步，提供管理员维护入口 |
| 测试污染演示库 | 高 | 使用独立临时数据库，夹具隔离，执行前后检查 |
| 外部模型不可用 | 中 | 模型可选，失败回退本地摘要并标注模式 |
| 文档、截图和代码不一致 | 中 | 冻结后复核，交付清单逐项确认 |

## 8 验收与当前状态

验收步骤：

1. 执行 pytest 和 Ruff；
2. 执行前端生产构建；
3. 启动 Flask 主系统并检查健康接口；
4. 手工走登录、文档、问答、来源、图谱和审计主链路；
5. 检查匿名、员工、作者、管理员和跨部门权限；
6. 检查桌面与手机的布局、控制台和交互；
7. 核对文档、UML、截图、报告和提交包清单。

放行规则：

- 全部阻断项通过、核心测试通过、无权限泄露：准予交付；
- 非核心视觉或文档问题已记录且不影响主链路：可有条件通过；
- 无法启动、核心链路中断、权限泄露、测试失败或关键文件缺失：不得交付。

当前状态：

- pytest 全量测试通过；
- Ruff 检查通过；
- Vue 生产构建通过；
- 桌面和手机页面巡检通过；
- 正式 Word、PDF 和提交包应以最终冻结版本重新复核。

最终交付以实际测试日志、构建日志、线上页面检查、文档清单和验收记录为准。本计划不将课程演示系统描述为真实企业生产系统，也不将虚构演示数据描述为真实业务数据。
