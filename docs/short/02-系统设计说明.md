# 智慧企业知识财富库系统——系统设计说明（精简版）

| 项目 | 内容 |
|---|---|
| 文档编号 | SDD-SHORT-002 |
| 文档版本 | V2.0 |
| 适用系统 | 智慧企业知识财富库系统 V2.0 |
| 编制日期 | 2026-10-31 |
| 架构风格 | 前后端分离、单体后端、分层服务 |
| 前端 | Vue 3 + Vite + Vue Router + ECharts |
| 后端 | Flask 3 + Flask-Login + SQLAlchemy |
| 数据库 | SQLite，可通过 `DATABASE_URL` 切换 |
| 质量基线 | pytest、Ruff、Vite 生产构建、Playwright 页面巡检 |

> 本文档描述当前 V2.0 的实现设计，不把规划中的向量数据库、微服务或附件系统写成已交付能力。架构取舍以课程规模、可运行性和可验证性为先。

## 1 设计目标与原则

### 1.1 设计目标

1. 用一个可运行系统打通登录、文档、权限、检索、问答、图谱和审计主链路。
2. 让服务端权限规则成为唯一可信边界，前端状态不作为授权依据。
3. 让 RAG 问答可解释：能展示来源、片段、模式和降级原因。
4. 让文档、知识片段和图谱在保存后保持同步。
5. 让课程交付可复现：依赖、构建、测试、启动和静态演示均有明确入口。

### 1.2 设计原则

- **简单优先**：单体 Flask + SQLite 足以覆盖课程规模，不引入无法验证的分布式组件。
- **权限先行**：所有业务查询先认证、再授权、后检索。
- **契约稳定**：REST API 返回中文标签和统一错误结构。
- **可解释**：RAG 使用关键词、标题、标签与短语评分，回答附带来源。
- **渐进增强**：外部大模型是可选项，未配置或失败时保留本地摘要。
- **前后端同构体验**：加载、空状态、错误、确认和移动端适配由统一设计约束管理。
- **不夸大边界**：静态站是 Mock 演示，不是生产认证或真实 AI 服务。

## 2 总体架构

```text
浏览器
  └─ Vue 3 SPA
      ├─ AppShell：导航、搜索、用户与退出
      ├─ Vue Router：路由与登录/管理员守卫
      ├─ Views：工作台、文档、问答、图谱、管理、关于
      ├─ Stores：会话与 Toast
      └─ API Client：同源 /api 请求与统一错误
                  │
            Flask Application
              ├─ Flask-Login 会话与角色
              ├─ REST API 蓝图 /api
              ├─ Jinja 兼容页面蓝图
              ├─ 文档与权限服务
              ├─ RAG 检索与问答服务
              ├─ 图谱同步与过滤服务
              └─ 审计记录服务
                        │
                   SQLAlchemy
                        │
                     SQLite
```

### 2.1 运行时组成

| 组成 | 职责 |
|---|---|
| Vue 3 SPA | 页面渲染、路由守卫、表单、图表、响应式交互 |
| Flask 应用工厂 | 配置、扩展、蓝图、错误页、种子数据初始化 |
| Flask-Login | 会话身份、登录状态和当前用户 |
| REST API | 认证、文档、问答、图谱、管理、系统信息 |
| SQLAlchemy | 数据模型、查询、关系与事务 |
| SQLite | 单机持久化；测试使用独立临时库 |
| Cloudflare Pages | 纯静态 Mock 演示，不连接 Flask 数据库 |

### 2.2 一次典型请求

1. 浏览器进入 `/ui/`，Flask 返回 Vue 生产入口。
2. Vue Router 调用 `/api/auth/session` 判断登录状态。
3. 页面发起到 `/api/*` 的同源请求。
4. 后端校验会话、角色和文档权限。
5. 业务层读取或写入数据库，并按需写审计。
6. 前端统一处理响应、错误提示和页面状态。

## 3 技术选型

| 技术 | 用途 | 选择理由 |
|---|---|---|
| Vue 3 | 前端组件与响应式状态 | 依赖少、组件化清晰、适合课程展示 |
| Vite | 开发与生产构建 | 启动快、构建产物简单 |
| Vue Router | 页面路由与守卫 | 支持 SPA 和角色路由控制 |
| ECharts | 工作台图表和知识图谱 | 本地依赖、图表能力完整 |
| Flask 3 | REST API 与静态托管 | 轻量、易于阅读和测试 |
| Flask-Login | 会话认证 | 与 Flask 集成直接，适合单体应用 |
| SQLAlchemy | ORM 与关系模型 | 表结构清晰、便于测试隔离 |
| SQLite | 数据库 | 无需外部服务，适合单机演示 |
| jieba | 中文分词 | 为本地关键词检索提供基础能力 |
| pytest | 自动化测试 | 覆盖接口、权限、RAG 和系统主路径 |

未采用微服务、Redis、消息队列、向量数据库、独立图数据库和大数据平台，原因是当前数据规模、部署环境和课程验收重点不支持这些组件的收益。

## 6 核心数据模型

| 表 | 关键字段 | 关系与作用 |
|---|---|---|
| `users` | `id`, `username`, `password_hash`, `display_name`, `role`, `department` | 用户身份；一对多文档、问答、收藏、审计 |
| `categories` | `id`, `name`, `description` | 文档分类；一对多文档 |
| `documents` | `id`, `title`, `content`, `summary`, `department`, `visibility`, `status`, `version`, `tags`, `category_id`, `author_id` | 知识主体；关联分类、作者 |
| `knowledge_chunks` | `id`, `document_id`, `chunk_index`, `content`, `keywords` | 文档切分片段；多对一文档 |
| `graph_nodes` | `id`, `name`, `node_type`, `description`, `document_id` | 图谱节点；名称唯一 |
| `graph_edges` | `id`, `source_id`, `target_id`, `relation` | 节点间关系 |
| `favorites` | `id`, `user_id`, `document_id`, `created_at` | 用户收藏；同一用户与文档唯一 |
| `qa_history` | `id`, `user_id`, `question`, `answer`, `sources`, `mode`, `created_at` | 个人问答记录与来源 |
| `audit_logs` | `id`, `user_id`, `action`, `detail`, `created_at` | 管理审计追踪 |

### 6.1 数据一致性

- 保存文档时重建知识片段并同步图谱；
- 删除文档时清理知识片段、收藏和关联图谱节点/边；
- 分类、部门、关键词和图谱节点使用幂等同步逻辑；
- API 输出标签由服务端统一转换为中文；
- 时间统一格式化为无微秒的本地时间字符串；
- 测试数据库与演示数据库完全隔离。

## 7 权限与安全设计

### 7.1 权限执行链

```text
请求
  → 是否登录
  → 用户角色是否允许
  → 文档是否可见
  → 文档是否已发布
  → 执行业务查询
  → 写审计（如适用）
  → 返回 JSON/页面
```

### 7.2 文档可见性

```text
可见 = 管理员
     或作者本人
     或（文档为已发布，且密级为公开/内部）
     或（文档为已发布，且密级为机密且同部门）
```

具体实现会区分本人草稿/归档文档、普通用户检索范围和问答检索范围，但列表、详情、来源与图谱均复用同一权限前提。

### 7.3 安全措施

- 密码使用哈希保存，不在 API 中返回；
- 登录失败按来源限流，并写入失败审计；
- 未登录返回 401，越权返回 403；
- 登录回跳只允许站内路径，阻止开放重定向；
- 设置 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` 和权限策略头；
- API 响应设置 `Cache-Control: no-store`；
- `.env` 不进入 Git；
- 外部模型密钥只允许通过服务端环境变量注入；
- 静态演示站不提供真实认证，也不能接触真实业务数据库。

## 8 关键流程设计

### 8.1 登录流程

1. 前端提交用户名和密码。
2. 后端校验限流、密码哈希和用户状态。
3. 成功时建立会话，失败时记录审计并返回统一错误。
4. 前端读取角色并跳转到站内安全地址。
5. 管理员菜单仅在会话用户为管理员时显示，服务端仍再次校验。

### 8.2 文档保存流程

1. 前端校验标题和正文，展示未保存状态。
2. 提交标题、摘要、正文、分类、部门、密级、状态、版本和标签。
3. 后端执行字段和权限校验，保存文档。
4. 重建知识片段、提取关键词、同步图谱。
5. 返回文档 ID，前端跳转详情页。
6. 保存成功或失败均提供明确反馈。

### 8.3 RAG 问答流程

1. 认证用户提交问题。
2. 先过滤可见、已发布文档。
3. 加载知识片段，使用 jieba 分词并计算相关度。
4. 按 Top-K 聚合片段和来源，限制同文档片段数量。
5. 有模型配置时尝试生成回答；无配置或失败时生成可解释本地摘要。
6. 保存历史与审计，返回模式、回答、来源和片段。
7. 前端展示来源折叠面板、模式标签和历史记录。

### 8.4 图谱流程

1. 文档对象变化后触发节点和关系同步。
2. 普通用户请求图谱时，仅基于可见文档及其邻接节点计算子图。
3. 管理员可读取完整图谱并新增节点/关系。
4. 前端默认加载核心视图，支持完整图谱、名称开关、适配画布和节点聚焦。
5. 移动端使用触摸友好的操作说明，明确单指平移、双指缩放和点击进入详情。

### 8.5 审计流程

1. 业务动作成功后调用审计记录函数。
2. 记录用户、动作、业务对象和必要的摘要信息。
3. 管理员按操作类型、账号、明细关键词和页码查询。
4. 审计接口只允许管理员访问，普通用户不返回审计数据。

## 9 前端设计

### 9.1 路由

| 路径 | 页面 | 权限 |
|---|---|---|
| `/login` | 登录 | 公开 |
| `/dashboard` | 工作台 | 登录 |
| `/documents` | 文档列表 | 登录 |
| `/documents/new` | 新建文档 | 登录 |
| `/documents/:id` | 文档详情 | 登录且文档可见 |
| `/documents/:id/edit` | 编辑文档 | 作者或管理员 |
| `/qa` | 智能问答 | 登录 |
| `/graph` | 知识关系图 | 登录 |
| `/admin/users` | 用户管理 | 管理员 |
| `/admin/audits` | 审计日志 | 管理员 |
| `/about` | 系统说明 | 登录 |

### 9.2 状态与组件

- `session` store 管理会话用户和系统元信息；
- `toast` store 管理成功、错误、警告和普通提示；
- `AppShell` 统一管理桌面侧栏、移动断点导航、全局搜索、新建入口和退出；
- `PageHeader` 统一页面标题与操作区；
- `BaseChart` 统一 ECharts 生命周期、窗口变化和点击事件；
- 表格、空状态、错误提示和危险操作使用统一样式与反馈。

### 9.3 响应式与可用性

- 桌面侧栏在窄屏切换为抽屉，底部提供四个高频入口；
- 用户和审计表格在手机端变为字段明确的卡片，而非压缩列；
- 文档编辑页提供大正文编辑区、预览、保存快捷键和未保存离开确认；
- 问答欢迎页不自动聚焦手机输入框，建议问题与输入框互不遮挡；
- 收藏、删除等操作有明确按钮文本或无障碍名称；
- 弹窗提供 `role="dialog"`、`aria-modal` 和 Esc 关闭；
- 支持 `prefers-reduced-motion`，降低动画对敏感用户的影响。

## 10 REST API 设计

| 分组 | 端点示例 | 说明 |
|---|---|---|
| 系统 | `GET /api/health`、`GET /api/meta` | 健康检查和系统元信息 |
| 认证 | `POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/session` | 登录、退出、会话 |
| 工作台 | `GET /api/dashboard` | 权限内统计和最近动态 |
| 文档 | `GET/POST /api/documents`、`GET/PUT/DELETE /api/documents/{id}` | 列表、CRUD |
| 收藏 | `GET /api/documents/favorites`、`POST /api/documents/{id}/favorite` | 收藏列表与切换 |
| 分类 | `GET/POST /api/categories` | 分类查询与新增 |
| 问答 | `GET /api/qa`、`POST /api/qa/ask`、`GET /api/qa/history/{id}` | 问答、历史、建议 |
| 图谱 | `GET /api/graph`、`GET /api/graph/manage`、`POST /api/graph/nodes`、`POST /api/graph/edges` | 浏览与维护 |
| 管理 | `GET /api/admin/users`、`GET /api/admin/audits` | 用户和审计 |
| 关于 | `GET /api/about` | 能力、统计与项目说明 |

### 10.1 错误约定

| 状态码 | 含义 | 前端处理 |
|---|---|---|
| 400 | 参数缺失或格式错误 | 显示具体校验提示 |
| 401 | 未登录或会话失效 | 跳转登录页 |
| 403 | 角色或文档权限不足 | 显示无权限，不展示正文 |
| 404 | 资源不存在 | 显示不存在并返回列表 |
| 409 | 唯一性或冲突 | 提示修改后重试 |
| 429 | 登录尝试过多 | 提示稍后重试 |
| 500 | 服务端异常 | 显示通用错误，不暴露堆栈 |

## 12 性能、可靠性与已知限制

### 12.1 当前性能策略

- 前端使用路由级异步组件，减少首屏不必要的页面代码；
- 图表实例由 `BaseChart` 管理，避免重复初始化；
- 后端按用户权限先过滤再检索，避免计算无权内容；
- 演示数据规模为课程级，分页接口返回固定页大小；
- 静态站资源带长期缓存头，Mock 数据和入口不缓存。

### 12.2 当前瓶颈与改进方向

| 位置 | 现状 | 改进方向 |
|---|---|---|
| 检索 | Python 内计算相关度 | FTS/向量索引、混合检索与重排 |
| 文档 | 版本为字段，无历史快照 | 版本表、差异和回滚 |
| 数据库 | SQLite + `create_all` | Alembic 迁移、PostgreSQL |
| 安全 | 会话 CSRF 未显式实现 | CSRF Token、持久化限流、细粒度 RBAC |
| 运维 | 请求内同步处理 | 任务队列、指标、结构化日志、备份恢复 |
| 前端 | ECharts 形成较大异步包 | 图表按需加载、缓存和性能预算 |
| 问答 | 关键词检索为主 | 语义召回、重排、反馈和无答案识别 |

| 需求 | 设计模块 | 验证方式 |
|---|---|---|
| 登录与角色 | 认证模块、路由守卫、服务端鉴权 | 登录安全与 API 测试 |
| 文档与密级 | 文档模块、权限服务、知识片段同步 | CRUD、权限矩阵测试 |
| 检索问答 | RAG 服务、API、问答页面 | RAG 单元/接口测试、人工来源核对 |
| 知识图谱 | 图谱服务、ECharts 页面、管理员维护 | 图谱接口与页面巡检 |
| 审计与管理 | 审计表、管理员 API、管理页面 | 筛选分页与角色拒绝测试 |
| 构建与演示 | SPA 托管、Pages 构建脚本 | `npm run build`、`npm run pages:build` |

## 14 结论

本设计以可运行、可解释和可验证为优先，在课程规模内实现了完整业务闭环。已知性能、迁移、安全和知识生命周期限制均在文档中明确列出，后续演进应优先解决权限一致性、检索质量、数据库迁移和可观测性，而不是单纯增加页面数量。
